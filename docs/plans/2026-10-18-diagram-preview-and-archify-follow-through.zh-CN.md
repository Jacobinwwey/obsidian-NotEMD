## 根因与最小修复

真实宿主报告 Obsidian 1.14.4、NoteMD 1.9.14。独立 `obsidian-cli` 不可用，官方 `Obsidian.com` CLI 可用。CLI eval 中不能直接 `require('obsidian')`，因此宿主身份取自 CLI `version`，而不是该模块或安装器 user-agent。

选中的 Drawnix 示例成功生成了 32,529 字符的 SVG。故障发生在挂载后的 `collectSvgPresentationDiagnostics()`：约 0.16 倍显示比例下，文档标题与摘要实际仍相隔约 0.483 CSS 像素。校验器却用未缩放的 0.5 单位标签留白比较屏幕坐标矩形，导致合法的小预览被误判。现有证据不能证明宿主升级引入了该缺陷。

修复继续使用屏幕坐标中的 DOM 几何，但通过 `getScreenCTM()` 同步投影源 SVG 的留白。水平与垂直留白使用矩阵对应行的绝对值之和，覆盖均匀／非均匀缩放及坐标轴反射，不硬编码 Drawnix、宿主版本、缩略图宽度，也不添加绕过校验的模式。无变换的测试替身沿用单位缩放。真正的标签相交与后绘制图形遮挡仍然报错。该修复不会把轴对齐包围盒检测升级为旋转字形的精确相交检测。

对 T 个文本与 S 个图形，时间复杂度仍为 `O(T² + T·S)`，收集几何的存储复杂度为线性。本次有限修复不引入新的布局引擎或空间索引。

## 本地异常恢复

恢复前，`src/tests/diagramHistoryRepository.test.ts` 的内容变成了截断的输出选择器界面代码，而不是已跟踪的历史仓库测试。普通 Git 状态没有报告该差异。先将文件备份至 `.cache/preview-20261018/diagramHistoryRepository.test.before-recovery.ts`，再用补丁恢复 HEAD 内容。意外本地覆盖的机制尚未查明，不将其归因于 Obsidian 或 SVG 缺陷。

额外内容审计直接比较已跟踪源码／构建辅助文件与索引 blob，而不是只信任基于文件状态缓存的状态结果。既有换行差异单独归类，不批量重写。该操作是本地基线恢复，不是刻意修改历史功能。
