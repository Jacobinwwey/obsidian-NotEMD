# 参考 Archify 的图形质量实施计划

[English](./2026-10-18-er-quality.en.md)

## 目标与设计

改进 ER 的完整生成链路，不只修改配色。保留当前图形目录、源格式、前次修复及用户设置。设计方向为克制的技术文档表格：标题／字段层级清晰、类型与键标记可读、关系正交、基数有来源。不新增网络字体、运行时依赖、凭据、供应商调用，也不复制 Archify 运行时。

用户已授权按照建议推进实现。比较三种方案：仅换主题无法恢复丢失的语义；嵌入 Archify 会增加运行时／模式／安全边界；独立 ER 类型化载荷与共享场景是最小完整语义归属。其他图形保留现有引擎，后续优先级建议明确区分已实施与提案。

## 阶段

- [x] 1. 固定新克隆的 Archify 版本，对比模式、生成指导、场景几何、路由、图例及实际产物。
- [x] 2. 先写失败回归：规范 ER 校验、中英文身份、SQL 类型、复合键角色、FK 引用、基数、未知信息及旧载荷兼容。
- [x] 3. 建立 Mermaid、HTML／SVG、Draw.io 共用的 ER 语义边界；引用必须有效，不凭空添加字段；旧输入保留并明确说明兼容行为。
- [x] 4. 实现测量驱动的 ER 表格场景、避障正交路由、端点标记及不截断文字。字段导出为表格行，不再作为独立实体；SVG 与原生 Draw.io 使用同一场景。
- [x] 5. 强化生成指导，并用真实结构替换极简 ER 示例；保持预览／导出一致和前次适配／选字修复。
- [x] 6. 运行定向红绿回归、浏览器几何／主题／可访问性检查、生产构建、全量测试及 lint／审计。缺失的 UX 证据标记未知，不编造评分。

验证执行已完成，但不等于发布全绿签核：324 个非发布套件通过（3103 项通过、1 项跳过），单独复跑的未修改发布夹具仍有 5 项子进程超时／清理失败，另有 5 个非 ER 图库归档未同步。最初不排除全套的结果、实际导出证据及原生消费验证边界详见双语维护报告。

## 归属与验证

ER 合约与兼容转换归于 `src/diagram/adapters/er/`；规范载荷注册归于 `payloads/types.ts` 与 `payloads/validators.ts`。各渲染器入口仅分发完整 ER 操作；提示词／目录／示例共用同一合约。测试实际导出格式和真实浏览器 SVG 几何。不得提交、切换分支、发布、升级依赖、覆盖原笔记或清理 `.trellis`；保留已有未提交修复。

上一轮全量运行存在无关发布夹具的 20 秒子进程超时；如实记录新结果，不为此修改发布代码。
