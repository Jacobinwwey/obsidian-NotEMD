# 图表类型兼容与多格式输出设计

状态：设计提案；未包含在 10 月 1 日导出修复的已实现功能中。[English](2026-10-01-diagram-output-compatibility-design.en.md)

## 问题与建议

当前“首选输出格式”实际选择的是 `RenderTarget`，混合了渲染引擎、可编辑源文件和 HTML 呈现方式。设置页和侧栏在选择后重置另一项偏好来修正冲突，用户事前看不到限制，也不能要求一次生成交付多种格式。

保留图表类型单选，将输出下拉框改为**输出文件**复选框组。两个控件使用同一个能力计算结果：选择前禁用不兼容项、说明原因、保留显式选择。语义内容只生成一次，再导出所选格式。

本设计面向图表工作流。PPTX、MP4 仍属于独立的 Slidev 演示工作流；本次演示导出成功不代表所有图表渲染器都支持它们。

## 两种现有 HTML 的区别

| 当前选项 | 实际行为 | 建议名称 |
| --- | --- | --- |
| HTML（`html`） | 包含节点层级、关系、表格、证据的结构化阅读页面，不保留图表的几何布局；描述符中没有预览 SVG 或图片导出能力。 | HTML 结构化摘要 |
| Editable HTML/SVG（`editable-html-svg`） | HTML 内含确定性 SVG 图形及语义/编辑元数据，包括 `data-drawio` 属性；有 SVG 预览并支持 SVG/PNG/PDF 导出。它不是完整的浏览器所见即所得编辑器。 | HTML 图形预览；在说明中解释 SVG/编辑元数据 |

两者扩展名均为 `.html`，扩展名本身不能表达内容语义。本次 Drawnix 的 HTML 包装原始 SVG，提供浏览、缩放和下载功能，没有将图表切换到通用 `html` 渲染器。将这种派生 HTML 包装能力纳入产品，是后续实现的一部分。

## 方案比较

1. **建议：交付格式与渲染目标分离。** 渲染目标留在规划内部，用户选择有明确语义的输出文件，兼容关系由现有目录计算。这能直接满足多格式导出并消除名称歧义。
2. 给现有目标选择器增加禁用和多选。界面改动较少，但两个引擎可能产生不同布局，PDF/PNG 又需要另一组概念，根本歧义仍然存在。
3. 图表和导出分别使用独立对话框。适合复杂导出，但发现冲突太晚，持久化偏好也更难理解。

## 职责与能力模型

继续由 `diagramTypeCatalog.ts` 定义语义类型到渲染目标的兼容关系，由 `renderTargetCatalog.ts` 定义渲染目标的能力。扩展描述符，不在设置、侧栏、预览和 CLI 中复制矩阵。

稳定输出标识区分 `source:<target>`、`html-diagram`、`html-summary`、`svg`、`png`、`pdf`。源文件标识保留原生语义：`source:drawnix` 指 `.drawnix` 文件，不是泛泛的“可编辑”。内部渲染器标识与交付文件标识分开。

兼容计算由图表偏好规划模块负责，返回可选类型、可选输出和本地化原因键。生成规划器使用相同描述符解析完整导出计划。UI 只呈现计算结果，不根据扩展名或标签猜测兼容性。导出执行器负责依赖顺序、取消、写入及每项产物的状态。

每条路线必须是兼容渲染器明确支持的派生能力。SVG、PNG、PDF 和 HTML 图形预览共享该渲染器的确定性预览。HTML 结构化摘要仅在类型明确兼容摘要渲染器时可选。多个原生源文件需要明确声明的共同计划；初版不能推断原生格式间的无损转换，也不能为了获得文件而修改图表类型。

语义支持与环境就绪是两个事实。缺少 Chromium、FFmpeg 或原生编译器时，在执行前说明依赖缺失，不能悄悄改变兼容矩阵。

## 双向选择规则

令 `P(t, S)` 表示：存在已声明的计划，在不改变语义类型、不违反源文件保真要求的前提下，为类型 `t` 生成集合 `S` 中的全部输出。

- 类型可选，当且仅当 `P(类型, 已选输出)` 成立。
- 已选明确类型时，未选输出可选，当且仅当 `P(类型, 已选输出 ∪ {候选输出})` 成立。
- 类型为自动时，只要至少一个可执行类型满足同一条件，该输出就可选；自动生成只能从这个候选集合中选择类型。
- 已选输出始终可以取消，包括过时或冲突的持久化选项。禁用状态不能阻断恢复路径。
- 未显式选择输出表示自动采用类型现有默认目标的输出。界面标注“自动输出”，执行前显示最终文件类型，不表示什么都不导出。
- 无效旧组合保留为可见冲突，解决前禁用生成。“使用自动图表类型”“清空输出筛选”是显式恢复操作。
- 改动任一控件不能悄悄取消另一控件的选择。要切换到禁用项，先显式移除冲突。

示例：

| 用户选择 | 可用行为 | 禁用行为 |
| --- | --- | --- |
| Drawnix 源文件 | Drawnix 知识图；可追加 SVG/PNG/PDF 及拟新增的 HTML 图形预览 | Nested Scope 及无 Drawnix 路线的类型；未新增明确兼容路线前的 HTML 结构化摘要 |
| Nested Scope（`nested`） | HTML 图形预览、HTML 结构化摘要，以及通过兼容 SVG 渲染器导出的 SVG/PNG/PDF | Drawnix 源文件及其他不兼容原生源文件 |
| 自动 + SVG + PDF | 同一兼容预览路线能够生成两者的类型 | 仅提供结构化阅读页面的类型 |
| Nested Scope + HTML 摘要 + SVG | 同一语义规格交给两个明确兼容的渲染器；摘要名称解释其呈现差异 | 暗示将摘要 DOM 转换成原图 SVG |

实现时必须通过描述符机械验证这些示例。当前 Drawnix 类型仅声明 `drawnix`；Nested Scope 声明 `editable-html-svg` 和 `html`。

## 交互与无障碍

类型使用原生单选/下拉语义，输出使用复选框，分为**原生源文件**与**浏览/图片文件**。不兼容项降低视觉强调，并显示简短原因，例如“Nested Scope 无法生成 Drawnix 源文件”。不能只依赖颜色或悬停提示。提供相邻且键盘可达的兼容说明及 `aria-describedby` 关联。已选项可用键盘取消。使用礼貌播报区域提示兼容集合变化，保持焦点稳定。

设置页保存默认值，侧栏可对单次运行覆盖。二者使用相同的选择操作和原因文本。预览导出依据已生成会话的固定类型/规格，不能受生成后无关设置变化影响。CLI/API 对无效组合返回结构化错误和可移除项建议，不静默回退。

多选状态显示“已选择 3 种输出文件”等明确文本。写入前展示真实文件名。HTML 摘要和 HTML 图形预览分别显示、分别命名，例如 `topic.summary.html` 与 `topic.diagram.html`。

## 执行、持久化与恢复

1. 在持久化设置及 CLI/UI 请求边界验证输入。固定本次类型/输出选择，先检查依赖，再开始付费生成。
2. 生成一份标准语义规格；独立演示工作流生成一份 Slidev 稿。记录内容身份及所选输出。
3. 共享中间表示只渲染一次。派生文件使用有界并发，需要独占的外部原生应用串行执行。
4. 每份产物写入临时同级文件，验证后提交路径。不覆盖用户无关文件。稳定运行清单记录成功、失败、取消格式、哈希和错误，不包含凭据。
5. 取消时停止排队任务及支持中断的活动子进程，保留成功文件，只清理本次拥有的临时文件，明确报告部分完成。
6. 重试仅处理失败格式，复用仍有效的规格和中间产物。依赖或源内容变化时重验受影响部分。不能只为重试 PDF 再次请求 LLM。

在语义类型偏好旁持久化带版本的输出 ID 数组，例如 `preferredDiagramOutputs`。迁移期间保留旧目标数据以支持恢复和降级。旧 `html` 映射到 `html-summary`，旧 `editable-html-svg` 映射到带兼容渲染器约束的 `html-diagram`，原生目标映射到对应源文件 ID。自动保持自动默认。迁移必须幂等，并在边界一次性验证组合。未知 ID 和冲突旧组合需要展示，不能静默丢弃或替换。用户改动设置或既有正常持久化边界提交时再保存迁移，不能因只读检查就重写设置。

现有 `.drawnix.md` 包装仍是 Obsidian 预览；“Drawnix 源文件”下载原始 `.drawnix`。文件命名与清单必须区分包装、源文件及派生产物。

## 实施顺序与验收

以下为后续实施建议，不表示界面已经改变。

1. **能力契约与迁移：** 扩展描述符，实现计划存在性判断与选择状态转换；测试全部目录项、未知 ID、旧自动值、幂等和冲突持久化组合。
2. **设置与侧栏：** 替换单输出选择，接入共享兼容计算和本地化原因；验证键盘、焦点、禁用说明、自动、取消和冲突恢复。
3. **导出执行：** 共享规格/中间表示、派生 HTML 预览、防文件冲突、部分失败/取消和重试；验证多格式及重试仅调用一次 LLM。
4. **真实使用端：** 通过 CLI 在已打开测试 Vault 中验证 Drawnix 源文件 + HTML/SVG、Nested Scope HTML/SVG/PNG/PDF、重启后的设置恢复，以及无关设置不变。验证离线公式/字体和真实生成路径中的跨字节 Unicode。

必须满足：先选类型或先选格式得到相同支持集合；任何可选项都能形成有效计划；已选冲突始终可移除；设置/侧栏/CLI 结论一致；未知输出明确报错；缺少工具不改写语义偏好；部分成功产物可访问。PPTX/MP4 使用独立演示能力测试，不能作为通用图表导出宣传。
