# 图形输出偏好与可恢复多格式交付

[English](2026-10-02-diagram-output-implementation.en.md)

状态：P0–P4 已实施，本地验收完成；远端验收以对应提交的 Linux/Windows Verify plugin 工作流为准。本计划替代 10 月 1 日设计中的手动冲突恢复交互；最新用户决策要求优雅降级、支持项优先。

## 契约

- 演示导出与图形生成保持独立设置、能力目录、环境预检和执行路径。同扩展名不代表同能力。
- 图表类型单选，图形输出多选。原生源文件、图形 HTML/SVG/PNG/PDF、结构化摘要 HTML 使用不同交付标识。
- 先显示直接兼容项，再显示需要自动协调的项，最后显示不支持项。不隐藏冲突项；仅真正不支持的项禁用，已选项始终可取消。
- 最新显式选择优先。选择类型时保留请求输出，但使不兼容项暂不可用；选择输出时可自动协调到兼容类型，不要求重置或退出步骤。
- 持久化请求偏好，生成前固定有效计划；明确展示暂不可用项和回退。如果请求输出全部不可执行，采用有效兼容渲染器的默认源输出，覆盖率相同时保留旧渲染目标偏好。不能将源文件降级成图片后宣称原请求完成。
- 同一标准规格供选定原生渲染器及其派生输出使用；兼容的结构化摘要渲染器可复用相同规格。允许保留多个原生请求，但每次仅激活一个原生目标，最新兼容原生选择优先。
- 单次运行内复用中间产物；部分失败/取消保留成功文件；重试失败格式不再次请求 LLM。区分原生源文件与派生产物路径。
- 保持已修复的 Unicode 流式传输及离线 SVG/字体处理。真实验证保留原始笔记和无关用户设置。

## 职责与上线

现有类型/目标目录定义能力。图形专用偏好规划模块负责有效计划与兼容投影；设置和侧栏不复制规则。生成操作固定本次请求；导出操作负责中间表示复用、验证写入和逐格式状态。规划和执行不引入演示导出模块。

在持久化输入边界一次验证，安全未知标识保留为不可用偏好；迁移不立即写盘，保留旧渲染目标偏好。没有多输出请求时，现有单格式调用保持原行为。保留旧字段不等于已经证明降级版本安全；需要验证当前序列化行为并保留未知设置字段。

普通增删操作保留未知偏好版本及扩展字段；未知版本的请求仍隔离执行，使用支持的默认路线并显示版本提示，避免把未来 schema 静默解释为 v1。这是限定范围的兼容行为，不代表任意版本之间都能安全降级。

取舍：每批一个原生目标可限制转换歧义、保留编辑语义，不承诺同时转换成多种原生格式。持久化规格和缓存增加磁盘占用，但允许不访问模型的确定性恢复。已有恢复记录通过 Obsidian `DataAdapter.process()` 串行比较后更新，新输出采用验证后的暂存文件与 rename；该边界符合真实宿主契约，不声称具备整个文件系统的事务或断电原子性。

按上述顺序实施验证，再整体启用完整链路。不能先上线多选界面却只保存一种格式。本次不创建公开发布或标签；已有授权覆盖验证后集成到远端 main。
