# 多图表生成实施方案

## 范围与决策

保留已完成的同目录导出、可配置缓存和 PDF 标签修复。演示文稿继续使用独立管线。在旧单类型配置旁增加带版本的按类型偏好记录，保留未知字段和暂不可用请求。未选类型时自动分析原文。每种类型独立保存格式，取消勾选后仍保留。

采用紧凑的类型和格式下拉菜单。复选框控制是否参与生成；点击名称选中该类型并进入格式配置。悬停和键盘聚焦仅预览，不保存。已有预览在菜单展开时移到旁边，窄屏则放在上方，以占位元素保持原布局；关闭菜单后归位。兼容格式排在前面，不可用格式保留并置灰，不自动替换图表类型。

在现有命令锁内先冻结全部操作输入，再顺序生成。按类型隔离失败，取消时停止尚未开始的工作，返回每种类型的明确结果。保留显式单类型 CLI 请求兼容性。各类型独立保留导出收据和重试记录。

文件命名为 `<原文名>_<语义类型>.<扩展名>`，`drawnix-knowledge-map` 使用短名 `drawnix`。所有格式共享一次命名预留；重名追加序号。缓存 UUID 独立。新写 manifest v3，继续读取 v1/v2 并保留其路径约束。

## 验收顺序

1. 偏好迁移、类型隔离、未知版本、取消勾选与重选测试。
2. 批量执行、部分失败、取消、CLI 契约、命名和恢复测试。
3. 真实 DOM 的鼠标、键盘、320px 窄屏测试，以及既有预览竞态测试。
4. 构建并通过 CLI 重载到已打开的 `1Knowledge`，验证真实多类型产物及用户偏好保持。
5. 全量测试、lint 增量门禁、UI/渲染审计、双语文档；推送 main 并核验本次 CI。

## 取舍

顺序生成限制模型和渲染器负载，便于取消，代价是总耗时增加；同时避免并行模态框及渲染宿主竞争。可读文件名需要显式冲突预留，纯 UUID 虽简便但不符合命名诉求。临时预览状态和 CLI 覆盖均不得修改用户设置。

## 验证结果

- 本地构建、298 个测试套件（2,870 项通过、1 项既有跳过）、lint 增量门禁、UI 字符串审计、渲染宿主审计及 diff 格式检查通过。
- 真实 Chromium 测试覆盖 320px/900px 菜单、预览移动与归位、滚动时预览保持可见、焦点/Escape、独立格式、设置对象重载和串行保存。
- 通过官方 Obsidian CLI 将构建加载到已打开的 `1Knowledge`。从 `full_processed_zh-CN.md` 生成 Nested 的 SVG/PNG/PDF、流程图的 Mermaid/SVG、Drawnix 的源文件/HTML/SVG/PDF，全部位于原文目录。九项产物的 SHA-256 收据均匹配，原文内容未变。首次 Drawnix 模型请求超时没有阻断其他类型；通过已保存偏好单独重试后，四种格式全部完成。
- 新 PDF 的六条 Drawnix 关系标签均可提取并经视觉检查，已检查的文本输出无 Unicode 替换字符。沿用用户配置的输出语言。
- 真实设置窗口测试后，配置按原始字节恢复。复选框点击区域实测为 44×47 CSS px；20 次焦点切换到下一帧反馈的 p95 为 55.1 ms。交互审计使用上述证据；未测量的全产品转化/主操作指标及间距指标保留为未知。
- 恢复测试覆盖 v1/v2 记录、v3 篡改、逐格式重试、取消、大小写冲突及并发重名。演示文稿配置继续独立于图形偏好。

验证脚本和报告保留在本地 `.cache/multichart-*`，不作为插件运行依赖。
