## 行为约定

- 用户选择的格式属于最终交付文件。新多格式批次直接保存到原笔记目录，或直接保存到指定输出目录（支持 Vault 根目录）。
- 恢复记录、渲染中间缓存、写入暂存和原生附件使用独立位置。默认位于原 Markdown 目录的 `notemd_assert`，即使最终输出选择了自定义目录。
- 设置 → 图形预览与导出 → 图形中间文件目录支持统一的 Vault 相对目录。留空恢复逐笔记默认位置。非法路径就地提示，不替换之前保存的配置。
- 生成及预览请求冻结当时配置。更改位置影响后续请求；重试遵循已保存记录，不迁移既有成功输出。

## 实现与取舍

v2 恢复记录将输出文件名前缀与记录自身位置分开保存。输出文件名保留批次 UUID，避免覆盖其他批次或用户修改；原生源文件、图形 HTML 和结构化 HTML 使用不同后缀。

Drawnix 源文件 metadata、图形清单及附件记录同时重写为批次隔离的 Vault 相对路径，已有源文件预览读取器支持此类路径。发布后仅删除本次拥有的 `.pending` 暂存文件；恢复记录与附件仍支持重试及源图形，因此保留。

v1 解码器保留旧目录布局与哈希收据。发布继续使用暂存校验后 rename；恢复记录通过宿主串行 `adapter.process` 更新。目录初始化允许独立批次并发创建。演示导出继续使用独立配置和环境依赖。

## 矢量 PDF 关系标签

问题 PDF 的文本层包含全部五条中文关系，但每个标签内部的可见深色像素均为零。SVG 要求 4px 白色文字描边先于填充绘制，而 svg2pdf 固定输出先填充、后描边（`2 Tr`），覆盖了字形。新 Drawnix 渲染去掉多余描边，因为标签已有背景框；PDF 解析器也会为旧缓存 SVG 中带标记且有背景框的关系标签及其 tspan 禁用该描边，无关文字描边保持不变。真实 Chromium/svg2pdf 回归检查 PDF 文字绘制指令；宿主光栅检查另行验证可见字形，不以文本可提取替代视觉证据。
