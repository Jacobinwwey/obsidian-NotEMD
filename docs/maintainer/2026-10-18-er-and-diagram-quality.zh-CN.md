## ER 质量差距的生成链路根因

1. ER 提示仍属于通用 legacy 家族，没有真正的字段／键／引用结构。模型没有被要求生成的语义，无法靠换颜色补回来。
2. erAdapter.ts 将显示名称转成 ASCII 标识并大写；不同中文实体都可能变为 __，导致实体和关系合并。
3. 通用 children 无法表达 PK+FK／UK、原始注释、校验后的 FK 目标及两端独立可选性；无字段时还会凭空生成 string id。
4. 可编辑 SVG／Draw.io 使用 semanticFigureModel，把字段扁平化成独立卡片，无法获得真正的表格、表内字段与原生基数标记。
5. HTML、Mermaid、可编辑输出使用不同表示；原来的两表、各一个字段的例子没有暴露语义损失。
6. 通用固定卡片标题预算会拒绝实际上能扩展容纳的 ER 场景，并意外降级为 Mermaid。现在 ER 的文本容量由专属测量布局负责。

## 本次已落地链路

源笔记 → ER v2 提示配置 → JSON 响应解析 → entity-relationship 规范载荷 → 边界验证 → 共用测量场景 → 各格式序列化与规范 SVG 预览。

- 实体 id 与显示名称分离；字段保留原名、原始类型、注释、多个 PK／FK／UK 角色及 references { entity, attribute }。
- 在语义边界拒绝重复实体／字段、未知键角色、缺失 FK 目标、悬空引用和缺失关系端点／基数；ER 载荷不能冒充其他图表类型。
- 关系两端分别表达 one、zero-or-one、one-or-many、zero-or-many、unspecified，识别关系属性与基数分离。
- 测量键／字段名／类型／说明列宽、字段行高和实际端口容量；通过扩展表格保留字段。标签影响间距，正交 A* 路由避开实体内部，分散端口并支持自关联、平行关系。
- SVG 在表边绘制鱼尾、可选圆、必选竖线、未知标记和按实际键角色生成的图例。独立 HTML 提供可键盘展开、可选字的字段索引及离线 CSP；支持明暗样式，宽图使用有可读性下限的缩放／横向滚动。
- Mermaid 保留显示别名、SQL 标点、键列表、注释和 FK 目标。不能无损表达的名字会明确拒绝并建议其他格式；不支持的类型完整写入注释，不能静默丢弃。缺失类型显式为 unknown，不编造 string。
- Mermaid 无法忠实表达未知基数或未知识别关系状态。对于新的规范输入，明确提示选择 HTML/SVG、Draw.io 或补充来源，不猜测、不伪报转换成功。旧输入继续保留原有基数默认，并明确披露兼容行为。
- Draw.io 使用真正的 table／tableRow／cell、保留 XML 属性中的换行、原生 ER 端点标记与同源路由折点。“必选一”使用经上游 Draw.io ER 面板核实的 ERmandOne，而不是视觉含义不同的 ERone。
- Mermaid、HTML、可编辑 HTML/SVG、Draw.io 共享同一规范表格 SVG；这是预览与导出语义统一，不是声称 Mermaid 外部引擎或原生 Draw.io 打开后像素完全相同。
- ER 提示禁止以密度预算删字段／注释。新的三表样例覆盖复合键、FK 目标、原始类型与独立关系线型。默认输出和用户配置不变。

## 修复后额外复现并修复的 5 项问题

下列五项回归均先确认失败，再修改实现：

- 类图的中文类型名被合并为同一标识；现在使用防碰撞标识和可读别名。
- 时序图的 api-gateway 与 api_gateway 被合并，真实请求变成自发消息；声明和消息现在共用参与者标识映射。
- 树图遍历会隐藏不连通／无根环关系。现在以有限组件遍历保留全部来源节点与边（包括自环、森林），通过可见说明和橙色虚线标注非树结构，不再阻止出图。
- 固定 1040px 树图在十兄弟节点时产生负间距：宽 170px 的节点只相隔约 102.73px。现在画布按最宽层扩展，至少保留 24px 兄弟间距。
- lane-grid 关系曾指向没有步骤内容的空白。现在对已声明坐标内被引用的缺失步骤绘制“未提供步骤”占位，保留原交接而不编造业务内容，说明随图导出；未知坐标仍属无效。适用于 data-flow／process，不擅自改变另一套旧 Mermaid swimlane 模型。

这不表示类图／时序图已经获得完整专属 SVG／Draw.io 语义；它们的通用可编辑卡片投影仍属于已知局限。

## 跨图型优化优先级与验收契约

反复出现的问题是布局之前就已经丢失语义。所研究的 Archify 各图型契约真正值得借鉴的是：每种记法拥有自己的事实模型与容量规则，而不是照搬配色，或者让 33 个目录条目全部通过同一个卡片模型。下面是建议的后续投入顺序，不是额外已实现的功能。

1. **先做类图与时序图。** 类图生成必须先表达属性／方法、可见性、关系种类，SVG 分区才能忠实；时序图必须先表达有序消息／事件、返回、激活、片段作用域，原生生命线才有依据。当前标识修复只防止合并，不会补出这些事实。验收：中英文及碰撞标识始终独立；每项已提供成员／消息在各支持格式中保留；不支持的记法明确拒绝，不得退化为普通箭头。覆盖递归、并行片段、空类与长签名。
2. **随后是架构与集成拓扑。** 当前拓扑校验已拥有节点／区域，但密集连线需要边界端口与避障走廊，不是更多中点偏移。现状事实必须与目标态建议分开。验收：连线不穿越无关节点内部；端口挂接经原生编辑后仍成立；交叉与标签－路由冲突有测量、有披露。覆盖高扇出中心、反向连线、嵌套区域、断开的分量；只查节点重叠不够。
3. **树图、组织图与知识图。** 宽树修复确立了非负兄弟间距，但不等于最优层次构图。应按子树分配跨度，父节点对齐后代中心，并提供明确细节视图而不删分支。组织归属与 Drawnix 跨分支连线仍各自拥有契约。验收：全部节点按声明可达；父子／归属关系在导出后保留；Drawnix 跨分支箭头必须在原生应用验证挂接，不能从静态 SVG 推断。覆盖不对称深树与宽叶子序列。
4. **流程、泳道与数据流。** 端点单元存在是必要条件，但不能证明参与者交接、分支结果或载荷传递正确。即使共享泳道几何，流程与数据流语义也应分开。验收：所有边解析到原文步骤，或已声明坐标内明确标注的未提供步骤占位；分支结果与跨泳道归属可见；长标签拥有经过测量的走廊；不得凭空补出空步骤、数据存储或传递。旧泳道迁移必须明确转换契约。
5. **时间与定量图表。** 时间线的事件顺序、甘特的持续时间、执行瀑布是不同语义；雷达、柱、线、散点也必须先有单位、缺失值与比例尺策略，再做美化。验收：导出数值与来源一致；明确披露时间轴是否等比例或仅顺序；缺失观测仍然缺失；不得补造关键路径、插值、不确定性、因果结论。提供表格替代，并检查最终导出尺寸的文字，而不只是 viewBox 边界。Archify 的 ER 几何不能替代 Vega-Lite。
6. **矩阵、集合与排序／结构图。** 权限矩阵应通过版本化契约区分未知与明确拒绝；Venn 面积、漏斗宽度若只是示意，应明确说明；嵌套／层叠／medallion 保留包含与顺序，不得用厚度暗示数量。验收：导出后仍能识别来源事实；缺失不被转换为零／无权限；键盘与文本替代保留行列／成员关系上下文。

每种后续图型都应贯穿同一验收链：有来源依据的提示词夹具 → 类型化载荷校验 → 测量场景 → 目标格式能力检查 → 规范预览 → 导出／原生消费证据。跨格式必须比较同一个等价来源，并覆盖长中文标签、未知事实与容量上限。结构测试证明语义；浏览器几何证明局部可读性；原生编辑器往返证明可编辑性，三者不能相互替代。现有已完成的预览与 ER 工作应复用，不为推进该路线重复重写。
