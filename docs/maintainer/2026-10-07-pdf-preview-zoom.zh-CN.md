# PDF 预览缩放：根因、修复与证据

[English](./2026-10-07-pdf-preview-zoom.md)

后续的[可见窗口实机验收](./2026-10-07-pdf-preview-native-acceptance.zh-CN.md)已在真实屏幕密度下验证安装后的 1.9.14 候选，没有覆盖可见性或设备像素比。下文保留此前模拟密度的验证记录。

## 根因

二进制预览原先只渲染每页一次，每个 PDF 单位最多对应 1.5 个像素，还受整份文档底图预算限制。通用视口随后通过 CSS 把同一画布放大至 8 倍，因此源 PDF 的矢量也变成了被放大的低分辨率像素。这是预览问题，与导出 PDF 的页面尺寸无关。

本机存在多份 architecture PDF。`slidev-acceptance-20261006-final/architecture.zh-CN.pdf` 的第三页包含 Mermaid 架构图：全篇 36 页，页面为 735.12 × 414，含 289 个 `constructPath` 操作、80 个文字项，没有位图绘制操作。同名 fork-fixed 验收文档第三页仅有标题，没有用它证明图表清晰度。当前打开的 Drawnix PDF 是另一份单页文件。

## 实现

`DiagramPreviewViewport` 在缩放锚点对应的滚动位置更新后，发布倍率、设备像素密度和可见源区域。区域经过视口、窗口及滚动祖先裁剪；锁定导航后仍会报告可见性和外层滚动变化。

`PdfPreviewDetailRenderer` 为每份文档维护一个活动 PDF 渲染任务。重绘可见区域及 64 CSS 像素余量，取消过时任务，显示前校验版本，并在小幅平移时复用画布。页面和文字层坐标保持稳定，高清画布不截获指针事件，且位于原有文字层 DOM 下方。

每份文档底图预算约为 3200 万像素。高清画布单块限制为 800 万像素／8192 像素单边，显示中及替换中的画布共用 2400 万像素预算。底图也受单边限制：仅限制面积无法防护人工构造的 1,000,000 × 100 页面。这是兼容性测试，并非用户 PDF 的实际形状。关闭时取消任务并释放画布及 PDF 资源；源文件与导出页几何尺寸保持不变。

## 证据

- 新测试先因缺少自适应重绘而失败，实现后相关套件通过。额外狭长页回归先复现 200,000 像素宽画布，再加入限制。
- 原生 Obsidian CLI：36 个独立页面；第三页 8 倍缩放，模拟 DPR 1 与 2；对应渲染密度 8 与 16，画布分别为 807,975 和 3,231,900 像素；测量时仅有一个高清画布。
- 独立 PDF.js 原页渲染对比：DPR 2 的通道平均绝对差为 0.00587（范围 0–255），来自 CSS 小数坐标序列化舍入；验收容差为 0.05。旧底图放大后的相同指标为 3.43954。保存的画布图可明显区分清晰标签／路径与旧底图的模糊效果。
- 快速平移替换画布，文字层对象保持不变。Alt 阻止缩放／滚动，DOM Range 可选字。滚出屏幕释放高清画布，关闭后全部跟踪画布尺寸归零。源文件 SHA-256 和配置保持一致。
- CLI 在后台 vault 中临时模拟可见性及 DPR，结束后恢复。这是原生 PDF.js 画布证据，并非桌面截图或物理鼠标选字证明。
- 凭据：`.cache/pdf-source-inventory.json`、`.cache/pdf-zoom-native.json`、`.cache/pdf-zoom-native-page3-sharp.png`、`.cache/pdf-zoom-native-page3-old-magnified.png`。独立 Drawnix PDF 及 PNG 也通过二进制预览／Alt 检查。
- 首次全量集成检查有 315 个套件通过，另一个套件发现文档缺少语言配对。已补充独立的多格式中文文档，并通过针对性文档测试；最终发布检查完成后单独记录。

## 限制

在画布预算允许的范围内，预览能按所需密度清晰重绘 PDF 矢量，但不能恢复嵌入位图本来就不存在的细节。极大屏幕可能降低采样密度；未增加 OCR。预览缩放与导出 PNG 的 PPI 相互独立。

## 发布候选检查

新插件构建、界面字符串审计、渲染包审计、diff 检查及 lint 增量检查通过（20 个变动 TypeScript 文件，零新增问题）。网站 34 个语言版本全部构建；将过时的单格式菜单检查更新为复选框流程后，内容审计通过。导航／可访问性审计覆盖 96 个页面，零失败。翻译路由、标题结构及源文件哈希测试通过。

最终本地全量运行执行 316 个套件：313 个通过，三个在并行构建负载下出现进程／浏览器超时（3065 项通过、12 项失败、1 项跳过）。网站构建结束后，失败的发布器用例在 12.7 秒内通过；受影响的两个浏览器文件共 23 项在 18.9 秒内全部通过。没有为了复跑通过而放宽超时或修改产品代码。这是全量运行加失败项独立复验，并非一次不中断的全量绿灯；远端 Linux／Windows 检查仍是合入门禁。
