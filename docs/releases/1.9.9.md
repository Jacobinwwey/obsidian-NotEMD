# Notemd v1.9.9

## Highlights

- **Generate multiple diagram types in one run.** Each type owns its output selections. For example, generate a Drawnix source and PDF alongside a flowchart SVG, without changing another type’s formats. Deselection preserves preferences; an empty type selection uses automatic analysis.
- **Choose with a live preview.** Compact type and format menus replace the flat checklist. Checkboxes include types; clicking a name selects that type and opens its formats. Hover and keyboard focus update the adjacent preview without saving. Supported formats appear first, while incompatible choices remain visible and disabled.
- **Find exports beside the source.** Selected files use type-specific names such as `topic_drawnix.pdf` and `topic_flowchart.svg`. Numeric suffixes resolve collisions without overwriting existing files. A configured output folder remains supported.

## Fixes And Robustness

- Freeze source content, selection and execution settings for sequential multi-type generation. One type’s failure does not block the others. Cancellation stops pending types, preserves completed files and uses a continuous progress channel.
- Save each type’s generated specification and per-format delivery receipts. Retry failed exports from preview, history or the maintainer CLI without another model call. A failure before generation completes still requires generating that type again.
- Store recovery records, cached renders, staging files and optional attachments in a configurable Vault-relative intermediate folder. The default is `notemd_assert/` beside each source. Changing the folder affects new runs only; retain files referenced by existing artifacts.
- Read existing v1/v2 export records and write v3 records with cache identifiers independent of delivery names. Recovery checks SHA-256 receipts and preserves user-modified outputs. Name allocation covers concurrent and case-insensitive collisions.
- Keep up to six labeled, directed core relations in Drawnix overviews, at most three per node. Omitted relations remain in native metadata with reasons. Local routes reduce unnecessary long connectors.
- Keep boxed Drawnix relation text visible in vector PDF. Normalize older cached SVG labels before PDF conversion so their white text outline does not obscure glyphs.
- Preserve UTF-8 through generation, storage and recovery. Fix real Obsidian manifest writes and normalize quoted evidence at the input boundary. This repairs the user workflow rather than patching individual demonstration files.
- Preserve Escape ownership, keyboard focus, serialized settings saves and popout document boundaries. The preview stays visible while the type list scrolls and returns to its original position when the menu closes.

## Documentation And Format Boundaries

- Update the manuals, README files, homepage and upgrade guides with directly authored translations across the existing 34 website locales and 31 README editions. No translation API, LM Studio or other translation model was used. This is not independent native-speaker review; indexing policy remains unchanged.
- **Diagram HTML** contains a zoomable graphic. **Structured-summary HTML** contains text, structure and evidence. “Editable HTML/SVG” names a renderer, not a browser editor; use native source for editing.
- Presentation export retains separate settings, libraries and environment checks. PPTX and MP4 belong to that workflow and are not added to the diagram format selector.
- The existing 33 executable diagram entries, 36 provider presets and 21 plugin UI locales are not new catalogs introduced by 1.9.9.

## Verification And Evidence

- The release candidate passed 298 local Jest suites: 2,874 tests passed, with one existing skip. Plugin and documentation builds passed, including 850 website guide pages across 34 locales and 816 browser navigation scenarios. Linux and Windows verification gate publication of the release commit.
- CLI testing in the open `1Knowledge` Vault produced nine sibling files across Nested, Flowchart and Drawnix. All delivery hashes matched, the source stayed unchanged and settings were restored. A provider timeout did not block other types; a focused Drawnix retry completed its four formats.
- Real-browser checks cover 320px/900px menus, hover/focus without persistence, independent formats, Escape, preview relocation and scrolling. The PDF’s six relation labels were extracted and visually checked.
- See the [implementation evidence](https://github.com/Jacobinwwey/obsidian-NotEMD/blob/main/docs/multiple-diagrams-implementation.md) and [1.9.9 acceptance record](https://github.com/Jacobinwwey/obsidian-NotEMD/blob/main/docs/maintainer/release-1.9.9-acceptance.md) for execution boundaries and publication receipts.

## Upgrade And Known Limits

- Stop active tasks and back up the Vault. Install `main.js`, `manifest.json` and `styles.css` from the same release, preserve settings and generated files, then reload Obsidian. Check one note before running a large batch.
- Existing single-type preferences are read compatibly and migrate when edited. Unknown schema versions remain stored without being rewritten as a known version.
- Generation is sequential to bound provider and renderer contention. More selected types take more total time. Cancellation is not rollback and cannot guarantee that the provider stops generation or billing.
- Drawnix cross-branch arrows remain static and can detach after rearrangement in its editor. Physical mobile devices and Obsidian 0.15.0 are not newly verified by this release.

Required release assets: `main.js`, `manifest.json`, `styles.css`, `README.md`.
