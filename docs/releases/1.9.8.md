# Notemd v1.9.8

## Highlights

- **More predictable cancellation and recovery.** Cancellation reaches queued work, provider transports and retry waits. Late title-generation responses cannot continue guarded writes or moves. Overlapping diagram saves preserve conflicting edits and report recovery outputs.
- **Corrected native exports.** PowerPoint tables preserve independent border sides, opacity, merged-cell edges and complete collapsed-row separators beneath merged headers. CircuitikZ NAND/NOR and transmission-gate output has corrected wiring and readable mirrored labels.
- **Consistent batch retrieval.** Title-generation batches use a stable local-knowledge snapshot. Indexing tolerates notes that disappear or leave the selected scope, with frozen-corpus and retained-heap evidence kept separate from broader retrieval-quality claims.

## Fixes And Robustness

- Reuse a translation directory created by another task during folder preparation. Preserve source-folder fallback for a conflicting file or a still-missing directory, and do not claim peer-created folders as new output.
- Prevent research append and translation creation/overwrite when cancellation arrives during the final source read or output-folder preparation. Preserve completed results for writes already accepted by Vault.
- Keep history-drawer focus inside the dialog while loading and tabbing, stop Escape at the drawer, and preserve search input/caret across asynchronous refreshes. Consecutive keystrokes, filters, retry focus and late closed-view responses have real-browser regressions.
- Keep successful writes counted when cancellation prevents a later move. Preserve partial or binary outputs when safe cleanup cannot be established.
- Serialize saves with overlapping Vault paths and cover same-named sources and shared companion files. Retain existing Drawnix companion directories for inspection instead of assuming they are unused.
- Add a targeted native PowerPoint assertion for the previously missed half-width separator. DrawingML node presence and whole-slide image scores cannot replace this check.
- Use a verified draft publication flow: strict arguments and version/tag checks, offline preview, clean-source rebuild, frozen upload bytes, draft-first upload and downloaded SHA-256 verification.
- Constrain same-tag retries to matching candidate provenance. Authentication/network failures cannot be mistaken for a missing release, and existing public assets cannot be silently overwritten.
- Install both locked Chromium revisions in the release workflow and treat dispatch input as validated data before using it.

## Documentation And Discoverability

- Preserve inline path and identifier punctuation in right-to-left guides, with a rendered-glyph check for the leading dot in `.obsidian`. Browser coverage includes keyboard journeys to the current upgrade guide and FAQ.
- Use actual UI control names in task guidance. Keep documentation table headers visible across light/dark themes and preserve Korean word boundaries on narrow screens; browser checks cover transparent header text as well as contrast and navigation.
- Correct guides against actual workflow IDs, settings, output paths and provider behavior. The default One-Click Extract sequence remains add-links → batch title generation → batch Mermaid repair.
- Provide explicit newcomer, user, developer and Agent entry points, with a dedicated upgrade guide and a working contribution entry.
- Separate 36 provider presets, 21 plugin UI locales and 34 website locale routes. The provider and 33-entry diagram catalogs already existed in 1.9.7 and are not counted as new 1.9.8 features.
- Author and review translated documentation directly with Codex, without LM Studio or translation-engine calls. AI authorship is not independent native-speaker review; indexability remains a separate publication decision.
- Keep release facts aligned across metadata and documentation while preserving the real date/tag of historical development chronicles. Replace unsupported offline, platform and competitor claims with explicit implementation boundaries.

- Release process tests exercise real temporary Git repositories, rebuilding and hashing, with the remote boundary controlled for upload interruption, corrupt downloads, lookup errors, draft discovery and idempotent retries.

The [1.9.8 acceptance record](https://github.com/Jacobinwwey/obsidian-NotEMD/blob/main/docs/maintainer/release-1.9.8-acceptance.md) preserves candidate hashes, execution receipts and limitations.

## Upgrade And Known Limits

- Preserve settings and existing command IDs. Stop active tasks, back up the Vault, install runtime files from the same release, reload and inspect a disposable note before resuming large batches.
- Cancellation is not rollback and cannot guarantee that an upstream service stops generation or billing. Completed writes and recovery files may remain.
- Drawnix cross-branch arrows remain static relationships and can detach after application rearrangement. Mermaid/SVG content in PPTX can remain an image fallback rather than editable native shapes.
- Physical mobile devices and Obsidian 0.15.0 remain unverified; the manifest minimum is not a fresh compatibility test. Optional native exporters have separate dependencies.
- Lexical retrieval evidence, including the frozen Top-3 result of 7/9 positive cases, does not prove semantic-search quality or performance on arbitrary Vaults.

Required release assets: `main.js`, `manifest.json`, `styles.css`, `README.md`.
