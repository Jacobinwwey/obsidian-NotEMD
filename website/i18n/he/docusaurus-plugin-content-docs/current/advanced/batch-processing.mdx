# עיבוד באצווה

<TLDR>פעולות תיקייה חולקות בחירה ודיווח התקדמות, אך לא כללי דריסה. ברירת המחדל למקביליות היא אחת. התחילו בתיקיית ניסיון קטנה, בדקו היקף ויעדים ורק אז הרחיבו.</TLDR>

## סקירה

סרגל הצד/סייר הקבצים מציעים קישורים, מושגים, כותרות, תרגום, קטעים מקוריים ותיקוני Mermaid ונוסחאות לתיקיות. אין פעולת מחקר כללית לתיקייה; יצירה מכותרת יכולה להוסיף מחקר. אצווה אינה עסקת תיקייה: תוצרים שהושלמו נשמרים בשגיאה או בביטול.

## אופן הפעולה

### מודל ביצוע

1. בחרו משימה ותיקייה עם הקבצים הרצויים בלבד.
2. סיומות, בחירה ומסנני פלט ייעודיים למשימה קובעים מועמדים.
3. המשימה משתמשת בספק/מודל שלה ומדווחת מצב, שגיאות ונתיבים.
4. בדקו דוח ותוצרים אחרי סיום/ביטול ולפני הרצה חוזרת.

קישורים, מושגים, כותרות, קטעים מקוריים, Mermaid ונוסחאות כוללים תתי־תיקיות כברירת מחדל. **תרגום תיקייה כולל כברירת מחדל רק ילדים ישירים.** מצב מפתח ופרופילי בחירת קבצים מתקדמים יכולים לשנות היקף ומסננים. בדקו התאמות בפועל.

### דריסה

| משימה | בדיקה לפני חזרה |
| ------ | ------------------------------------ |
| קישורים | תוצאה נפרדת כברירת מחדל; בדקו סיומת, תיקייה והעברת מקור |
| מושגים | קישורי חזרה פעילים יכולים להשלים הערות קיימות; כפילויות בנפרד |
| יצירה מכותרות | כתיבה למקורות מתאימים ואז העברה אם יעד complete פנוי |
| תרגום | תרגום קיים עשוי להתחלף; ברירת מחדל `_<language>.md` |
| Mermaid / נוסחאות | שינוי הערות נבחרות; בדקו וגבו |

אין אפשרות כללית לדלג/להוסיף/להחליף. יעד complete תפוס חוסם העברה אחרי יצירה מכותרת, לא את היצירה שכבר קדמה לה. יצירה והעברה נספרות בנפרד.

### מקביליות

שמרו `batchConcurrency: 1` עד שמדגם מצליח. חלק מהמסלולים דורשים גם `enableBatchParallelism`; תרגום תיקייה משתמש במקביליות ישירות. יותר מקביליות מעמיסה ספק, זיכרון ושרת מקומי ללא הבטחת מהירות. מרווחי בקשות/קבוצות אינם מונעים כל מכסה או שימוש אחר באותו חשבון.

## הגדרות

| הגדרה | ערך התחלתי | השפעה |
| --------- | --------- | -------- |
| `batchConcurrency` | `1` | מקביליות מבוקשת במסלולים מתאימים |
| `enableBatchParallelism` | `false` | הפעלת תזמון מקביל נתמך |
| `batchSize` | `50` | גודל קבוצה בתזמון קבוצתי |
| `batchInterDelayMs` | `1000` | השהיה בין קבוצות מתוזמנות |
| `apiCallIntervalMs` | `500` | מרווח בין בקשות API מקבילות |
| `folderTaskIncludeSubfoldersMode` | `legacy` | שימור כללי תתי־התיקיות של כל משימה |
| `enableStableApiCall` | `false` | מצב בקשות יציב מפורש |

### מודלים למשימות

פעולות תיקייה עוקבות אחרי בחירת המודל במשימת הקובץ המקבילה. בדקו מסלולים לפני מידע פרטי. הקשר מקומי באצוות כותרות משתמש בתמונת מצב אחת מההתחלה; עריכות במהלך הריצה אינן מתערבבות באחזורים המאוחרים. התחילו אצווה חדשה כדי לכלול אותן.

## דוגמה

צרו `trial-titles` עם שתי הערות כותרת. הריצו **Batch generate from titles** ובדקו תוכן, `trial-titles_complete` סמוכה וספירות יצירה/העברה/שגיאה. חקרו את הקובץ שנכשל תחילה. הרצה חוזרת של תיקיית המקור אינה מחדשת אוטומטית רק את העבודה שנותרה.

## ביטול ושחזור

ביטול עוצר תזמון חדש ובקשות נתמכות. מערכת חיצונית יכולה לסיים בקשה/כתיבה שכבר התקבלה; החיוב בשליטת הספק. המתינו, השוו קבצים מוכנים לנתיבי שחזור/התנגשות ונקו רק לאחר בדיקה.

## עצות

- בדקו את בחירת הקבצים האמיתית בפרופיל.
- ב־429 הקטינו מקביליות ובדקו מכסות.
- הבדילו בין מבוטל, נכשל והושלם.
- שמרו דוגמה שלא שונתה וגיבוי.
