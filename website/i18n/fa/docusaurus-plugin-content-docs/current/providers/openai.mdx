# ارائه‌دهندهٔ OpenAI

<TLDR>نمایهٔ OpenAI مسیر مشترک Chat Completions را به کار می‌گیرد. کلید و مدل پذیرندهٔ این پروتکل را انتخاب کنید. مدل اولیه دسترسی فعلی یا کیفیت همگانی را تضمین نمی‌کند.</TLDR>

## آماده‌سازی

برای سرویس رسمی **OpenAI**، کلید و `https://api.openai.com/v1` را تنظیم کنید. حضور در فهرست، مدل مخصوص API دیگر را سازگار نمی‌کند. درگاه نمایه و header خودش را دارد؛ Azure از **Azure OpenAI**، deployment و نسخهٔ API استفاده می‌کند.

## نشانی و احراز هویت

| فیلد | مقدار اولیه |
| ------- | -------------- |
| پروتکل | `openai-compatible` |
| کلید API | الزامی |
| نشانی پایه | `https://api.openai.com/v1` |
| مدل | `gpt-4o` |
| دما | `0.5` |
| آزمون اتصال | `models-then-chat` |

شکل‌های شناخته‌شدهٔ نشانی پیش از ساخت مسیر نرمال می‌شوند. از نمایه شروع و نشانی نهایی را ببینید؛ قطعهٔ مسیر را تصادفی اضافه نکنید.

## مدل‌ها

**Fetch models** فهرست را درخواست می‌کند؛ **آزمایش اتصال** ممکن است فقط از همان موفق شود. مدل دقیق را با یادداشت بیازمایید. استدلال، thinking، نمونه‌گیری و بودجه باید با قواعد مدل و نمایه مطابق باشند.

## رفع خطا

- 401 یا 403: کلید، پروژه، حق دسترسی و حساب.
- 404: endpoint، شناسه و سازگاری API.
- فهرست موفق و تولید ناموفق: خطای chat و پارامترها.
- پاسخ بلند قطع‌شده: ورودی، بودجه و پاسخ واقعی را ببینید؛ آزمون کوتاه کافی نیست.

## کاربرد مناسب

برای endpoint مستقیم OpenAI با Chat Completions. یادداشت خود را ارزیابی کنید؛ قیمت و دسترسی مدل مستقل از Notemd تغییر می‌کنند.
