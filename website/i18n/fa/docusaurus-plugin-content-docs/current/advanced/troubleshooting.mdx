# رفع خطا

<TLDR>با ارائه‌دهنده، مدل و تنظیمات دقیق روی یادداشت آزمایشی بازتولید کنید. پیشرفت و مسیر خروجی را ببینید. احراز هویت، تولید، تحلیل و نوشتن مرزهای جدا هستند؛ اتصال موفق کل گردش‌کار را تأیید نمی‌کند.</TLDR>

## نمای کلی

نسخهٔ Notemd و Obsidian، سیستم‌عامل، عمل، پروتکل، مدل و حداقل مراحل را ثبت کنید. تا پایان لغو کار تازه شروع نکنید. خروجی و بازیابی را تا روشن شدن منشأ نگه دارید.

## تشخیص

### آزمون اتصال

**آزمایش اتصال** بسته به نمایه فقط فهرست یا تولید کوتاه را بررسی می‌کند. سپس کار واقعی کوچک را برای مدل و قرارداد خروجی اجرا کنید.

### پیشرفت و تشخیص توسعه‌دهنده

پیشرفت وضعیت، خطا و مقصد و فعالیت API درخواست منتظر یا پایان‌یافته را نشان می‌دهد. debug را فقط در صورت نیاز روشن کنید. تشخیص طولانی ممکن است سهمیه مصرف کند. گزارش ممکن است متن، پاسخ جزئی، نشانی و کلید داشته باشد؛ پیش از اشتراک محلی پاک‌سازی کنید. metadata نمایهٔ پاک‌شده هم باید بررسی شود.

## خطاهای رایج

### کلید نامعتبر یا خالی

401: کلید مربوط به همین نشانی و ارائه‌دهنده، بدون فاصلهٔ اضافی. 403: مجوز حساب و پروژه، دسترسی مدل و پرداخت. تلاش دوباره اطلاعات ورود اشتباه را اصلاح نمی‌کند.

### شبکه

میزبان، درگاه، پروتکل و مسیر را از دستگاه Obsidian بررسی کنید. Ollama یا LM Studio باید با مدل آماده اجرا باشند. `localhost` همان دستگاه است نه رایانهٔ دیگر. نمایهٔ درست انتخاب کنید؛ fallback خودکار است، نه کلید انتخاب transport در UI.

### محدودیت 429

هم‌زمانی را کاهش و سهمیهٔ درخواست و token و مشتری‌های دیگر همان کلید را بررسی کنید. تکرار تنها برخی خطاهای موقت را حل می‌کند.

### مدل پیدا نمی‌شود

**Fetch models** یا نام دقیق مدل/deployment مجاز را استفاده کنید. نسخهٔ API و منطقه را ببینید؛ مدل اولیهٔ تاریخی ممکن است حذف شده باشد. Azure نام deployment و Ark گاهی endpoint ID می‌خواهد.

### مفهوم یا پیوندی نیست

فایل واقعی خروجی، مفید بودن اصل، قالب پاسخ و پوشهٔ مفهوم غیرخالی فعال را بررسی کنید. استخراج مستقل ابتدا فقط عنوان و بدون backlink است. اگر prompt نشانه را حذف کرده، با دستور داخلی مقایسه کنید.

### خروجی نیست یا جای دیگر است

مسیر گزارش‌شدهٔ `_processed.md`، `_<language>.md` یا complete را بخوانید. شکست ساخت پوشهٔ ترجمه می‌تواند به ذخیره کنار اصل منجر شود. تداخل و مجوز را قبل از تکرار بررسی کنید.

### فایل پس از لغو باقی مانده

نوشتهٔ کامل باقی می‌ماند و درخواست یا نوشتن پذیرفته‌شده می‌تواند تمام شود. نتیجهٔ هر فایل و تعارض بازیابی را پیش از حذف یا تکرار گروه ببینید.

### نمودار یا خروجی بومی

نوع‌ها به‌ترتیب تولید می‌شوند. خطای یکی مانع بقیه نیست؛ لغو، نوع‌های منتظر را متوقف و فایل‌های کامل را حفظ می‌کند. خروجی را از پیش‌نمایش یا تاریخچه بدون درخواست تازه از مدل دوباره امتحان کنید. خطای تولید نیازمند تولید مجدد همان نوع است. سوابق v1/v2 همچنان خواندنی‌اند.

HTML نمودار شامل تصویر قابل بزرگ‌نمایی است؛ HTML خلاصهٔ ساختاریافته متن، ساختار و ارجاعات را دارد. HTML/SVG قابل ویرایش نام رندرکننده است، نه ویرایشگر مرورگر. برای ویرایش از منبع بومی استفاده کنید. خروجی ارائه، از جمله PPTX و MP4، تنظیمات و وابستگی‌های جداگانه دارد. [راهنمای نمودارها](../features/diagrams).

## گزارش مشکل

1. با متن ساختگی کوچک و پوشهٔ اختصاصی بازتولید کنید.
2. نسخه، عمل، مدل، تنظیم لازم و نتیجهٔ انتظار/واقعی را ثبت کنید.
3. کمترین فایل و گزارش را بدون راز، متن خصوصی و نشانی اضافی پیوست کنید.
4. مشخص کنید روی یک فایل و دستور داخلی هم رخ می‌دهد یا نه.
5. در [GitHub Issues](https://github.com/Jacobinwwey/obsidian-NotEMD/issues) گزارش دهید.

تصویر صفحه به‌تنهایی معمولاً خطای قالب یا لغو را ثابت نمی‌کند. در صورت امکان اصل و خروجی یا ترتیب حداقلی بازتولید بدهید.
