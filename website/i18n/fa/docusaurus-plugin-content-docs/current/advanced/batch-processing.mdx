# پردازش گروهی

<TLDR>کارهای پوشه انتخاب و پیشرفت را به‌اشتراک می‌گذارند، اما رفتار ذخیره و بازنویسی یکسان نیست. هم‌زمانی اولیه یک است. ابتدا در پوشهٔ آزمایشی محدوده و مقصد را بررسی و بعد گسترده‌تر اجرا کنید.</TLDR>

## نمای کلی

از نوار کناری یا منوی پوشه برای پیوند، مفهوم، عنوان، ترجمه، متن اصلی و ترمیم Mermaid یا فرمول استفاده کنید. پژوهش عمومی پوشه وجود ندارد؛ تولید عنوان می‌تواند پژوهش را اضافه کند. گروه تراکنش واحد نیست؛ خروجی کامل با خطای فایل دیگر یا لغو باقی می‌ماند.

## روش کار

### مدل اجرا

1. کار و پوشهٔ دارای فایل‌های مطلوب را انتخاب کنید.
2. قواعد پسوند، انتخاب و استثنای خروجی هر کار اعمال می‌شود.
3. مدل همان کار استفاده و پیشرفت، خطا و مقصد گزارش می‌شود.
4. پس از پایان یا لغو، گزارش و فایل را پیش از تکرار ببینید.

پیوند، مفهوم، عنوان، متن اصلی، Mermaid و فرمول ابتدا زیرپوشه را هم شامل می‌شوند. **ترجمهٔ پوشه فقط فرزندان مستقیم را به‌طور اولیه می‌گیرد.** حالت توسعه‌دهنده همراه انتخاب پیشرفته می‌تواند محدوده و فیلتر را تغییر دهد؛ تطابق واقعی نمایه را بررسی کنید.

### بازنویسی

| کار | بررسی پیش از تکرار |
| ------ | ------------------------------------ |
| پیوند | خروجی اولیه جدا؛ پسوند، پوشه و انتقال اصل را ببینید |
| مفهوم | امکان افزودن پیوند بازگشت فعال؛ بررسی تکرار جداست |
| تولید از عنوان | نوشتن در اصل واجد شرایط و سپس انتقال در صورت آزاد بودن complete |
| ترجمه | امکان جایگزینی ترجمهٔ موجود؛ معمولاً `_<language>.md` |
| Mermaid و فرمول | یادداشت منتخب را تغییر می‌دهند؛ نمونه و پشتیبان لازم است |

گزینهٔ همگانی ردکردن، افزودن یا جایگزینی نیست. مقصد complete اشغال‌شده جلوی انتقال را می‌گیرد، نه تولید متن پیش از آن را. تعداد تولیدشده و منتقل‌شده جدا گزارش می‌شود.

### هم‌زمانی

تا موفق شدن نمونه `batchConcurrency: 1` را نگه دارید. بعضی مسیرها `enableBatchParallelism` هم می‌خواهند، اما ترجمه مقدار هم‌زمانی را مستقیم استفاده می‌کند. افزایش آن فشار مدل، حافظه و سرور را زیاد می‌کند و سرعت را تضمین نمی‌کند. فاصلهٔ درخواست و گروه هم تمام محدودیت‌های حساب یا مشتری دیگر را حذف نمی‌کند.

## تنظیمات

| تنظیم | مقدار اولیه | اثر |
| --------- | --------- | -------- |
| `batchConcurrency` | `1` | هم‌زمانی درخواستی در مسیر مربوط |
| `enableBatchParallelism` | `false` | زمان‌بندی موازی پشتیبانی‌شده |
| `batchSize` | `50` | اندازهٔ گروه در زمان‌بندی گروهی |
| `batchInterDelayMs` | `1000` | مکث میان گروه‌های زمان‌بندی‌شده |
| `apiCallIntervalMs` | `500` | فاصلهٔ درخواست هم‌زمان API |
| `folderTaskIncludeSubfoldersMode` | `legacy` | حفظ محدودهٔ پیشین زیرپوشه برای هر کار |
| `enableStableApiCall` | `false` | حالت صریح درخواست پایدار |

### مدل کار در گروه

همان مسیر مدل کار تک‌فایل به کار می‌رود. پیش از دادهٔ خصوصی آن را بررسی کنید. بازیابی محلی عنوان گروهی یک snapshot در آغاز می‌سازد؛ ویرایش حین اجرا با نتیجهٔ بعدی مخلوط نمی‌شود. برای شامل کردن تغییرات گروه تازه شروع کنید.

## نمونه

در `trial-titles` دو یادداشت عنوان بدون فایل نامرتبط بسازید و **تولید دسته‌ای از عنوان‌ها** را اجرا کنید. محتوا، پوشهٔ هم‌سطح `trial-titles_complete` و شمار تولید، انتقال و خطا را ببینید. شکست هر فایل را جدا حل کنید؛ اجرای دوبارهٔ پوشه ادامهٔ خودکار دقیق کار ناتمام نیست.

## لغو و بازیابی

لغو زمان‌بندی تازه را متوقف و به درخواست پشتیبانی‌شده می‌رساند. درخواست یا نوشتن پذیرفته‌شدهٔ بیرونی ممکن است تمام شود و هزینه به ارائه‌دهنده وابسته است. منتظر پایان بمانید و خروجی و تعارض بازیابی را مقایسه کنید؛ نسخهٔ بازیابی را تا بررسی نگه دارید.

## نکته‌ها

- فایل‌های واقعاً انتخاب‌شدهٔ نمایه را ببینید.
- در 429 هم‌زمانی و سهمیه را بررسی کنید.
- لغو، شکست و تکمیل را جدا نگه دارید.
- قبل از ویرایش موجودها، نمونهٔ دست‌نخورده و پشتیبان داشته باشید.
