# پژوهش و جست‌وجوی وب

<TLDR>Research & summarize موضوع انتخابی یا عنوان را جست‌وجو می‌کند، از LLM خلاصهٔ زمینه را می‌خواهد و به Markdown فعال می‌افزاید. Tavily یا DuckDuckGo را صریحاً انتخاب کنید. نتیجهٔ جست‌وجو و ارجاع تولیدی نیازمند بررسی است.</TLDR>

## نمای کلی

ارائه‌دهندهٔ جست‌وجو از مدل خلاصه‌ساز جداست. Tavily کلید می‌خواهد؛ DuckDuckGo بدون کلید است ولی شبکه و محدودیت نرخ دارد. خلاصه‌ساز محلی پژوهش وب را آفلاین نمی‌کند.

## روش کار

### جست‌وجو سپس خلاصه

1. یادداشت مقصد را در Markdown باز و موضوع را انتخاب کنید یا عنوان را به کار ببرید.
2. **پژوهش و خلاصه‌سازی** را اجرا کنید.
3. Tavily گزیده برمی‌گرداند؛ DuckDuckGo ممکن است صفحهٔ نتایج را دریافت کند.
4. در صورت فعال بودن بازیابی محلی، گزیدهٔ محدودهٔ مجاز وارد prompt می‌شود.
5. مدل پژوهش خلاصه را زیر `Research Summary` با موضوع و نوع منبع اضافه می‌کند.
6. نشانی‌ها را باز و متن و نقل‌قول را تأیید کنید. زمینهٔ بازیابی‌شده تمام ادعاها را اثبات نمی‌کند.

### Tavily و DuckDuckGo

| گزینه | آماده‌سازی | محدودهٔ عملیاتی |
| -------- | ------- | ---------------------- |
| Tavily | انتخاب Tavily و کلید API | سهمیهٔ حساب و گزیده‌های برگشتی |
| DuckDuckGo | انتخاب صریح DuckDuckGo | بدون کلید؛ محدودیت جست‌وجو و دسترسی صفحه |

کلید خالی یا نامعتبر Tavily جست‌وجو را عوض نمی‌کند. نبود زمینهٔ مفید را در گزارش بررسی کنید. زمینهٔ محلی فعال و در دسترس می‌تواند هنوز مبنای خلاصه باشد؛ برچسب منبع آن را از پژوهش مبتنی بر وب جدا می‌کند.

### پژوهش هنگام تولید از عنوان

**Enable research in "Generate from title"** پژوهش را به تولید عنوان، از جمله حالت گروهی، اضافه می‌کند. ابتدا خاموش است. این مسیر پشتیبانی‌شدهٔ پوشه است و فرمان عمومی مستقل Research Folder وجود ندارد.

## تنظیمات

| تنظیم | مقدار اولیه | اثر |
| --------- | --------- | -------- |
| `searchProvider` | `tavily` | انتخاب سرویس جست‌وجو |
| `tavilyApiKey` | `''` | کلید لازم برای Tavily |
| `tavilyMaxResults` | `5` | تعداد درخواستی نتیجهٔ Tavily |
| `tavilySearchDepth` | `basic` | عمق جست‌وجوی Tavily |
| `ddgMaxResults` | `5` | تعداد درخواستی نتیجهٔ DuckDuckGo |
| `ddgFetchTimeout` | `15` | مهلت دریافت صفحه به ثانیه |
| `maxResearchContentTokens` | `3000` | بودجهٔ تقریبی زمینهٔ وب |
| `researchProvider` | `DeepSeek` | ارائه‌دهندهٔ خلاصه در مسیر اختصاصی |
| `researchModel` | `''` | خالی یعنی مدل تنظیم‌شدهٔ ارائه‌دهنده |
| `researchSummarizeLanguage` | `en` | زبان در تنظیم زبان اختصاصی |
| `enableResearchInGenerateContent` | `false` | اجازهٔ پژوهش در تولید عنوان |
| `enableLocalKnowledgeRetrieval` | `false` | فعال‌سازی مستقل بازیابی محلی |
| `enableLocalKnowledgeForResearchSummarize` | `false` | استفادهٔ این کار از بازیابی محلی |

### زمینه و مدل

محدودیت زمینه تخمینی است، نه tokenization دقیق ارائه‌دهنده. بریدن متن ممکن است شاهد را حذف کند. سؤال را متمرکز و مدل/بودجه را متناسب انتخاب کنید. نمایهٔ محلی واژگانی است؛ جست‌وجوی embedding یا بازیابی کامل را نتیجه نمی‌دهد.

## نمونه

یادداشت `کدگذاری موقعیت نسبی` بسازید و پژوهش را اجرا کنید، سپس با مقالهٔ اصلی یا مستند رسمی مقایسه کنید. سؤال، URL واقعی و اصلاح را نگه دارید تا نتیجه قابل بررسی باشد. متن مثال راهنما نتیجهٔ اجرای پژوهش در خزانهٔ شما نیست.

## لغو و حریم خصوصی

افزودهٔ کامل باقی می‌ماند و درخواست پذیرفته‌شدهٔ مدل یا صفحه می‌تواند تمام شود. سرویس جست‌وجو پرسش، سایت درخواست و LLM زمینهٔ جمع‌شده و گزیدهٔ محلی مجاز را دریافت می‌کنند. گزارش را پیش از انتشار بررسی کنید.

## نکته‌ها

- منبع وب، یادداشت محلی و استنتاج مدل را جدا کنید.
- نقل‌قول، تاریخ و ادعای مهم را در اصل بررسی کنید.
- با پرسش کوچک خطای جست‌وجو و LLM را جدا تشخیص دهید.
- برای جلوگیری از افزودن تکراری، خلاصهٔ موجود را قبل از اجرا ببینید.
