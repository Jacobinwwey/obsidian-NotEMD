# ประมวลผลเป็นชุด

<TLDR>งานโฟลเดอร์ใช้การเลือกและการรายงานความคืบหน้าร่วมกัน แต่ไม่ได้มีกฎเขียนทับเหมือนกัน ค่าเริ่มต้นทำพร้อมกันหนึ่งงาน เริ่มในโฟลเดอร์ทดสอบ ตรวจขอบเขตและปลายทาง แล้วจึงขยาย</TLDR>

## ภาพรวม

เลือกงานโฟลเดอร์จากแถบด้านข้างหรือตัวสำรวจไฟล์ ได้แก่ ลิงก์ แนวคิด ชื่อเรื่อง การแปล ข้อความต้นฉบับ การซ่อม Mermaid และสูตร ไม่มีงานค้นคว้าทั่วไปสำหรับโฟลเดอร์โดยตรง แต่การสร้างจากชื่อเรื่องเพิ่มการค้นคว้าได้ งานชุดไม่ใช่ธุรกรรมทั้งโฟลเดอร์ ผลที่เสร็จแล้วยังอยู่เมื่อมีข้อผิดพลาดหรือยกเลิก

## วิธีทำงาน

### รูปแบบการรัน

1. เลือกงานและโฟลเดอร์ที่มีเฉพาะไฟล์ที่ต้องการ
2. นามสกุล การเลือก และตัวกรองผลลัพธ์เฉพาะงานกำหนดไฟล์ที่จะทำ
3. งานใช้ผู้ให้บริการ/โมเดลของตน พร้อมรายงานสถานะ ข้อผิดพลาด และพาธ
4. ตรวจรายงานและผลลัพธ์หลังเสร็จหรือยกเลิกก่อนทำซ้ำ

ลิงก์ แนวคิด ชื่อเรื่อง ข้อความต้นฉบับ Mermaid และสูตรรวมโฟลเดอร์ย่อยเป็นค่าเริ่มต้น **การแปลโฟลเดอร์ใช้เฉพาะไฟล์ลูกโดยตรงเป็นค่าเริ่มต้น** โหมดนักพัฒนาและโปรไฟล์เลือกไฟล์ขั้นสูงอาจเปลี่ยนขอบเขตและตัวกรอง ตรวจรายการที่ถูกเลือกจริง

### การเขียนทับ

| งาน | สิ่งที่ต้องตรวจก่อนรันซ้ำ |
| ------ | ------------------------------------ |
| ลิงก์ | ผลแยกเป็นค่าเริ่มต้น ตรวจ suffix โฟลเดอร์ และการย้ายต้นฉบับที่ตั้งเอง |
| แนวคิด | ลิงก์ย้อนกลับที่เปิดอาจเพิ่มในโน้ตเดิม ส่วนรายการซ้ำเป็นอีกงาน |
| สร้างจากชื่อเรื่อง | เขียนในต้นฉบับที่เข้าเงื่อนไข แล้วจึงย้ายถ้า complete ปลายทางว่าง |
| แปล | คำแปลเดิมอาจถูกแทนที่ ค่าเริ่มต้น `_<language>.md` |
| Mermaid / สูตร | แก้โน้ตที่เลือก ต้องตรวจและสำรองข้อมูล |

ไม่มีตัวเลือกร่วมแบบข้าม/เพิ่มต่อ/แทนที่สำหรับทุกงาน ในงานชื่อเรื่อง ถ้าปลายทาง complete มีไฟล์อยู่ จะขัดขวางการย้าย ไม่ได้ขัดขวางการสร้างเนื้อหาที่เกิดก่อนหน้า จำนวนที่สร้างและที่ย้ายรายงานแยกกัน

### การทำงานพร้อมกัน

คง `batchConcurrency: 1` จนกว่าตัวอย่างจะผ่าน บางเส้นทางต้องเปิด `enableBatchParallelism` ด้วย ส่วนการแปลโฟลเดอร์ใช้ค่าพร้อมกันโดยตรง การเพิ่มงานขนานเพิ่มภาระผู้ให้บริการ หน่วยความจำ และเซิร์ฟเวอร์ในเครื่อง ไม่รับประกันว่าเร็วขึ้น ช่วงห่างคำขอหรือกลุ่มงานไม่ได้ป้องกันทุกโควตาหรือการใช้บัญชีเดียวกันจากที่อื่น

## การตั้งค่า

| การตั้งค่า | ค่าเริ่มต้น | ผล |
| --------- | --------- | -------- |
| `batchConcurrency` | `1` | จำนวนงานพร้อมกันที่ขอบนเส้นทางที่รองรับ |
| `enableBatchParallelism` | `false` | เปิดการจัดตารางขนานที่รองรับ |
| `batchSize` | `50` | ขนาดกลุ่มสำหรับการจัดตารางแบบกลุ่ม |
| `batchInterDelayMs` | `1000` | ช่วงพักระหว่างกลุ่มที่จัดตารางไว้ |
| `apiCallIntervalMs` | `500` | ช่วงห่างคำขอ API ที่ทำพร้อมกัน |
| `folderTaskIncludeSubfoldersMode` | `legacy` | รักษาพฤติกรรมโฟลเดอร์ย่อยเฉพาะแต่ละงาน |
| `enableStableApiCall` | `false` | โหมดคำขอเสถียรที่เลือกอย่างชัดเจน |

### โมเดลของงาน

งานโฟลเดอร์ใช้การเลือกโมเดลเดียวกับงานไฟล์คู่กัน ตรวจเส้นทางก่อนใช้ข้อมูลส่วนตัว บริบทในเครื่องสำหรับการสร้างจากชื่อเรื่องแบบชุดใช้ snapshot เดียวจากตอนเริ่ม การแก้ระหว่างรันจะไม่ถูกปนในผลค้นหาภายหลัง หากต้องการรวมการแก้ไขนั้นให้เริ่มชุดใหม่

## ตัวอย่าง

สร้าง `trial-titles` ที่มีโน้ตชื่อเรื่องสองไฟล์ เรียก **สร้างแบบกลุ่มจากชื่อเรื่อง** แล้วตรวจเนื้อหา โฟลเดอร์ `trial-titles_complete` ข้างกัน และจำนวนที่สร้าง/ย้าย/ผิดพลาด ตรวจไฟล์ที่ล้มเหลวก่อน การรันโฟลเดอร์ต้นฉบับใหม่ไม่ได้ทำต่อเฉพาะงานที่เหลือให้โดยอัตโนมัติ

## การยกเลิกและกู้คืน

ยกเลิกเพื่อหยุดการจัดงานใหม่และคำขอที่รองรับ ระบบภายนอกอาจทำคำขอหรือการเขียนที่ยอมรับแล้วจนจบ ผู้ให้บริการเป็นผู้กำหนดค่าบริการ รอแล้วเปรียบเทียบไฟล์ที่เสร็จกับพาธกู้คืน/ข้อขัดแย้ง ลบไฟล์กู้คืนหลังตรวจแล้วเท่านั้น

## ข้อแนะนำ

- ตรวจการเลือกไฟล์จริงของโปรไฟล์
- ลดงานพร้อมกันและตรวจโควตาเมื่อเกิด 429
- แยกสถานะยกเลิก ผิดพลาด และสำเร็จ
- เก็บตัวอย่างที่ไม่แก้ไขและข้อมูลสำรองก่อนเปลี่ยนไฟล์
