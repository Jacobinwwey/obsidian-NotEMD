# รู้จัก Notemd

<TLDR>Notemd เป็นปลั๊กอิน Obsidian ภายใต้ MIT สำหรับสร้าง Markdown ที่มี wiki-links โน้ตแนวคิด สรุปการค้นคว้า คำแปล และแผนภาพที่ตรวจและเก็บไว้ได้ เลือกผู้ให้บริการ งาน และขอบเขต แล้วตรวจคำตอบโมเดลก่อนนำเข้าคลังความรู้</TLDR>

## Notemd คืออะไร

ปลั๊กอินเชื่อมงานใน vault กับ 36 โปรไฟล์คลาวด์ gateway และเซิร์ฟเวอร์ในเครื่อง แต่ละงานเขียนผลตามสัญญาของตน เรียกแยกหรือรวมเป็นเวิร์กโฟลว์ในแถบด้านข้างได้ ผลลัพธ์อยู่ใน vault แต่งานคลาวด์ส่งเนื้อหาและการค้นคว้าเว็บใช้เครือข่าย การเก็บไฟล์ในเครื่องกับการรันโมเดลในเครื่องเป็นคนละการตัดสินใจ

## ความสามารถหลัก

### Wiki-links และแนวคิด

ขอให้โมเดลค้นแนวคิดและเพิ่มลิงก์ งานลิงก์เริ่มต้นสร้างไฟล์ประมวลผลแยก ไฟล์แนวคิดต้องเลือกโฟลเดอร์ การแยกอิสระเริ่มจากชื่อเรื่องและไม่มีลิงก์ย้อนกลับ ดู [ลิงก์](./features/wiki-links) และ [แนวคิด](./features/concept-notes)

### ค้นคว้าและบริบทในเครื่อง

Tavily/DuckDuckGo ให้บริบทสำหรับสรุปที่เพิ่มลงโน้ตปัจจุบัน การค้นข้อมูลในเครื่องแบบจำกัดขอบเขตที่เปิดเพิ่มอาจให้ข้อความประกอบการสร้างเนื้อหา ดัชนีเป็นการค้นตามคำ ไม่ใช่ semantic search ด้วย embeddings ดู [ค้นคว้า](./features/research)

### แปลและข้อความต้นฉบับ

แปลไฟล์/โฟลเดอร์ หรือแยกข้อความต้นฉบับเพื่อตอบคำถาม ตรวจข้อความอ้างอิงกับแหล่งเดิม การเลือกข้อความไม่ลดขอบเขตการแปลทั้งไฟล์ ดู [การแปล](./features/translation)

### แผนภาพและการส่งออก

เลือกแผนภาพหลายประเภทในการทำงานครั้งเดียว และเลือกหลายรูปแบบผลลัพธ์แยกกันสำหรับแต่ละประเภท ยกเลิกการเลือกแล้วค่ารูปแบบยังคงอยู่ หากไม่เลือกเลย ระบบจะวิเคราะห์เนื้อหาอัตโนมัติ [คู่มือแผนภาพ: Draw.io, Drawnix, Mermaid, CircuitikZ](./features/diagrams).

### เวิร์กโฟลว์

**One-Click Extract** เพิ่มลิงก์ สร้างเนื้อหาจากชื่อเรื่องให้โน้ตที่เข้าเงื่อนไขในโฟลเดอร์แนวคิด/โฟลเดอร์ที่เลือก แล้วซ่อม Mermaid ใน complete แนวคิดเดิมอาจถูกนำมาทำด้วย แต่ละขั้นยังมีเงื่อนไขและผลลัพธ์ของตน ดู [DSL ที่ตรงจริง](./features/workflows)

## เริ่มต้น

1. [ติดตั้ง](./getting-started/installation) ใน vault ที่ตั้งใจ
2. ใช้โมเดลที่เข้าถึงได้ทดสอบโน้ตทดลอง
3. ตรวจโฟลเดอร์แนวคิดและพาธผลลัพธ์
4. ตรวจผลก่อนรันชุดใหญ่

ไม่มีเวลาตายตัวหรือความยาวโน้ตขั้นต่ำที่ใช้ได้กับทุกกรณี เลือกงานเล็กที่ตรวจสอบได้

## ขอบเขตแผนภาพ

ข้อกำหนดแบบมีชนิดและการเรนเดอร์ตามเป้าหมายกำหนดสิ่งที่รองรับ `DiagramSpec` ไม่รับรองทุกไวยากรณ์หรือการจัดวางเหมือนภาพอ้างอิง `circuitikz` รองรับโครงสร้างที่จำกัด TikZJax เป็นส่วนภายนอก ภาพตัวอย่างไม่พิสูจน์การคอมไพล์จริง ลูกศรข้ามกิ่งแบบคงที่ของ Drawnix ไม่รับรองว่าจะยังเชื่อมติดหลังจัดตำแหน่งใหม่

## โครงสร้าง

งานส่งไปยังผู้ให้บริการที่เลือก คำตอบถูกแยกวิเคราะห์/ตรวจ แล้วเขียนเป็นโน้ตหรือไฟล์ การค้นหาเพิ่มบริบทตามต้องการ ส่วนตัวอย่าง/ส่งออกมีขอบเขตตามรูปแบบ [คู่มือนักพัฒนา](./developers/overview) ระบุเจ้าของโค้ดและการทดสอบ ส่วน [คู่มือ Agent](./agents/overview) ระบุคำสั่งส่งออกสาธารณะที่จำกัด ทะเบียนภายในไม่ใช่ API อัตโนมัติสาธารณะทั่วไป

## เปรียบเทียบเครื่องมือ {#notemd-vs-other-obsidian-ai-plugins}

เลือกตามงานจริง ได้แก่ แปลงไฟล์ สนทนา เชื่อมชื่อแบบกำหนดแน่นอน ค้นข้อมูล หรือแก้ไขในแอปปลายทาง ใช้คู่มือปัจจุบันและตัวอย่างเดียวกัน พร้อมบันทึกเวอร์ชันและการตั้งค่า

## ข้อมูลและความเข้ากันได้

งานคลาวด์รับข้อมูลเข้า คำค้น และข้อความในเครื่องที่เปิดให้ใช้ ตรวจเส้นทางสำหรับงานส่วนตัว การยกเลิกหยุดงานต่อไปที่รองรับและรักษาผลที่เสร็จ แต่ไม่รับประกันการหยุดสร้างข้อความหรือคิดค่าบริการที่ปลายทาง

Manifest กำหนด Obsidian อย่างน้อย `0.15.0` และอนุญาตโหลดบนมือถือ เวอร์ชันดังกล่าวและอุปกรณ์มือถือจริงยังไม่มีการยืนยันปัจจุบัน การส่งออกบางชนิดอาจต้องใช้เครื่องมือเดสก์ท็อป เว็บไซต์มี 34 เส้นทางภาษา และ UI มี 21 ภาษา ความสามารถภาษาของโมเดลเป็นอีกเรื่องหนึ่ง
