# แผนภาพ

<TLDR>
เลือกแผนภาพหลายประเภทในการทำงานครั้งเดียว และเลือกหลายรูปแบบผลลัพธ์แยกกันสำหรับแต่ละประเภท ยกเลิกการเลือกแล้วค่ารูปแบบยังคงอยู่ หากไม่เลือกเลย ระบบจะวิเคราะห์เนื้อหาอัตโนมัติ
</TLDR>

เมื่อส่งออกทั้งหมดสำเร็จ บันทึกจะยุบไว้โดยค่าเริ่มต้น ปุ่มล็อกข้างปุ่มลบจะหยุดการเลื่อนและซูมเพื่อให้เลือกข้อความ SVG/HTML ได้ PNG/PDF เปิดในตัวดูของ Obsidian การส่งออกงานนำเสนอเลือกได้หลายรูปแบบและต้องใช้ Slidev fork ของ Jacobinwwey โดยไม่สลับไปใช้แพ็กเกจทางการ


แต่ละแผนภาพมีการซูม เลื่อน ปรับพอดี และขนาดจริงแยกกัน ใช้ Ctrl/Command + ล้อเมาส์เพื่อซูม และล้อเมาส์ปกติเพื่อเลื่อน การส่งออก PNG ขนาดใหญ่คงค่า 72–600 PPI ที่เลือกไว้ (ค่าเริ่มต้น 300) SVG เป็นรูปแบบเวกเตอร์ โดย PPI ใช้กับการส่งออกภาพแรสเตอร์เท่านั้น


**สร้างภาพที่เข้ากันได้กับ Obsidian** — เปิดโดยค่าเริ่มต้น ตรวจสอบการถอดรหัส PNG ใน Obsidian หากล้มเหลวจะเก็บต้นฉบับและเพิ่มสำเนาที่มี PPI ต่ำกว่า ชื่อไฟล์ทั้งสองระบุ PPI เมื่อปิดจะส่งออกเฉพาะต้นฉบับตามที่ขอ (`note_drawnix_300ppi.png`, `note_drawnix_obsidian_87ppi.png`).

## ตัวเลือกสามอย่าง

| ตัวเลือก | กำหนดสิ่งใด | ตัวอย่าง |
| --- | --- | --- |
| ประเภทแผนภาพ | ความหมายของแผนภาพ | ผังงาน ลำดับ วงจร กราฟ |
| รูปแบบต้นทาง | ไฟล์ที่แก้ไขหรือนำกลับใช้ได้ | Mermaid, JSON Canvas, Draw.io, Drawnix, CircuitikZ |
| รูปแบบส่งออก | ภาพหรือเอกสารสำหรับแบ่งปัน | SVG, PNG, PDF |

HTML แผนภาพมีภาพที่ซูมได้ ส่วน HTML สรุปแบบมีโครงสร้างมีข้อความ โครงสร้าง และแหล่งอ้างอิง HTML/SVG ที่แก้ไขได้เป็นชื่อตัวเรนเดอร์ ไม่ใช่เครื่องมือแก้ไขในเบราว์เซอร์ ให้ใช้ไฟล์ต้นฉบับสำหรับแก้ไข การส่งออกงานนำเสนอรวมถึง PPTX และ MP4 มีการตั้งค่าและส่วนพึ่งพาแยกกัน

## เลือกต้นทาง

| รูปแบบ | เหมาะกับ | ไฟล์ต้นทาง |
| --- | --- | --- |
| Mermaid | แผนภาพใน Markdown | บล็อกโค้ด Mermaid |
| JSON Canvas | Canvas ของ Obsidian โดยตรง | `.canvas` |
| Draw.io | แก้ไขใน diagrams.net หรือเครื่องมือที่เข้ากัน | `.drawio` |
| Drawnix | แก้ไขแบบวาดมือหรือไวท์บอร์ด | `.drawnix` |
| CircuitikZ | วงจรไฟฟ้าและทรานซิสเตอร์ที่มีโครงสร้าง | `.tex` |

รูปแบบที่รองรับแสดงก่อน ตัวเลือกที่ไม่เข้ากันยังมองเห็นแต่ถูกปิดใช้งาน สามารถนำคำขอเดิมที่ไม่ทำงานออกได้ แต่ละประเภทเก็บรูปแบบของตนเอง หากใช้คำขอใดไม่ได้เลย ระบบจะลองรูปแบบต้นฉบับเริ่มต้นของตัวเรนเดอร์ที่ใช้งานและรายงานคำขอที่ไม่พร้อมใช้

## สร้างและส่งออก

1. เปิดโน้ตต้นทางที่รองรับ หากใช้บางส่วนให้แยกเป็นโน้ต เพราะการเลือกข้อความไม่จำกัดงานทั้งไฟล์
2. เลือกแผนภาพหลายประเภทในการทำงานครั้งเดียว และเลือกหลายรูปแบบผลลัพธ์แยกกันสำหรับแต่ละประเภท ยกเลิกการเลือกแล้วค่ารูปแบบยังคงอยู่ หากไม่เลือกเลย ระบบจะวิเคราะห์เนื้อหาอัตโนมัติ
3. ช่องทำเครื่องหมายใช้รวมประเภทในการสร้าง คลิกชื่อเพื่อเลือกประเภทและแก้ไขรูปแบบ วางเมาส์หรือโฟกัสด้วยแป้นพิมพ์เพื่อเปลี่ยนตัวอย่างโดยไม่บันทึกการตั้งค่า Escape ปิดเมนูและคืนโฟกัส
4. เรียก **สร้างไดอะแกรม**
5. ไฟล์ที่เลือกจะส่งออกอัตโนมัติข้างโน้ตต้นฉบับหรือเข้าสู่โฟลเดอร์ผลลัพธ์ที่ตั้งไว้โดยตรง ชื่อระบุประเภท เช่น `topic_drawnix.pdf` และ `topic_flowchart.svg` หากชื่อซ้ำจะเติม `-2`, `-3` เป็นต้น โดยไม่เขียนทับไฟล์เดิม
6. ตรวจบอร์ดและแผง Mermaid ตามลำดับต้นทางใน preview แนวตั้งที่เลื่อนรวมกัน แต่ละแผงใช้ความสูงจริง
7. เลือก **ส่งออก SVG**, **ส่งออก PNG** หรือ **Export PDF** ต่อแผง หรือส่งออกทั้งหมดจากด้านบน เลือกโฟลเดอร์ต้นฉบับหรือโฟลเดอร์กำหนดเองสัมพันธ์กับ vault ชื่อไฟล์กำหนดแน่นอนตามแผง และข้อผิดพลาดแผงหนึ่งไม่หยุดแผงอื่น เก็บต้นทางที่แก้ไขได้ผ่าน **บันทึกไฟล์ต้นฉบับ**

กำหนดโฟลเดอร์ไฟล์ระหว่างทางร่วมกันด้วยพาธสัมพัทธ์ต่อ Vault หรือเว้นว่างเพื่อใช้ `notemd_assert/` ข้างแต่ละต้นฉบับ ที่นี่เก็บบันทึกการกู้คืน แคชการเรนเดอร์ และไฟล์แนบเสริม เก็บไฟล์ที่ยังถูกอ้างอิงไว้ การเปลี่ยนโฟลเดอร์มีผลเฉพาะงานใหม่

ประเภทต่าง ๆ สร้างตามลำดับ ความล้มเหลวหนึ่งไม่ขัดขวางประเภทอื่น การยกเลิกหยุดประเภทที่รอและเก็บไฟล์ที่เสร็จแล้ว ลองส่งออกซ้ำจากตัวอย่างหรือประวัติโดยไม่ต้องขอโมเดลใหม่ หากขั้นสร้างล้มเหลวต้องสร้างประเภทนั้นใหม่ บันทึก v1/v2 ยังอ่านได้

เมนูส่งออกและหัวแผงมีสามการทำงานเดียวกัน **History** เปิดการค้นหา ตัวกรอง เปิดใหม่ และไฟล์ที่บันทึกโดยไม่ซ่อน preview เข้าประวัติจาก palette/แถบด้านข้างได้แม้ไม่มีโน้ตปัจจุบัน

SVG/PDF มาจากเรขาคณิตเวกเตอร์ PDF เก็บ layout SVG และการวัดข้อความ แทนการแปลงทั้งภาพเป็นบิตแมป PPI ใช้เฉพาะ PNG ช่วง 72–600 ค่าเริ่มต้น 300

## ทำแผนภาพหนาแน่นให้อ่านได้

กริด lane แบบ HTML/SVG ที่แก้ได้วัดและตัดบรรทัดสรุปก่อนชื่อเรื่องกับหัวแถว วาดเซลล์ก่อนเส้นเชื่อมและป้าย เส้นทางมุมฉากหลบเซลล์ที่ใช้อยู่และเผื่อพื้นที่ข้อความ

`quadrantChart` มีการปรับรูปแบบเฉพาะโดยไม่ใช้การซ่อมเครื่องหมายอัญประกาศ/รูปร่างแบบ flowchart วงเล็บเปิดที่คัดลอกมาจะถูกลบเฉพาะเมื่อไม่มีคู่และอยู่ท้ายป้ายจุด วงเล็บที่ตั้งใจในชื่อเรื่อง แกน และชื่อควอดแรนต์คงอยู่

[ชุดตัวอย่าง](https://github.com/Jacobinwwey/obsidian-NotEMD/tree/main/docs/diagram-examples) เก็บข้อมูลเข้าสองภาษา SVG/PNG และ manifest ค่า `passed` อ้างถึงการรันและ bundle ที่บันทึก ไม่ใช่การทดสอบใหม่ทุกชนิดในทุกเวอร์ชัน มี 33 แถวที่เรียกใช้ได้ 21 ภาษา UI และ 34 ภาษาของเว็บไซต์ ไวยากรณ์อ้างอิงที่ต้องตรงเป๊ะห้าแบบยังไม่อยู่ในตัวเลือกจนกว่าจะพิสูจน์ layout แยกได้

## Drawnix พร้อม Mermaid ภายใน

Notemd ทำความสะอาด SVG และเก็บต้นฉบับ Mermaid ใน metadata ของ `.drawnix` Preview ไม่ต้องใช้ runtime Drawnix/Plait ค่าเริ่มต้นอยู่ได้ในไฟล์เดียวโดยไม่มี `.assets` ตัวเลือก **Also export complete Mermaid visuals** สร้างต้นฉบับ SVG และ manifest ประกอบ ยังรองรับ `.assets` เดิม และอาจสร้าง SVG ที่หายขึ้นใหม่จากต้นฉบับที่เก็บไว้

รูปภาพใช้ preview ที่ฝังข้อมูลเมื่อทำได้ ลำดับคือข้อมูลฝัง ไฟล์ประกอบเก่า แล้วจึงข้อความต้นทางที่มี เก็บไฟล์ที่ยังถูกอ้างอิงไว้ การส่งออกใหม่ที่อยู่ได้เองไม่พิสูจน์ว่าโฟลเดอร์ร่วมเก่าไม่จำเป็น

Drawnix เก็บความสัมพันธ์แบบมีทิศทางที่ระบุชัดเจนทั้งหมด โดยไม่จำกัดจำนวนรวมหรือจำนวนต่อโหนด ลบเฉพาะข้อความสัมพันธ์ที่ซ้ำกัน และเก็บภาคแสดงที่ต่างกันกับทิศทางย้อนกลับ เส้นทางภายนอกที่มีช่วงทับซ้อนกันใช้ช่องแยก ส่วนเส้นทางที่ไม่ทับซ้อนใช้ช่องร่วมกัน ป้ายกำกับจัดแถวตามขนาดจริงและขยายพื้นที่วาดเมื่อจำเป็น ลูกศรที่ไม่มีป้าย ระบุเพียงความเกี่ยวข้องทั่วไป หรือซ้ำกับลำดับชั้นยังเก็บในเมทาดาทาพร้อมเหตุผล ข้อความในกรอบความสัมพันธ์แสดงใน PDF รวมถึงจากแคช SVG เก่า ลูกศรข้ามกิ่งยังเป็นแบบคงที่และอาจหลุดจากโหนดเมื่อจัดใหม่ใน Drawnix

## ขอบเขตการส่งออกเข้าแอปจริง

ต้นทางกับผลภาพเป็นคนละผลลัพธ์ ทดสอบไฟล์ตัวแทนในโปรแกรมปลายทาง PowerPoint รักษาตารางที่รองรับและแก้ได้ รวมเส้นคั่นที่แก้ใต้เซลล์รวม ส่วน Mermaid/SVG อาจฝังเป็นภาพ Preview หรือคะแนนภาพทั้งสไลด์ไม่แทนการตรวจในแอปจริง

## วงจร

เลือก **Circuit diagram** และ **CircuitikZ source file** Notemd สร้างคำอธิบายมีโครงสร้างก่อนแล้วจึงสร้างต้นทาง เพื่อจำกัด LaTeX ที่ไม่แน่นอน ขอบเขตตั้งใจจำกัด โดยเฉพาะ NMOS แบบ common-source และบล็อก CMOS ที่รองรับ ตรวจต้นทางและ preview ก่อนใช้ทางวิศวกรรมหรือเผยแพร่

Preview SVG เป็นเครื่องมือช่วยตรวจ ไม่ใช่หลักฐานว่าคอมไพล์ LaTeX/TikZJax ในเครื่องแล้ว Preview, SVG/PNG และ PDF ของ preview ไม่ต้องใช้ LaTeX บนเดสก์ท็อปเปิด **CircuitikZ native compile environment** เพื่อวินิจฉัยหรือสร้าง PDF จากการคอมไพล์จริง ใช้ `tectonic`/`pdflatex` ของระบบ executable ที่กำหนดเอง หรือ Tectonic แบบจัดการที่ล็อกเวอร์ชันหลังเลือก **Install** อย่างชัดเจน แผงแสดงความคืบหน้า/ข้อผิดพลาดและลบ runtime ที่จัดการได้

## ปัญหา

### ประเภทแผนภาพผิด

เลือกชนิดเอง สำหรับวงจรใช้ **Circuit diagram** กับ **สร้างไดอะแกรม** ไม่ใช่คำสั่งเก่า **สรุปเป็นแผนภาพ Mermaid**

### ต้นทางไม่เหมาะ

รูปแบบที่รองรับแสดงก่อน ตัวเลือกที่ไม่เข้ากันยังมองเห็นแต่ถูกปิดใช้งาน สามารถนำคำขอเดิมที่ไม่ทำงานออกได้ แต่ละประเภทเก็บรูปแบบของตนเอง หากใช้คำขอใดไม่ได้เลย ระบบจะลองรูปแบบต้นฉบับเริ่มต้นของตัวเรนเดอร์ที่ใช้งานและรายงานคำขอที่ไม่พร้อมใช้

### ไม่มีเมนูส่งออก

SVG/PNG/PDF ต้องมีตัวอย่างภาพ หากมีเพียงข้อความ ให้บันทึกต้นทางและเปิดด้วยโปรแกรมภายนอกที่เหมาะ

### CircuitikZ คอมไพล์ไม่ได้

ตรวจ **CircuitikZ native compile environment** ซ่อม runtime ที่จัดการ หรือยืนยันว่า compiler ของระบบ/ที่กำหนดเองดึงแพ็กเกจ `circuitikz` ได้ Bundle ปลั๊กอินไม่มี TeX distribution เต็มชุด

## 1.9.10 — ตัวอย่างที่ปลอดภัยและการตั้งค่าเฉพาะ Vault

ตัวอย่าง SVG ที่นำเข้าจะลบเนื้อหาที่ทำงานได้และทรัพยากรภายนอก โดยคงป้ายภาษาจีนและรูปแบบของแผงไว้ ผู้ให้บริการเฉพาะอุปกรณ์แยกตาม Vault แล้ว ให้นำเข้ารายการเก่าอย่างชัดเจนจากการตั้งค่า โดยรายการเดิมและการกำหนดค่าปัจจุบันจะยังอยู่ ตัวอย่างงานนำเสนอใช้เซิร์ฟเวอร์ loopback ที่จัดการผู้ใช้ร่วมกัน หากบันทึกรายการโปรดหรือคัดลอกล้มเหลวจะแจ้งข้อผิดพลาด การลบทำตามการตั้งค่า Vault ความเข้ากันได้ของ PNG ยังเปิดอยู่ โดยเก็บต้นฉบับและเพิ่มสำเนา PPI ต่ำที่ตรวจสอบแล้วเฉพาะเมื่อจำเป็น Drawnix ไม่มีเพดานความสัมพันธ์ตายตัว และงานนำเสนอยังใช้การตั้งค่าแยก ติดตั้งไฟล์รุ่นเดียวกัน โหลดใหม่ และทดสอบหนึ่งบันทึกก่อนทำงานเป็นชุด

## 1.9.11 — แผนภาพชัดเจนขึ้นและส่งออก PDF ได้อย่างน่าเชื่อถือ

Drawnix วางกิ่งที่สัมพันธ์กันมากไว้ใกล้กันและลดเส้นเชื่อมที่ซ้อนทับหรือตัดกัน โดยคงทุกโหนดและความสัมพันธ์ที่ระบุไว้อย่างชัดเจน ลูกศรข้ามกิ่งยังคงใช้พิกัดตายตัวหลังจัดเรียงใหม่

การส่งออก PDF รองรับตัวเลือก SVG ที่ซับซ้อนและรูปแบบที่สืบทอดหลังการทำความสะอาด โดยเติม viewBox ที่ขาดหาย และย่อหน้าที่ใหญ่เกินไปตามสัดส่วนพร้อมรักษากราฟิกเวกเตอร์

ข้อมูลวินิจฉัยจัดกลุ่มตามแท็กและพับไว้โดยค่าเริ่มต้น ขยายกลุ่มเพื่ออ่านข้อความและคำแนะนำทั้งหมด โดยจำนวนแยกตามระดับความรุนแรงยังคงแสดงอยู่

บันทึกสะสมต่อเนื่องระหว่างขั้นตอนงานและการเปิดตัวอย่างซ้ำตลอดเซสชันปลั๊กอิน ใช้ ล้างบันทึก เพื่อเริ่มใหม่ การโหลดปลั๊กอินใหม่จะไม่เก็บประวัติบันทึกเดิม

## 1.9.12 — ตัวอย่างข้อมูลวินิจฉัยที่เรียบง่ายขึ้น

เมื่อไม่มีข้อผิดพลาด แผงวินิจฉัยทั้งหมดจะพับไว้โดยค่าเริ่มต้น เหลือเพียงชื่อและจำนวนแยกตามระดับความรุนแรง หากมีข้อผิดพลาด แผงจะขยายโดยอัตโนมัติ ขยายแผงและกลุ่มแท็กเพื่ออ่านข้อความและคำแนะนำทั้งหมด โดยไม่มีการลบบันทึกวินิจฉัยใด ๆ เฉพาะกลุ่มข้อผิดพลาดจะขยายโดยอัตโนมัติ ส่วนคำเตือนและข้อมูลยังพับไว้ แม้จะใช้แท็กเดียวกันก็ตาม
