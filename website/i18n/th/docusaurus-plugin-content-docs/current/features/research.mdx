# ค้นคว้าและค้นเว็บ

<TLDR>Research & summarize ค้นจากข้อความที่เลือกหรือชื่อโน้ต ให้ LLM สรุปบริบทที่หาได้ แล้วเพิ่มลงใน Markdown ปัจจุบัน เลือก Tavily หรือ DuckDuckGo อย่างชัดเจน และตรวจอ้างอิงแหล่งข้อมูล</TLDR>

## ภาพรวม

ผู้ให้บริการค้นหากับโมเดลสรุปเป็นคนละส่วน Tavily ต้องใช้คีย์ ส่วน DuckDuckGo ไม่ต้องมีคีย์ แต่ยังใช้เครือข่ายและอาจจำกัดการเข้าถึง โมเดลในเครื่องไม่ได้ทำให้การค้นคว้าเว็บเป็นงานออฟไลน์

## วิธีทำงาน

### ค้นหาและสรุป

1. เปิดโน้ตปลายทางในตัวแก้ไข Markdown เลือกหัวข้อหรือใช้ชื่อโน้ต
2. เรียก **ค้นคว้าและสรุป**
3. Tavily ให้ข้อความย่อ ส่วน DuckDuckGo อาจดึงหน้าผลลัพธ์
4. หากอนุญาต อาจเพิ่มบริบทจากข้อมูลในเครื่องตามขอบเขตที่เลือก
5. โมเดลเขียนสรุปใต้ `Research Summary` พร้อมหัวข้อและชนิดแหล่งข้อมูล
6. เปิด URL ที่เกี่ยวข้องและตรวจข้อกล่าวอ้าง บริบทที่ดึงมาไม่ได้พิสูจน์ทุกข้อความอ้างอิงที่โมเดลสร้าง

### Tavily หรือ DuckDuckGo

| ตัวเลือก | เตรียมการ | ข้อจำกัดในการทำงาน |
| -------- | ------- | ---------------------- |
| Tavily | เลือก Tavily และใส่คีย์ | โควตาบัญชีและข้อความย่อที่บริการส่งกลับ |
| DuckDuckGo | เลือก DuckDuckGo อย่างชัดเจน | ไม่ต้องมีคีย์ แต่มีข้อจำกัดการค้นหาและความพร้อมของหน้าเว็บ |

คีย์ Tavily ที่ว่างหรือผิดไม่ทำให้เปลี่ยนบริการอัตโนมัติ ตรวจรายงานเมื่อได้บริบทจากเว็บน้อย ข้อความในเครื่องที่เปิดใช้และมีอยู่ยังอาจช่วยสรุปได้ ป้ายแหล่งข้อมูลจะแยกกรณีนี้จากข้อความที่อ้างอิงเว็บ

### ค้นคว้าระหว่างสร้างจากชื่อเรื่อง

**Enable research in "Generate from title"** เพิ่มการค้นคว้ารวมถึงในงานชุด โดยเริ่มปิดไว้ นี่คือเส้นทางโฟลเดอร์ที่รองรับ ไม่มีคำสั่ง Research Folder แบบทั่วไปแยกออกมา

## การตั้งค่า

| การตั้งค่า | ค่าเริ่มต้น | ผล |
| --------- | --------- | -------- |
| `searchProvider` | `tavily` | เลือกบริการค้นหา |
| `tavilyApiKey` | `''` | คีย์ Tavily |
| `tavilyMaxResults` | `5` | จำนวนผล Tavily ที่ขอ |
| `tavilySearchDepth` | `basic` | ความลึกในการค้นหา Tavily |
| `ddgMaxResults` | `5` | จำนวนผล DuckDuckGo ที่ขอ |
| `ddgFetchTimeout` | `15` | เวลาหมดอายุของการดึงหน้าผลลัพธ์เป็นวินาที |
| `maxResearchContentTokens` | `3000` | งบบริบทเว็บโดยประมาณ |
| `researchProvider` | `DeepSeek` | ผู้ให้บริการสรุปเมื่อเปิดเส้นทางตามงาน |
| `researchModel` | `''` | ค่าว่างใช้โมเดลของผู้ให้บริการ |
| `researchSummarizeLanguage` | `en` | ภาษาผลลัพธ์แยกตามงาน |
| `enableResearchInGenerateContent` | `false` | อนุญาตการค้นคว้าระหว่างสร้างจากชื่อเรื่อง |
| `enableLocalKnowledgeRetrieval` | `false` | เปิดการค้นข้อมูลในเครื่องแยกต่างหาก |
| `enableLocalKnowledgeForResearchSummarize` | `false` | ใช้บริบทในเครื่องสำหรับงานนี้ |

### บริบทและโมเดล

ขีดจำกัดบริบทเป็นค่าประมาณ ไม่ใช่ token จริงของผู้ให้บริการ การตัดข้อความอาจตัดหลักฐานด้วย ควรตั้งคำถามให้แคบและเลือกงบโมเดล/คำตอบให้เหมาะ ดัชนีในเครื่องเป็นการค้นตามคำ ไม่ได้มี embeddings โดยปริยายหรือรับประกันว่าพบทุกข้อมูล

## ตัวอย่าง

สร้างโน้ต `การเข้ารหัสตำแหน่งสัมพัทธ์` แล้วค้นคว้า เปรียบเทียบคำอธิบายกับงานวิจัยต้นฉบับหรือเอกสารทางการ เก็บคำถาม URL จริง และข้อแก้ไขเพื่อให้ตรวจข้อสรุปย้อนหลังได้ ตัวอย่างนี้ไม่ใช่การค้นหาที่ได้ทำให้ vault ของคุณแล้ว

## การยกเลิกและความเป็นส่วนตัว

เนื้อหาที่เพิ่มเสร็จแล้วยังอยู่ คำขอโมเดลหรือหน้าเว็บที่รับไว้แล้วอาจทำจนจบ ผู้ให้บริการค้นหาได้รับคำค้น เว็บไซต์ได้รับคำขอ และ LLM ได้บริบทที่รวบรวมทั้งหมด รวมข้อความในเครื่องที่อนุญาต ตรวจข้อมูลวินิจฉัยก่อนแบ่งปัน

## ข้อแนะนำ

- แยกแหล่งเว็บ โน้ตในเครื่อง และข้ออนุมานของโมเดล
- ตรวจข้อความอ้างอิง วันที่ และข้อกล่าวอ้างสำคัญในแหล่งต้นฉบับ
- ทดสอบบริการค้นหากับ LLM แยกกันด้วยคำถามเล็ก
- อ่านสรุปที่มีอยู่ก่อนเพื่อไม่เพิ่มซ้ำ
