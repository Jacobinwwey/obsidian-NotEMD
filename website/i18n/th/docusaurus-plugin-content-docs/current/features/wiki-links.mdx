# Wiki-links

<TLDR>Process file (add links) ขอให้ LLM ที่เลือกค้นหาแนวคิดและเพิ่มลิงก์ Obsidian โดยปกติจะสร้าง `_processed.md` แยกและเก็บต้นฉบับไว้ การสร้างไฟล์แนวคิดต้องเลือกโฟลเดอร์ก่อน ควรตรวจผลลัพธ์ก่อนขยายขอบเขต</TLDR>

## ภาพรวม

โมเดลอาจเลือกต่างกันในแต่ละครั้งและเชื่อมไปยังแนวคิดที่ยังไม่มีไฟล์ wiki-link เป็นจุดหมายในการนำทาง ไม่ใช่หลักฐานว่าคำสองคำมีความหมายเดียวกันหรือคำอธิบายถูกต้อง

## วิธีทำงาน

### การประมวลผล

โน้ตถูกแบ่งเป็นส่วน ส่งให้ผู้ให้บริการ/โมเดล แล้วนำคำตอบมาประกอบ งานอาจสร้างหรืออัปเดตไฟล์แนวคิดในโฟลเดอร์ที่เลือก ตรวจข้อผิดพลาดบางส่วนและพาธผลลัพธ์จริงในรายงาน

### ตัวอย่าง

ต้นฉบับ:

```text
การเรียนรู้ของเครื่องใช้โครงข่ายประสาทเทียมเพื่อค้นหารูปแบบ
```

ผลลัพธ์ที่อาจได้:

```markdown
[[การเรียนรู้ของเครื่อง]]ใช้[[โครงข่ายประสาทเทียม]]เพื่อค้นหารูปแบบ
```

นี่เป็นเพียงตัวอย่าง การเลือกคำขึ้นอยู่กับต้นฉบับ โมเดล และพรอมป์ต์

## การใช้

### โน้ตปัจจุบัน

เรียก **ประมวลผลไฟล์ (เพิ่มลิงก์)** บนสำเนา แล้วตรวจ `_processed.md` ข้างกัน suffix โฟลเดอร์ผลลัพธ์ และการย้ายต้นฉบับที่ตั้งเองอาจเปลี่ยนตำแหน่ง

### หลายโน้ต

เลือก **ประมวลผลโฟลเดอร์ (เพิ่มลิงก์)** ตรวจโฟลเดอร์และขอบเขต แล้วเริ่มจำนวนน้อย ไม่มีตัวเลือกเขียนทับ/ข้ามร่วมกันสำหรับทุกงานโฟลเดอร์ ดู [ประมวลผลเป็นชุด](../advanced/batch-processing)

### เลือกคำเอง

**Create wiki link and generate note from selection** เป็นการทำงานแยกสำหรับคำที่เลือก ไม่ได้จำกัดงานทั้งไฟล์ให้เหลือเฉพาะส่วนที่เลือก ตรวจโน้ตแนวคิดและเนื้อหาที่อาจสร้างขึ้น

## เลือกวิธีให้เหมาะ

การใช้โมเดลช่วยค้นหาแนวคิดที่เป็นไปได้จากเนื้อหา หากต้องการลิงก์ที่ทำซ้ำได้ตามชื่อที่มีอยู่ การจับคู่ชื่อแบบกำหนดแน่นอนอาจเหมาะกว่า เปรียบเทียบเครื่องมืออื่นด้วยคู่มือปัจจุบันและตัวอย่างเดียวกันที่ระบุวันที่

## ความสามารถ

### ลดคำพ้อง

`replaceSynonymsDuringConceptExtraction` เพิ่มคำสั่งให้ลดแนวคิดที่ซ้ำซ้อน เป็น Boolean ที่เริ่มปิด ไม่ใช่เกณฑ์ความคล้ายเชิงตัวเลข ตรวจตัวย่อและความหมายใกล้กันด้วยตนเอง

### ความสมบูรณ์ของลิงก์

Obsidian จัดการการอัปเดตลิงก์เมื่อเปลี่ยนชื่อตามการตั้งค่าและการกระทำที่ใช้ การลบปลายทางอาจทิ้ง wiki-link ที่หาเป้าหมายไม่พบ ซึ่งต่างจากข้อความกล่าวถึงที่ยังไม่ได้เชื่อมลิงก์ ตรวจไฟล์ชื่อเดียวกันในหลายโฟลเดอร์

### แยกอย่างเดียว

ใช้ **ดึงแนวคิด (ไฟล์ปัจจุบัน)** เพื่อแยกแนวคิดโดยไม่เขียนต้นฉบับใหม่ แม่แบบและลิงก์ย้อนกลับต่างจากงานเพิ่มลิงก์ ดู [โน้ตแนวคิด](./concept-notes)

## ไฟล์แนวคิด

### สร้างอัตโนมัติ

เมื่อเปิดใช้และเลือกโฟลเดอร์แนวคิด อาจสร้างโน้ตที่มีชื่อเรื่องและ `Linked From` ระบบไม่ได้เติมคำอธิบายที่ค้นคว้าแล้ว หัวข้อแนวคิดที่เกี่ยวข้อง หรือแม่แบบ frontmatter ทั่วไปโดยอัตโนมัติ ให้สร้างเนื้อหาจากชื่อเรื่องแยกต่างหาก

### ตั้งค่า

ค้นหาโฟลเดอร์แนวคิด โฟลเดอร์ไฟล์ประมวลผล suffix และการย้ายต้นฉบับ โฟลเดอร์แนวคิดเริ่มว่าง ควรแยกผลทดสอบจากแหล่งต้นฉบับ

## ขั้นสูง

### บริบทและพรอมป์ต์

`chunkWordCount` จำกัดส่วนข้อความโดยประมาณ การกำหนดสาขาและพรอมป์ต์เองช่วยชี้นำการเลือก แต่ตัวเลือกประโยค/ย่อหน้าทั่วไป ความถี่ขั้นต่ำ และตัวแปรแม่แบบแนวคิดไม่ได้เป็นตัวเลือกที่ระบุไว้ของงานนี้

## แนวทางที่ควรใช้

- เทียบข้อความอ้างอิง สูตร และโค้ดกับต้นฉบับ
- ตัดสินว่าคำใดควรมีโน้ตแนวคิด
- ทดสอบการเปลี่ยนพรอมป์ต์ด้วยชุดตัวอย่างคงที่
- สำรองก่อนย้ายต้นฉบับหรือเขียนทับปลายทาง

## ประสิทธิภาพ

เวลาและค่าใช้จ่ายขึ้นกับผู้ให้บริการ โมเดล ข้อมูลเข้า ผลลัพธ์ และการลองใหม่ ไม่มีเวลาตายตัวต่อโน้ตหรือราคาต่อร้อยไฟล์ ควรวัดจากตัวอย่างและปริมาณใช้จริงของคุณ

## ปัญหา

### ไม่มีลิงก์

ตรวจคำขอ คำตอบ ต้นฉบับที่ตั้งใจ และไฟล์ผลลัพธ์ที่รายงาน ไม่มีจำนวนคำขั้นต่ำที่รับประกันลิงก์มีประโยชน์

### ลิงก์มากเกินไป

จำกัดพรอมป์ต์หรือสาขาให้แคบลง คำสั่งลดคำพ้องชี้นำโมเดล แต่ไม่ได้บังคับพจนานุกรม

### ลิงก์หลังเปลี่ยนชื่อ

ตรวจการตั้งค่า Obsidian และชื่อที่กำกวม แก้ปลายทางอย่างตั้งใจ การเรียก LLM อีกครั้งไม่ใช่การซ่อมลิงก์แบบกำหนดผลแน่นอน
