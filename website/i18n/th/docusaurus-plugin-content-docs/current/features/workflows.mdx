# เวิร์กโฟลว์

<TLDR>เวิร์กโฟลว์เรียกการทำงานในแถบด้านข้างตามลำดับ แต่ละการทำงานอาจต้องเลือกโฟลเดอร์หรือมีตัวแก้ไขที่เปิดอยู่ นี่ไม่ใช่ท่อส่งข้อความ แต่ละขั้นเก็บข้อมูลเข้า ผลลัพธ์ และผลข้างเคียงของตนเอง เริ่มด้วยโน้ตทดสอบและโฟลเดอร์แยก</TLDR>

## ภาพรวม

ค่าเริ่มต้น **One-Click Extract** คือ

```text
One-Click Extract::process-current-add-links>batch-generate-from-titles>batch-mermaid-fix
```

1. เพิ่มลิงก์ในโน้ตปัจจุบัน และสร้างแนวคิดหากตั้งโฟลเดอร์ไว้
2. สร้างเนื้อหาจากชื่อเรื่องให้โน้ตที่เข้าเงื่อนไขในโฟลเดอร์แนวคิด/โฟลเดอร์ที่เลือก รวมถึงไฟล์ที่มีอยู่ก่อน
3. ซ่อม Mermaid ในโฟลเดอร์ complete ของการสร้างนั้น

ค่าเริ่มต้นของชุดคำสั่งนี้ไม่ทำการค้นคว้าเว็บ การสร้างจากชื่อเรื่องจะเพิ่มได้เมื่อเปิดการตั้งค่าแยก ดู [ประมวลผลเป็นชุด](../advanced/batch-processing)

## วิธีทำงาน

### การรัน

ขั้นตอนทำตามลำดับ แถบด้านข้างแสดงขั้นปัจจุบันและข้อผิดพลาด การยกเลิกหยุดขั้นถัดไปและส่งต่อไปยังคำขอที่รองรับ ไฟล์ที่เสร็จแล้วคงอยู่ จึงไม่ใช่ธุรกรรมที่ย้อนทั้งชุดได้ โฟลเดอร์แนวคิดเป็นตัวเลือกแรก การสร้างเป็นชุดจำโฟลเดอร์ต้นทางและ complete จากนั้น Mermaid ใช้ complete ส่วนการทำงานอื่นยังมีเงื่อนไขไฟล์ ข้อความที่เลือก และการโต้ตอบของตน

### DSL

ใช้ปุ่มที่มีชื่อหนึ่งปุ่มต่อบรรทัด `::` แยกชื่อจากการทำงาน และ `>` แยก ID บรรทัดว่างและบรรทัดขึ้นต้นด้วย `#` ถูกข้าม ID ที่ไม่รู้จักถูกปฏิเสธ

```text
แยกและวาด::extract-concepts-current>summarize-as-mermaid
```

ใช้ตัวสร้างเวิร์กโฟลว์หรือแก้ DSL โดยตรง ID คงที่ ส่วนป้ายเปลี่ยนตามภาษา UI งานโฟลเดอร์มี ID ของตน ไม่ควรสร้างชื่อด้วยการแทนข้อความโดยเดา

| ID | การทำงาน / เงื่อนไข |
| ------------ | ----------------------- |
| `process-current-add-links` | เพิ่มลิงก์ในโน้ตปัจจุบัน |

| `research-and-summarize` | ค้นคว้าข้อความที่เลือก/ชื่อเรื่องในตัวแก้ไข Markdown ที่เปิดอยู่ |

| `batch-translate-folder` | แปลโฟลเดอร์ที่เลือก |

### ชุดเริ่มต้นหรือชุดของคุณ

One-Click Extract ถูกกำหนดไว้แล้ว ปุ่มอื่นกำหนดเองด้วยชื่อและลำดับ ตรวจ tooltip ในแถบด้านข้าง และแก้ข้อผิดพลาดการแยกคำสั่งก่อนใช้

## การตั้งค่า

| การตั้งค่า | ค่าเริ่มต้น | ผล |
| --------- | --------- | -------- |
| `customWorkflowErrorStrategy` | `stop_on_error` | หยุดเมื่อขั้นใดรายงานข้อผิดพลาดครั้งแรก |
| `useMultiModelSettings` | `false` | ใช้ผู้ให้บริการปัจจุบันจนเปิดเส้นทางตามงาน |
| `enableResearchInGenerateContent` | `false` | ไม่ค้นคว้าระหว่างสร้างจากชื่อเรื่องจนกว่าจะเปิด |

`continue_on_error` อนุญาตให้ทำขั้นถัดไปหลังผิดพลาด ใช้เฉพาะเมื่อขั้นเหล่านั้นทำงานกับข้อมูลที่ยังเหลือได้ การทำต่อไม่ได้เปลี่ยนงานที่สำเร็จบางส่วนให้กลายเป็นสำเร็จทั้งหมด

### โมเดลแต่ละขั้น

ตัวงานเป็นผู้เลือกโมเดล ฟิลด์ที่ว่างใช้โมเดลที่กำหนดของผู้ให้บริการนั้น ตรวจทุกเส้นทางก่อนประมวลผลข้อมูลส่วนตัว

## ตัวอย่าง

ตั้ง `trial-concepts` ที่ว่างและใช้ต้นฉบับทดลอง ตรวจแนวคิดและโฟลเดอร์ complete ที่รายงาน หากไม่ชัดว่าผลจะไปที่ใด ให้เรียกแต่ละขั้นแยกก่อน แล้วค่อยขยายหลังตรวจผล

## ข้อแนะนำ

- ทำชุดงานให้เข้าใจที่มาของไฟล์และสาเหตุข้อผิดพลาดได้
- งานลบยังคงต้องยืนยันแบบโต้ตอบ จึงไม่เหมาะกับชุดที่ไม่มีผู้ดูแล
- ตรวจบันทึกและไฟล์หลังยกเลิกหรือเกิดความขัดแย้งการกู้คืน
- ทดสอบโมเดลและโฟลเดอร์จริง การเชื่อมต่อผ่านไม่ได้พิสูจน์ว่ามีโควตาพอสำหรับงานยาว
