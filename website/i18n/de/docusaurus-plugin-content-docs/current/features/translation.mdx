# Übersetzung

<TLDR>
Notemd übersetzt die aktive Datei oder geeignete Dateien eines Ordners. Standardmäßig entsteht eine separate Datei mit Sprachsuffix. Qualität und Sprachabdeckung hängen vom Modell ab, nicht von den 21 UI-Sprachen oder 34 Website-Routen.
</TLDR>

## Überblick

Wähle Zielsprache und Anbieter vorab und teste eine Kopie mit Fachbegriffen, Links und Code. Diese Funktion nutzt das gewählte LLM, keine spezielle Google-Translate-Integration.

Die Aktionen bearbeiten Dateien oder Ordner. Kopiere für einen einzelnen Absatz den Text in eine temporäre Notiz. Markierter Text beschränkt **Aktuelle Datei übersetzen** nicht.

## Ablauf

### Übersetzungsbefehl

1. Zielsprache wählen; Standard Englisch, unabhängig von der UI.
2. Quelle öffnen und **Aktuelle Datei übersetzen** ausführen.
3. Lange Inhalte werden geteilt, übersetzt und zusammengefügt.
4. Gemeldetes Ziel öffnen und Bedeutung, Begriffe, Zitate, Links und Code prüfen.

`Example.md` wird für Französisch standardmäßig zur benachbarten `Example_fr.md`. Die Quelle bleibt, ein vorhandenes Ziel wird überschrieben. Kein standardmäßiges Anhängen an die Quelle und keine garantierte `Translation`-Überschrift.

### Sprachpaare

Das Modell erkennt die Quellsprache. Ein Menüeintrag beweist keine Übersetzungsgenauigkeit. Prüfe Fachsprache und gemischte Abschnitte; bei langen Notizen kann Kontext zwischen Teilen fehlen.

### Modell je Aufgabe

Aktiviere Aufgabenmodelle für `translateProvider` und `translateModel`; sonst gilt der aktive Anbieter. Lokale Modelle benötigen laufenden Server und Modelldateien. Cloud-Anbieter erhalten Prompt und Inhalt. Vergleiche mit einer fachlichen Quelle statt einer pauschalen Rangliste.

### Ordnerübersetzung

**Ordner stapelweise übersetzen** berücksichtigt standardmäßig direkte Kinder; erweiterte Profile können den Umfang ändern. Gleichnamige Quellen können in einem gemeinsamen Zielordner kollidieren. Prüfe Pfade und vorhandene Übersetzungen vor Wiederholung.

## Einstellungen

| Einstellung | Standard | Wirkung |
| --------- | --------- | -------- |
| `language` | `en` | Gewählte Zielsprache |
| `translateProvider` | `DeepSeek` | Anbieter bei Aufgabenrouting |
| `translateModel` | `''` | Leeres Feld übernimmt Anbietermodell |
| `useCustomTranslationSuffix` | `false` | Standardmäßig Sprachcode als Suffix |
| `translationCustomSuffix` | `_translated` | Suffix bei aktivierter Anpassung |
| `useCustomTranslationSavePath` | `false` | Standardmäßig neben der Quelle speichern |
| `translationSavePath` | `''` | Vault-relativer Zielordner |
| `batchConcurrency` | `1` | Angeforderte Parallelität für Ordnerübersetzung |

Kann ein eigener Ordner nicht angelegt werden, kann die Laufzeit auf den Quellordner zurückfallen und meldet den tatsächlichen Pfad. Ein leeres eigenes Suffix kann die Quelle adressieren; für separate Übersetzungen ein unterschiedliches Suffix wählen.

## Beispiel

Wähle Englisch und übersetze eine kurze chinesische Testnotiz. Vergleiche `_en.md` mit Quelle, Begriffen, Zahlen, Gleichungen und Links, bevor du den ganzen Ordner bearbeitest.

## Abbruch und Prüfung

Abbruch stoppt weitere unterstützte Arbeit, macht fertige Übersetzungen aber nicht rückgängig und garantiert keinen Kostenstopp. Prüfe Bericht und Dateien. Eine Markdown-Erhaltungsanweisung ist keine parserseitige oder semantische Garantie.

## Tipps

- Quellen sichern und Namenskollisionen prüfen.
- Beim Testen eigene Suffixe und Ordner verwenden.
- Codebezeichner, Mathematik, URLs und Eigennamen nachlesen.
- Diagnosen vor Weitergabe bereinigen.
