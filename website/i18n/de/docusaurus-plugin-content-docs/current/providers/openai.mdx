# OpenAI-Anbieter

<TLDR>
Das OpenAI-Profil nutzt die gemeinsame OpenAI-kompatible Chat-Completions-Laufzeit. Setze Schlüssel und ein Modell für dieses Protokoll. Der voreingestellte Modellname ist kein aktuelles Zugriffsversprechen oder allgemeiner Qualitätsrat.
</TLDR>

## Einrichtung

Wähle **OpenAI**, trage den Schlüssel ein und verwende offiziell `https://api.openai.com/v1`. Das Modell muss Chat Completions unterstützen; die Modellliste macht ausschließlich über andere APIs verfügbare Modelle nicht kompatibel.

Für Gateways deren Profil mit korrekten Headern nutzen. Azure über **Azure OpenAI** mit Deployment und API-Version konfigurieren.

## Adresse und Authentifizierung

| Feld | Voreinstellung |
| ------- | -------------- |
| Transport | `openai-compatible` |
| API-Schlüssel | Erforderlich |
| Basis-URL | `https://api.openai.com/v1` |
| Modell | `gpt-4o` |
| Temperatur | `0.5` |
| Verbindungstest | `models-then-chat` |

Die Laufzeit normalisiert bekannte Basis-URL-Formen und bildet Modell-/Chatrouten. Beginne mit der Voreinstellung und prüfe den aufgelösten Pfad, statt Segmente zu erraten.

## Modelle finden

**Fetch models** fragt den konfigurierten Endpunkt ab. **Verbindung testen** kann nur durch die Liste erfolgreich sein. Prüfe danach den exakten Anbieter/Modellweg mit einer Testnotiz.

Reasoning, Thinking, Sampling und Ausgabelimits hängen von Profil- und Modellregeln ab. Ein gelistetes Modell akzeptiert nicht automatisch alle Parameter.

## Fehlerbehebung

- `401`/`403`: Schlüssel, Projekt, Modellrechte, Kontostatus.
- `404`: Endpoint, Modell-ID und passende API.
- Liste erfolgreich, Aufgabe nicht: tatsächlichen Chatfehler und Parameter prüfen.
- Lange Antwort scheitert: Ausgabelimit, Quellgröße und Antwort prüfen; Kurztests decken nicht alle Langläufer ab.

## Geeigneter Einsatz

Für direkte OpenAI-Modelle mit implementiertem Chat-Completions-Protokoll. Repräsentative Aufgabe prüfen; Preise und Verfügbarkeit ändern sich unabhängig von Notemd.
