# Anthropic-Anbieter

<TLDR>
Nutze Anthropic für die native Messages API. Claude über ein OpenAI-kompatibles Gateway gehört in dessen Profil. Prüfe verfügbaren Modellzugriff; der historische Standardname kann ersetzt werden müssen.
</TLDR>

## Einrichtung

Wähle **Anthropic**, gib den API-Schlüssel und einen verfügbaren Claude-Modellnamen ein. Behalte den nativen Endpunkt, außer dein Deployment bietet ausdrücklich dasselbe Protokoll. Verbindung testen, dann die beabsichtigte Aufgabe an einer Testnotiz.

## Adresse und Authentifizierung

| Feld | Voreinstellung |
| ------- | -------------- |
| Transport | `anthropic` |
| API-Schlüssel | Erforderlich |
| Basis-URL | `https://api.anthropic.com` |
| Modell | `claude-3-5-sonnet-20240620` |
| Temperatur | `0.5` |
| Verbindungstest | `chat-only` |

Die Laufzeit verwendet `/v1/messages` mit nativen Schlüssel-/API-Versionsheadern. Keine OpenAI-Chatroute in dieses Profil eintragen. Der Standardmodellname beschreibt den Repository-Wert, nicht aktuelle Upstream-Verfügbarkeit.

## Modelle finden

Native Anthropic-Modellliste nutzen, sofern verfügbar. Bei eingeschränkter Liste einen berechtigten Namen eingeben und den Chat-Verbindungstest nutzen. Lange und strukturierte Aufgaben separat prüfen.

## Fehlerbehebung

- `401`/`403`: Schlüssel, Workspace/Projekt, Abrechnung und Modellrechte.
- `404`: Endpunkt und aktuelle Verfügbarkeit.
- Gateway-ID abgelehnt: Gateway-Profil und erwartete ID verwenden.
- Lange Antwort scheitert: Limits und Fehler vor zusätzlichen Versuchen prüfen.

## Geeigneter Einsatz

Für native Messages-Endpunkte. Vergleiche die Ausgabe auf eigenen Quellen, statt Anbieter als universelle Rangliste zu behandeln. Aufgabenrouting erlaubt gezielten Einsatz.
