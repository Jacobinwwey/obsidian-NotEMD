# Installation

<TLDR>
Installiere **Notemd** über Obsidians Community-Erweiterungen oder kopiere die drei Plugin-Dateien derselben GitHub-Version in deinen Vault. Aktiviere das Plugin, richte einen Anbieter ein und prüfe eine Testnotiz. Lokale Modellserver und native Exporte benötigen eigene Voraussetzungen.
</TLDR>

## Methode 1: Community-Erweiterungen (empfohlen)

1. Öffne im gewünschten Vault **Settings → Community plugins**.
2. Aktiviere Community-Erweiterungen bei Bedarf und wähle **Browse**.
3. Suche **Notemd**, prüfe das Repository `Jacobinwwey/obsidian-NotEMD` und wähle **Install**.
4. Wähle **Enable** und öffne die Notemd-Seitenleiste über das Menüband oder die Befehlspalette.

[Notemd in Obsidian öffnen](obsidian://show-plugin?id=notemd). Erkennt der Browser diesen Link nicht, verwende die Schritte oben.

## Methode 2: Manuelle Installation

### Voraussetzungen

Du brauchst Obsidian und einen Vault, den du sichern kannst. Das Manifest nennt `0.15.0` als Mindestversion; das belegt keinen aktuellen Test auf dieser alten Version.

### Schritte

1. Lade `main.js`, `manifest.json` und `styles.css` aus demselben [GitHub Release](https://github.com/Jacobinwwey/obsidian-NotEMD/releases/latest). Die ebenfalls veröffentlichte `README.md` ist Referenzmaterial, keine Laufzeitvoraussetzung.
2. Kopiere die Dateien nach `<vault>/.obsidian/plugins/notemd/`. Passe `.obsidian` an, falls dein Vault ein anderes Konfigurationsverzeichnis nutzt.
3. Lade Obsidian neu und aktiviere Notemd.
4. Prüfe die angezeigte Version. Kombiniere kein neues Manifest mit einem alten Bundle.

## Alternative: BRAT

Wer [BRAT](https://github.com/TfTHacker/obsidian42-brat) bereits nutzt, kann `Jacobinwwey/obsidian-NotEMD` über dessen Beta-Plugin-Ablauf hinzufügen. Verwende für Fehlerreproduktionen eine konkrete Version. BRAT bleibt optional.

## Prüfung

Wähle einen erreichbaren Anbieter und ein verfügbares Modell, dann **Verbindung testen**. Bearbeite anschließend eine kopierte Notiz aus dem [Schnellstart](./quick-start). Manche Verbindungstests prüfen nur die Modellliste; erst eine Aufgabe prüft Generierung und Speicherung.

## Systemvoraussetzungen

| Bereich | Grenze |
| --------- | ---------- |
| Plugin-Manifest | Mindestversion `0.15.0`; `isDesktopOnly` ist false |
| Prüfnachweise | Datierte Abnahme der Version prüfen; physische Mobilgeräte und Obsidian 0.15.0 derzeit nicht verifiziert |
| Gehostetes LLM | Netzwerk, berechtigtes Konto/Schlüssel und unterstütztes Modell |
| Lokales LLM | Separat installierter laufender Server mit heruntergeladenem oder geladenem Modell |
| Native Folien-/Schaltungsexporte | Desktop-Werkzeuge und formatspezifische Abhängigkeiten vorher prüfen |

Es gibt keine pauschale OS-Versionsgarantie für alle optionalen Exporte. Eine Schaltungsvorschau beweist keine native TeX-Kompilierung; ein Desktop-Test beweist keine Mobilkompatibilität.

## Deinstallation

Deaktiviere oder entferne Notemd über die Community-Erweiterungen. Erzeugte Notizen und Artefakte bleiben Vault-Dateien. Prüfe sie vor dem Löschen und sichere Einstellungen für eine Neuinstallation. Deinstallation macht abgeschlossene Änderungen nicht rückgängig.

## Aktualisierung

Nutze **Check for updates** und aktualisiere Notemd. Manuell: laufende Aufgaben beenden, Vault und Einstellungen sichern, die drei Laufzeitdateien aus derselben Version ersetzen und neu laden. Lies die Versionshinweise und teste klein vor weiteren Stapeln.

Ersetze keine Vault-Einstellungsdatei durch ein Release-Asset. Installiere für einen Rückwechsel bewusst eine bekannte kompatible Version und behalte benötigte Ausgaben.
