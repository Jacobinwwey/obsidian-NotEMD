# Pemrosesan batch

<TLDR>Tindakan folder berbagi kontrol pemilihan dan progres, tetapi penulisan/penimpaannya berbeda. Konkurensi bawaan satu. Mulai dari folder uji, periksa cakupan dan tujuan, lalu perluas.</TLDR>

## Gambaran umum

Gunakan tindakan folder di bilah samping atau menu penjelajah berkas. Tersedia tambah tautan, ekstraksi konsep, generasi judul, terjemahan, ekstraksi kutipan asli, perbaikan Mermaid dan rumus. Tidak ada riset folder generik; generasi judul dapat menyertakan riset opsional.

Batch bukan transaksi seluruh folder. Hasil yang berhasil ditulis tetap ada jika berkas lain gagal atau operasi dibatalkan.

## Cara kerja

### Model eksekusi

1. Pilih tugas/folder dan pastikan hanya berkas yang dimaksud akan diproses.
2. Tugas mengumpulkan berkas yang memenuhi aturan ekstensi/pemilihan dan mengecualikan keluaran khusus tugas.
3. Penyedia/model tugas digunakan dan progres, kegagalan, tujuan dilaporkan.
4. Setelah selesai/batal, tinjau laporan serta berkas sebelum retry.

Tambah tautan, konsep, generasi judul, kutipan asli, Mermaid, dan rumus secara bawaan menyertakan subfolder. **Terjemahan folder hanya anak langsung secara bawaan.** Profil pemilihan lanjutan dapat mengubah cakupan/filter jika mode pengembang dan pemilihan lanjutan aktif. Periksa profil nyata, jangan menganggap semua rekursif sama.

### Penimpaan

| Tugas | Periksa sebelum mengulang |
| ------ | ------------------------------------ |
| Tambah tautan | Hasil terpisah secara bawaan; periksa sufiks, folder, dan pemindahan sumber |
| Ekstraksi konsep | Konsep lama dapat menerima tautan balik jika aktif; duplikat ditinjau terpisah |
| Generasi judul | Isi ditulis ke sumber yang memenuhi syarat; hasil sukses dipindah ke complete jika tujuan bebas |
| Terjemahan | Hasil terjemahan dengan nama sama dapat ditimpa; bawaan `_<language>.md` |
| Mermaid / rumus | Mengubah catatan pilihan; periksa sampel dan pertahankan cadangan |

Tidak ada pengaturan lewati/tambah/ganti universal. Pada generasi judul, tujuan complete yang sudah ada mencegah pemindahan, bukan berarti generasi sebelumnya dilewati. Jumlah dihasilkan dan dipindahkan dibedakan.

### Konkurensi

Pertahankan `batchConcurrency` pada `1` sampai sampel representatif berhasil. Beberapa jalur memerlukan `enableBatchParallelism` untuk penjadwalan paralel; terjemahan folder memakai konkurensinya langsung. Konkurensi menambah tekanan penyedia, memori, dan server lokal, bukan jaminan lebih cepat.

Interval API dan jeda antarkelompok mengurangi lonjakan tetapi tidak menjamin terhindar dari kuota permintaan/token, batas akun, atau aplikasi lain yang memakai endpoint sama.

## Konfigurasi

| Pengaturan | Bawaan | Efek |
| --------- | --------- | -------- |
| `batchConcurrency` | `1` | Konkurensi yang diminta pada jalur relevan |
| `enableBatchParallelism` | `false` | Aktifkan penjadwalan paralel yang didukung |
| `batchSize` | `50` | Ukuran kelompok pada penjadwalan berkelompok |
| `batchInterDelayMs` | `1000` | Jeda antarkelompok jika diterapkan |
| `apiCallIntervalMs` | `500` | Interval untuk penjadwalan permintaan konkuren |
| `folderTaskIncludeSubfoldersMode` | `legacy` | Pertahankan cakupan subfolder bawaan tiap tugas |
| `enableStableApiCall` | `false` | Mode permintaan stabil eksplisit |

### Model per tugas

Tindakan folder memakai pilihan penyedia/model tugas satu berkas terkait. Periksa sebelum isi privat. Pengambilan lokal opsional untuk generasi batch memakai satu snapshot di awal, sehingga suntingan saat proses tidak diam-diam masuk ke hasil pengambilan berikutnya. Mulai batch baru untuk menyertakannya.

## Contoh

Buat `trial-titles` berisi dua catatan judul saja. Jalankan **Pembuatan massal dari judul**, tinjau isi, `trial-titles_complete`, serta jumlah generasi/pemindahan/kesalahan. Diagnosis berkas gagal dahulu; mengulang folder bukan otomatis melanjutkan tepat bagian tersisa.

## Pembatalan dan pemulihan

Pembatalan menghentikan penjadwalan baru dan diteruskan ke permintaan yang didukung. Panggilan/penulisan yang diterima sistem luar dapat selesai; tagihan dikendalikan penyedia. Tunggu tugas menetap, periksa hasil dan jalur konflik/pemulihan. Pertahankan berkas pemulihan sampai dibandingkan dengan catatan sekarang.

## Saran

- Validasi berkas yang cocok sebelum memakai profil pemilihan.
- Kurangi konkurensi dan periksa kuota saat 429.
- Bedakan batal, gagal, dan selesai.
- Simpan sampel utuh dan cadangan sebelum mengubah catatan lama.
