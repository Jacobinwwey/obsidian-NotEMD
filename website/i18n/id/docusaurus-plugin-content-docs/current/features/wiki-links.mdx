# Wiki-link

<TLDR>Process file (add links) meminta LLM mengenali konsep dan menambahkan wiki-link Obsidian. Bawaannya menulis `_processed.md` terpisah dan mempertahankan sumber. Berkas konsep opsional membutuhkan folder pilihan. Periksa satu hasil sebelum memperluas ke folder.</TLDR>

## Gambaran umum

Gunakan untuk mengusulkan tautan dari makna catatan. Istilah dapat berbeda antarproses dan belum tentu memiliki berkas. Wiki-link adalah tujuan navigasi, bukan bukti konsep setara atau penjelasan hasil generasi benar.

## Cara kerja

### Pemrosesan

Catatan dipotong, tiap bagian dikirim ke penyedia/model, respons digabung, lalu hasil ditulis. Konsep dapat dibuat atau diperbarui dalam folder terkonfigurasi. Periksa kegagalan parsial dan jalur sebenarnya dalam laporan.

### Contoh

Sumber:

```text
Model pembelajaran mesin menggunakan jaringan saraf untuk mempelajari pola dari contoh.
```

Salah satu kemungkinan hasil:

```markdown
Model [[pembelajaran mesin]] menggunakan [[jaringan saraf]] untuk mempelajari pola dari contoh.
```

Ini ilustrasi. Istilah persis bergantung pada sumber, model, dan prompt.

## Penggunaan

### Catatan aktif

Buka salinan Markdown dan jalankan **Proses file (tambah tautan)** dari bilah samping/palet. Dengan bawaan, periksa `_processed.md` di sampingnya. Sufiks, folder hasil, dan pengaturan pindah sumber dapat mengubah perilaku tujuan.

### Beberapa catatan

Pilih **Proses folder (tambah tautan)**, konfirmasi folder/lingkup, dan mulai dari sampel kecil. Tidak ada sakelar timpa/lewati universal untuk semua tugas folder. Baca [batch](../advanced/batch-processing) sebelum mengulang.

### Teks tertentu

Gunakan **Create wiki link and generate note from selection** untuk memilih istilah sendiri. Ini tindakan terpisah; pilihan teks tidak membatasi tambah tautan seluruh berkas. Tinjau catatan konsep dan isi yang dihasilkan.

## Memilih pendekatan

Bantuan model cocok untuk menemukan kandidat konsep dari isi. Pencocokan judul deterministik lebih tepat jika reproduktibilitas terhadap nama catatan yang ada diutamakan. Periksa dokumentasi terkini proyek lain; panduan ini tidak mengklaim perbandingan fitur/kecepatan tanpa pengukuran bertanggal.

## Fitur

### Penekanan sinonim

`replaceSynonymsDuringConceptExtraction` menambah instruksi untuk menghindari konsep sinonim atau sangat tumpang tindih. Ini Boolean nonaktif secara bawaan, bukan ambang kemiripan numerik. Tinjau singkatan dan istilah berdekatan sendiri.

### Integritas tautan

Obsidian mengelola pembaruan tautan saat penggantian nama sesuai pengaturan dan operasi yang dipakai. Menghapus tujuan dapat menyisakan wiki-link tak terselesaikan, berbeda dari sebutan tanpa tautan. Periksa basename ambigu di folder berbeda.

### Ekstraksi tanpa penulisan ulang

**Ekstrak konsep (file saat ini)** membuat konsep tanpa menulis ulang sumber. Kontrol templat minimal dan tautan balik berbeda dari tambah tautan. Lihat [konsep](./concept-notes).

## Generasi catatan konsep

### Pembuatan otomatis

Jika keluaran konsep aktif dan jalurnya dipilih, tambah tautan dapat membuat judul serta tautan `Linked From`. Tidak otomatis ada deskripsi riset, bagian konsep terkait, atau frontmatter yang dapat ditemplatkan bebas. Jalankan generasi judul terpisah untuk isi lebih lengkap.

### Konfigurasi

Cari folder konsep, folder hasil, sufiks tambah tautan, dan opsi pindah sumber. Folder konsep awalnya kosong. Pisahkan tujuan dari koleksi sumber saat menguji.

## Opsi lanjutan

### Konteks dan prompt

`chunkWordCount` mengatur ukuran potongan perkiraan. Pembelajaran terfokus dan prompt khusus dapat mempersempit konsep. Tidak tersedia pemilih konteks kalimat/paragraf, ambang kemunculan minimum, atau variabel templat konsep umum yang didokumentasikan untuk tugas ini.

## Praktik penggunaan

- Bandingkan hasil dengan sumber, termasuk kutipan, rumus, dan kode.
- Tinjau apakah istilah tertaut perlu catatan konsep.
- Uji prompt pada sampel tetap sebelum folder.
- Cadangkan sebelum mengaktifkan pemindahan sumber atau menulis ke tujuan lama.

## Kinerja

Latensi/biaya bergantung penyedia, model, ukuran prompt, panjang hasil, dan retry. Tidak ada janji detik per catatan atau biaya per 100 catatan. Ukur sampel dan pemakaian akun sebelum menambah lingkup.

## Pemecahan masalah

### Tidak ada tautan

Periksa hasil permintaan, respons, catatan yang diproses, dan berkas keluaran. Tidak ada jumlah kata minimum yang menjamin tautan berguna.

### Terlalu banyak tautan

Persempit prompt atau aktifkan pembelajaran terfokus lalu periksa hasil. Penekanan sinonim mengarahkan model, bukan memaksakan kosakata.

### Rusak setelah ganti nama

Periksa pengaturan pembaruan tautan Obsidian dan ambiguitas sebelumnya. Pulihkan/perbaiki tujuan secara sengaja; mengulang LLM bukan perbaikan tautan deterministik.
