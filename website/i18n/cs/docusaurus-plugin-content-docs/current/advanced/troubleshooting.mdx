# Řešení potíží

<TLDR>Reprodukujte problém na zkušební poznámce se stejným poskytovatelem, modelem a nastavením úlohy. Čtěte průběh i výstupní cestu. Oddělte autentizaci, generování, parsování a zápis; test spojení neověřuje celý postup.</TLDR>

## Přehled

Zaznamenejte verze Notemd/Obsidian, OS, akci, protokol, model a minimální kroky. Nerestartujte během ukončování zrušené úlohy. Výstupy a soubory obnovy ponechte, dokud neporozumíte jejich původu.

## Diagnostika

### Test spojení

**Test connection** může ověřovat jen seznam modelů nebo krátké generování. Poté spusťte malou skutečnou úlohu vybraným modelem v požadovaném formátu.

### Průběh a vývojářská diagnostika

Průběh ukazuje stav, chyby a cesty; aktivita API odlišuje čekání od dokončení. Debug zapínejte podle potřeby. Dlouhý diagnostický požadavek může spotřebovat kvótu. Zprávy mohou obsahovat poznámky, částečné odpovědi, endpointy a klíče. Před sdílením je místně prověřte a odstraňte citlivá data, včetně metadat profilů s odstraněnými citlivými poli.

## Běžné chyby

### Chybějící nebo neplatný klíč

401: ověřte profil/endpoint a nechtěné mezery. 403: účet, projekt, modelová oprávnění a účtování. Opakování neopraví chybné přihlašovací údaje.

### Síť

Ze zařízení Obsidianu ověřte server, port, protokol a cestu. Ollama/LM Studio musí běžet s dostupným modelem. `localhost` je toto zařízení, nikoli jiný počítač. Vyberte správný profil; fallback se volí automaticky, ne přepínačem transportu.

### Limit 429

Snižte počet souběžných požadavků a ověřte limity volání/tokenů i další uživatele klíče. Opakování řeší jen některé přechodné chyby.

### Model nenalezen

Použijte **Fetch models** nebo známé ID modelu/deploymentu. Ověřte API a region. Příklady mohou zestárnout; Azure potřebuje deployment a Ark může vyžadovat endpoint-ID.

### Chybějící odkazy či pojmy

Ověřte skutečný výstup, použitelný zdroj, formát odpovědi a povolenou zvolenou složku pojmů. Samostatná extrakce začíná názvy bez zpětných odkazů. Pokud chybí značky, porovnejte výchozí prompt.

### Výstup chybí nebo je jinde

Čtěte hlášenou cestu `_processed.md`, `_<language>.md` či complete. Chyba přípravy překladové složky může vést k použití složky zdroje. Před opakováním prověřte konflikty a oprávnění.

### Soubory po zrušení

Dokončené zápisy zůstávají a přijaté požadavky mohou doběhnout. Před smazáním nebo opakováním celé složky prozkoumejte soubory a konflikty obnovy.

### Diagram nebo export do aplikace

Typy se generují postupně. Chyba jednoho neblokuje ostatní; zrušení zastaví čekající typy a zachová hotové soubory. Export opakujte z náhledu či historie bez nového požadavku modelu. Chyba generování vyžaduje nové vygenerování daného typu. Záznamy v1/v2 zůstávají čitelné.

HTML diagramu obsahuje grafiku s přiblížením; HTML strukturovaného souhrnu obsahuje text, strukturu a zdroje. Upravitelný HTML/SVG označuje renderer, nikoli webový editor. K úpravám použijte nativní zdroj. Export prezentací včetně PPTX a MP4 má samostatná nastavení a závislosti. [Příručka diagramů](../features/diagrams).

## Hlášení problému

1. Reprodukujte chybu syntetickou poznámkou a testovací složkou.
2. Uveďte verze, akci, model, potřebná nastavení a očekávaný/skutečný výsledek.
3. Přiložte minimální soubory/záznamy bez klíčů, soukromého obsahu a zbytečných metadat endpointu.
4. Uveďte, zda problém nastává v jediném souboru s výchozím promptem.
5. Otevřete [GitHub Issue](https://github.com/Jacobinwwey/obsidian-NotEMD/issues).

Samotný snímek obrazovky obvykle neprokazuje chybu formátu či zrušení. Je-li to možné, dodejte zdroj a výstup nebo minimální kroky.
