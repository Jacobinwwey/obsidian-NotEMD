# Traduction

<TLDR>
Notemd traduit le fichier actif ou les fichiers admissibles d’un dossier avec votre LLM. Il crée par défaut un fichier séparé à suffixe linguistique. Qualité et langues dépendent du modèle ; les 21 langues d’interface et 34 langues du site ne sont ni limites ni garanties de traduction.
</TLDR>

## Vue d’ensemble

Choisissez langue et fournisseur, puis testez une copie contenant terminologie, liens et code représentatifs. Cette fonction utilise votre LLM, pas une intégration dédiée Google Translate.

Les actions portent sur fichiers et dossiers. Pour un passage seul, copiez-le dans une note temporaire. Une sélection dans l’éditeur ne limite pas **Traduire le fichier actuel** à ce texte.

## Fonctionnement

### Commande de traduction

1. Choisissez la langue de sortie ; anglais par défaut, indépendamment de l’interface.
2. Ouvrez la source et lancez **Traduire le fichier actuel**.
3. Les longues entrées sont découpées, envoyées au modèle de traduction puis réunies.
4. Ouvrez le chemin annoncé et vérifiez sens, termes, citations, liens Markdown et code.

`Example.md` traduit en français devient par défaut `Example_fr.md`, à côté de la source conservée. Une destination identique est écrasée. Aucun ajout automatique à la source ni titre `Translation` n’est garanti.

### Couples de langues

Le modèle déduit la langue source. Une langue présente dans le menu ne prouve pas l’exactitude de ce couple. Testez les textes mixtes et les termes spécialisés ; le découpage limite le contexte entre fragments.

### Modèle par tâche

Activez les réglages par tâche pour `translateProvider` et `translateModel` ; sinon, le fournisseur actif s’applique. Un modèle local nécessite serveur et modèle prêts. Le cloud reçoit prompt et contenu. Comparez les sorties à une source métier, pas à un classement générique.

### Traduction de dossier

**Traduire le dossier par lot** sélectionne par défaut les fichiers directement enfants ; les profils avancés peuvent modifier le périmètre. Deux sources de même basename réunies dans un dossier de sortie peuvent se heurter. Vérifiez destinations et traductions existantes avant relance.

## Configuration

| Paramètre | Défaut | Effet |
| --------- | --------- | -------- |
| `language` | `en` | Langue cible sélectionnée |
| `translateProvider` | `DeepSeek` | Fournisseur avec routage par tâche |
| `translateModel` | `''` | Reprendre le modèle du fournisseur si vide |
| `useCustomTranslationSuffix` | `false` | Utiliser le suffixe de langue par défaut |
| `translationCustomSuffix` | `_translated` | Suffixe lorsque l’option personnalisée est active |
| `useCustomTranslationSavePath` | `false` | Enregistrer près de la source par défaut |
| `translationSavePath` | `''` | Dossier de sortie relatif au coffre |
| `batchConcurrency` | `1` | Concurrence demandée pour le dossier |

Si le dossier personnalisé ne peut être créé, l’exécution peut revenir au dossier source : contrôlez le chemin réellement annoncé. Un suffixe personnalisé vide peut viser le fichier source ; choisissez un suffixe distinct pour conserver une traduction séparée.

## Exemple

Choisissez l’anglais, copiez une courte note chinoise dans un dossier d’essai, puis traduisez le fichier. Comparez `_en.md` à la source : termes, nombres, équations et liens doivent être contrôlés avant le dossier entier.

## Annulation et relecture

L’annulation arrête la suite du travail là où elle est prise en charge. Elle n’annule ni les traductions déjà écrites ni la facturation distante. Examinez rapport et fichiers. Demander de préserver Markdown n’est pas une garantie syntaxique ou sémantique.

## Conseils

- Sauvegardez la source et vérifiez les collisions de noms.
- Utilisez suffixe et dossier distincts pendant les essais.
- Relisez identifiants, mathématiques, URL et noms propres.
- Retirez les informations privées des diagnostics partagés.
