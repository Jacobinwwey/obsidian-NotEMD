# Diagrammes

<TLDR>
Choisissez le type de diagramme, puis son format source réutilisable. Examinez le résultat dans Obsidian, y compris le tableau Drawnix et les panneaux Mermaid intégrés, puis exportez chaque panneau en SVG, PNG ou PDF.
</TLDR>

## Distinguer les trois choix

| Choix | Rôle | Exemples |
| --- | --- | --- |
| Type de diagramme | Sens du diagramme | Organigramme, séquence, circuit, graphique de données |
| Format source | Fichier modifiable ou réutilisable créé | Mermaid, JSON Canvas, Draw.io, Drawnix, CircuitikZ |
| Format d’export | Image ou document de partage | SVG, PNG, PDF |

Draw.io et Drawnix sont des **formats source**, pas des types de diagramme. CircuitikZ vise les circuits. Une même prévisualisation peut produire plusieurs exports ; CircuitikZ ne limite pas la sortie au SVG.

## Choisir le format source

| Format | Usage | Fichier source |
| --- | --- | --- |
| Mermaid | Diagrammes dans Markdown | Bloc de code Mermaid |
| JSON Canvas | Canvas natif Obsidian | `.canvas` |
| Draw.io | Édition dans diagrams.net ou outil compatible | `.drawio` |
| Drawnix | Édition de tableau blanc | `.drawnix` |
| CircuitikZ | Circuits électriques et à transistors structurés | `.tex` |

Laissez **Preferred source format** sur **Auto** sans besoin d’éditeur particulier ; Notemd choisit un format compatible avec le type.

## Générer et exporter

1. Ouvrez une source prise en charge. Pour un passage seul, créez une note séparée : la sélection ne restreint pas l’action sur fichier.
2. Choisissez le type ou **Auto-detect**.
3. Choisissez la source ou **Auto** ; Drawnix convient aux cartes compatibles à nœuds modifiables et visuels Mermaid.
4. Lancez **Generer un diagramme**.
5. Relisez les panneaux dans leur ordre source : un conteneur vertical garde Drawnix et les visuels Mermaid à leur hauteur rendue.
6. Utilisez **Exporter en SVG**, **Exporter en PNG** ou **Export PDF** par panneau, ou l’export supérieur pour tous. En multipanneau, choisissez dossier source ou dossier relatif au coffre ; un fichier déterministe est écrit par panneau et un échec isolé n’arrête pas les autres.
7. **Enregistrer le fichier source** conserve aussi l’artefact modifiable.

Le menu Export et l’en-tête de chaque panneau proposent les exports visuels ; il n’est pas nécessaire de fusionner toute la prévisualisation en image opaque.

**History** ouvre le tiroir du coffre sans masquer le diagramme. Recherchez, filtrez, rouvrez une prévisualisation ou ses fichiers. L’historique est également accessible sans note active depuis la palette et la barre latérale.

SVG et PDF utilisent la géométrie vectorielle ; le PDF conserve disposition et métriques du SVG. Le PPI ne règle que le PNG : 72–600, 300 par défaut.

## Prévisualisations denses lisibles

Les grilles à couloirs HTML/SVG mesurent et replient le résumé avant titre et en-tête, puis peignent cellules avant connexions et étiquettes. Le routage orthogonal réserve zones de libellés et cellules occupées pour limiter collisions et masquages.

`quadrantChart` reçoit une normalisation propre à sa famille : les corrections de formes et guillemets de flowchart sont ignorées. Seul un crochet ouvrant final non apparié copié par le fournisseur est retiré d’un point ; les crochets intentionnels des titres et axes restent.

Les [exemples du dépôt](https://github.com/Jacobinwwey/obsidian-NotEMD/tree/main/docs/diagram-examples) contiennent entrées bilingues, SVG/PNG et manifeste. `passed` décrit l’exécution et le bundle enregistrés, pas une revalidation de chaque type pour toute version ultérieure.

Le catalogue exécutable contient 33 lignes, l’interface 21 langues, le site 34 routes. Cinq grammaires de référence exactes restent hors du sélecteur jusqu’à obtention de preuves indépendantes de leurs contrats de disposition.

## Drawnix avec Mermaid intégré

Notemd assainit le SVG Mermaid et conserve sa source dans les métadonnées `.drawnix`. La prévisualisation peut l’afficher sans exécuter Drawnix/Plait. La voie par défaut est autonome, sans dossier `.assets`. **Also export complete Mermaid visuals** ajoute sources, SVG et manifeste compagnons pour l’édition externe. Les anciens `.assets` restent pris en charge ; un SVG manquant peut être reconstruit depuis la source conservée.

Les images résolues reçoivent lorsque possible une prévisualisation SVG avec données intégrées. Ordre de chargement : données embarquées, anciens compagnons, reconstruction depuis le texte. Conservez les dossiers encore référencés ; un nouvel export autonome ne prouve pas qu’un ancien dossier partagé est inutile.

Le tableau principal précède les panneaux Mermaid, dans un seul conteneur déroulant. Rouvrir une entrée enregistrée reconstruit panneaux, dimensions et actions d’export.

La disposition réserve titres, résumés et étiquettes, et contourne les nœuds. Une carte incompatible avec une disposition lisible prise en charge échoue avec une erreur de format. Les flèches entre branches sont statiques : leur attachement après déplacement dans Drawnix n’est pas établi. Vérifiez dans l’éditeur cible.

## Limites des exports natifs

Source et export visuel sont deux livrables. Testez dans l’application destinataire. Les tableaux PowerPoint conservent la structure modifiable prise en charge et les séparateurs corrigés sous les cellules fusionnées ; Mermaid/SVG peuvent rester des images. Prévisualisation et score global de capture ne remplacent pas un contrôle natif.

## Circuits

Choisissez **Circuit diagram** et **CircuitikZ source file**. Une description structurée précède la source TeX, limitant les demandes LaTeX non contraintes.

La prise en charge CircuitikZ reste volontairement délimitée, notamment aux amplificateurs NMOS à source commune et blocs CMOS compatibles. Relisez source et prévisualisation avant usage technique ou publication.

Le SVG de contrôle est produit par Notemd ; il ne prouve aucune compilation réussie par LaTeX ou TikZJax.

LaTeX n’est pas nécessaire pour prévisualiser ou exporter SVG/PNG/PDF de prévisualisation. Pour compiler sur ordinateur, ouvrez **CircuitikZ native compile environment**. Utilisez `tectonic`, `pdflatex`, un exécutable personnalisé ou le Tectonic géré épinglé après choix explicite **Install**. Le panneau montre progression et erreurs et permet de retirer le runtime géré.

## Dépannage

### Mauvais type

Choisissez explicitement le type. Pour un circuit, utilisez **Generer un diagramme** avec **Circuit diagram**, pas l’ancienne synthèse Mermaid.

### Source inadaptée

Revenez à **Auto** ou choisissez un format prévu pour le type. CircuitikZ vise les circuits ; Draw.io/Drawnix les diagrammes structurés compatibles.

### Menu Export absent

SVG, PNG et PDF exigent une prévisualisation visuelle. Si seul le texte source est disponible, enregistrez-le et ouvrez-le dans l’outil adapté.

### Compilation CircuitikZ externe en échec

Vérifiez l’environnement natif et réparez le runtime géré, ou assurez l’accès au paquet `circuitikz` pour votre compilateur. Le bundle n’intègre pas une distribution TeX complète.
