# Traitement par lots

<TLDR>
Les actions de dossier partagent sélection et suivi, mais leurs écritures diffèrent. La concurrence par défaut vaut un. Commencez par un dossier d’essai dédié, vérifiez périmètre et destinations, puis augmentez le volume.
</TLDR>

## Vue d’ensemble

La barre latérale et le menu de l’explorateur proposent liens, concepts, génération depuis les titres, traduction, extraction originale et réparations Mermaid/formules. Il n’existe pas de recherche générique par dossier ; la génération depuis les titres peut inclure la recherche.

Le lot n’est pas une transaction : les écritures réussies restent si un autre fichier échoue ou si vous annulez.

## Fonctionnement

### Exécution d’un lot

1. Sélectionnez tâche et dossier, sans fichiers involontaires.
2. La tâche collecte les fichiers admissibles selon extensions et règles de sélection, en excluant ses sorties spécifiques.
3. Elle utilise son couple fournisseur/modèle et rapporte progression, erreurs et destinations.
4. Examinez rapport et fichiers à la fin ou après annulation, avant relance.

Les sous-dossiers sont inclus par défaut pour liens, concepts, titres, extraction originale, Mermaid et formules. **La traduction de dossier ne prend que les enfants directs.** Les profils avancés peuvent modifier le périmètre si mode développeur et sélection avancée sont activés. Vérifiez le profil réel.

### Réécriture des sorties

| Tâche | À vérifier avant relance |
| ------ | ------------------------------------ |
| Ajout de liens | Sortie séparée par défaut ; vérifier suffixe, dossier et déplacement de la source |
| Concepts | Les notes existantes peuvent recevoir un backlink activé ; doublons contrôlés séparément |
| Génération depuis les titres | Écrit dans les notes admissibles, puis déplace vers complete si la destination est libre |
| Traduction | Peut écraser une traduction correspondante ; suffixe `_<language>.md` par défaut |
| Réparation Mermaid / formules | Modifie les notes sélectionnées ; tester et sauvegarder |

Aucun réglage universel ignorer/ajouter/remplacer ne couvre ces tâches. Pour les titres, une destination complete occupée empêche le déplacement, pas la génération précédente. Les comptes générés et déplacés sont distincts.

### Concurrence

Conservez `batchConcurrency: 1` jusqu’à réussite d’un échantillon. Certains chemins exigent aussi `enableBatchParallelism` ; la traduction utilise directement sa concurrence. Augmenter charge le fournisseur, la mémoire et le serveur local sans garantir de gain.

Intervalles API et entre groupes réduisent les rafales, sans garantir le respect de tous les quotas ni isoler les autres applications utilisant le même endpoint.

## Configuration

| Paramètre | Défaut | Effet |
| --------- | --------- | -------- |
| `batchConcurrency` | `1` | Concurrence demandée sur les chemins concernés |
| `enableBatchParallelism` | `false` | Planification parallèle là où elle est prise en charge |
| `batchSize` | `50` | Taille des groupes pour les chemins groupés |
| `batchInterDelayMs` | `1000` | Délai entre groupes lorsque applicable |
| `apiCallIntervalMs` | `500` | Intervalle de planification des requêtes concurrentes |
| `folderTaskIncludeSubfoldersMode` | `legacy` | Conserver le périmètre de sous-dossiers propre à chaque tâche |
| `enableStableApiCall` | `false` | Mode de requête stable explicite |

### Modèles et contexte local

Le lot reprend le routage de la tâche unitaire ; vérifiez-le pour les données privées. La recherche locale de génération depuis les titres utilise un instantané construit au début du lot. Les modifications ultérieures n’y sont pas mélangées ; commencez un nouveau lot pour les inclure.

## Exemple

Placez deux notes de titres dans `trial-titles`, sans autres fichiers. Lancez **Génération par lot à partir des titres**, puis vérifiez contenu, dossier `trial-titles_complete` et comptes générés/déplacés/erreurs. Diagnostiquez les fichiers en échec ; relancer le dossier n’est pas une reprise exacte des seules tâches restantes.

## Annulation et récupération

L’annulation arrête la nouvelle planification et se propage aux requêtes prises en charge. Un appel ou une écriture déjà acceptés peuvent finir ; la facturation reste distante. Attendez la stabilisation, examinez résultats et conflits, et conservez les fichiers de récupération jusqu’à comparaison.

## Conseils

- Vérifiez les fichiers réellement sélectionnés par un profil.
- Réduisez concurrence et contrôlez quotas pour les codes 429.
- Distinguez annulation, échec et réussite.
- Conservez un échantillon intact et une sauvegarde avant modification.
