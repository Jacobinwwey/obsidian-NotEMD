# Fournisseur OpenAI

<TLDR>
Le préréglage OpenAI utilise le moteur partagé Chat Completions compatible OpenAI. Configurez clé et modèle acceptant ce protocole. Le modèle prédéfini n’est ni une garantie d’accès actuel ni une recommandation universelle.
</TLDR>

## Configuration

Choisissez **OpenAI**, saisissez la clé et conservez `https://api.openai.com/v1` pour le service officiel. Le modèle doit accepter Chat Completions ; apparaître dans une liste ne rend pas compatible un modèle réservé à une autre API.

Pour une passerelle, préférez son préréglage et ses en-têtes. Pour Azure, utilisez **Azure OpenAI**, avec déploiement et version API.

## Adresse et authentification

| Champ | Valeur prédéfinie |
| ------- | -------------- |
| Transport | `openai-compatible` |
| Clé API | Obligatoire |
| URL de base | `https://api.openai.com/v1` |
| Modèle | `gpt-4o` |
| Température | `0.5` |
| Test de connexion | `models-then-chat` |

Le moteur normalise les formes connues d’URL avant de construire les routes de liste ou de dialogue. Partez du préréglage et inspectez la route résolue au lieu d’ajouter des segments au hasard.

## Découverte

**Fetch models** interroge le serveur choisi. **Tester la connexion** peut réussir sans tester la génération. Faites ensuite passer une note jetable dans le couple exact.

Raisonnement, thinking, échantillonnage et limites de sortie suivent les règles du modèle et du préréglage. Une liste valide ne garantit pas chaque combinaison de paramètres.

## Dépannage

- `401`/`403` : clé, projet, droits du modèle et état du compte.
- `404` : adresse, identifiant et API compatible.
- Liste valide mais tâche en échec : inspecter l’erreur de dialogue et les réglages.
- Sortie longue tronquée : contrôler budget, taille source et réponse ; un test court ne couvre pas tous les échecs longs.

## Cas d’usage

Utilisez ce profil pour OpenAI direct avec Chat Completions. Évaluez vos propres notes. Tarifs et disponibilité peuvent changer sans nouvelle version de Notemd.
