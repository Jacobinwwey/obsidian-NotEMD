# Rozwiązywanie problemów

<TLDR>Odtwórz problem na jednej testowej notatce z tym samym dostawcą, modelem i ustawieniami zadania. Czytaj postęp i ścieżkę wyniku. Rozróżnij uwierzytelnienie, generowanie, parsowanie oraz zapis; test połączenia nie sprawdza całego przepływu.</TLDR>

## Przegląd

Zapisz wersje Notemd/Obsidiana, system, działanie, protokół, model i minimalne kroki. Nie uruchamiaj ponownie, gdy anulowanie jeszcze trwa. Zachowaj wyniki i pliki odzyskiwania, aż wyjaśnisz ich pochodzenie.

## Diagnostyka

### Test połączenia

**Testuj połączenie** może sprawdzać tylko listę modeli lub krótką generację. Następnie wykonaj małe prawdziwe zadanie z wybranym modelem i formatem wyniku.

### Postęp i diagnostyka deweloperska

Postęp pokazuje status, błędy i miejsca zapisu; aktywność API rozróżnia żądania oczekujące i ukończone. Debug włączaj w razie potrzeby. Długa diagnostyka może zużywać kwoty. Raporty mogą zawierać notatki, częściowe odpowiedzi, adresy i klucze. Przejrzyj je i maskuj lokalnie przed udostępnieniem; zamaskowane profile również wymagają kontroli metadanych.

## Typowe błędy

### Brak lub błędny klucz

401: poprawny profil/endpoint i brak przypadkowych spacji. 403: konto, projekt, prawa do modelu i rozliczenia. Ponowienia nie naprawiają nieprawidłowych danych dostępu.

### Sieć

Sprawdź host, port, protokół i ścieżkę z urządzenia z Obsidianem. Ollama/LM Studio muszą działać z dostępnym modelem. `localhost` oznacza to urządzenie, nie inny komputer. Wybierz właściwy profil; fallback jest automatyczny, nie wybierany przyciskiem transportu.

### Limit 429

Zmniejsz współbieżność i sprawdź kwoty żądań/tokenów oraz innych użytkowników tego klucza. Ponowienia usuwają tylko część przejściowych błędów.

### Nie znaleziono modelu

Użyj **Fetch models** lub znanego modelu/deploymentu. Sprawdź wersję API i region. Przykłady mogą być stare; Azure potrzebuje deploymentu, Ark może potrzebować ID endpointu.

### Brak linków lub pojęć

Sprawdź właściwy plik wynikowy, sensowne źródło, format odpowiedzi i ustawiony aktywny folder pojęć. Samodzielna ekstrakcja zaczyna od tytułów bez linków zwrotnych. Porównaj z domyślnym promptem, jeśli usunięto znaczniki.

### Wynik zniknął lub jest gdzie indziej

Czytaj raportowaną ścieżkę `_processed.md`, `_<language>.md` albo complete. Nieudane tworzenie folderu tłumaczeń może skierować zapis do źródłowego. Sprawdź kolizje i uprawnienia przed powtórzeniem.

### Pliki po anulowaniu

Ukończone zapisy pozostają, a przyjęte żądania mogą się zakończyć. Sprawdź pliki i konflikty odzyskiwania przed usunięciem lub ponowną całą partią.

### Diagram lub natywny eksport

Wybierz obsługiwany typ/źródło i sprawdź środowisko slajdów/CircuitikZ. Podgląd nie jest testem natywnym. Jeśli nie ma podglądu wizualnego, zapisz źródło tekstowe do właściwego narzędzia zewnętrznego. [Diagramy](../features/diagrams).

## Zgłoszenie błędu

1. Odtwórz na sztucznej notatce w folderze testowym.
2. Podaj wersje, działanie, model, konieczne ustawienia i wynik oczekiwany/rzeczywisty.
3. Dołącz minimalne pliki/logi bez kluczy, prywatnych treści i zbędnych metadanych endpointów.
4. Napisz, czy problem występuje na jednym pliku z domyślnymi promptami.
5. Otwórz [GitHub Issue](https://github.com/Jacobinwwey/obsidian-NotEMD/issues).

Sam zrzut ekranu rzadko dowodzi błędu formatu lub anulowania. Jeśli to możliwe, podaj źródło/wynik lub minimalną sekwencję kroków.
