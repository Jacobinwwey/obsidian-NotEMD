# Tłumaczenie

<TLDR>Notemd tłumaczy aktywny plik lub odpowiednie pliki folderu wybranym LLM. Domyślnie powstaje osobny plik z sufiksem języka. Jakość zależy od modelu; 21 języków UI i 34 języki witryny nie są granicą ani gwarancją tłumaczeń.</TLDR>

## Przegląd

Wybierz język docelowy i dostawcę. Przetestuj kopię z terminologią, linkami i kodem. Funkcja używa LLM, nie osobnej integracji Google Translate. Polecenia dotyczą plików/folderów. Przenieś pojedynczy fragment do tymczasowej notatki; zaznaczenie nie ogranicza **Przetłumacz bieżący plik**.

## Jak to działa

### Zadanie tłumaczenia

1. Wybierz język docelowy, początkowo angielski, niezależny od UI.
2. Otwórz źródło i uruchom **Przetłumacz bieżący plik**.
3. Długi tekst zostaje podzielony, wysłany i połączony.
4. Otwórz raportowany plik; sprawdź znaczenie, terminy, cytaty, linki Markdown i kod.

Francuskie tłumaczenie `Example.md` domyślnie trafia do `Example_fr.md` obok zachowanego źródła. Istniejący wynik jest nadpisywany. Dopisywanie do oryginału lub stały nagłówek `Translation` nie są domyślnymi gwarancjami.

### Pary językowe

Model rozpoznaje język źródła. Pozycja menu nie dowodzi jakości pary językowej. Testuj tekst wielojęzyczny i terminy specjalistyczne; fragmentacja może utracić kontekst.

### Model dla zadania

Trasa zadania używa `translateProvider`/`translateModel`, inaczej aktywnego dostawcy. Lokalnie potrzebny jest serwer/model, chmura otrzymuje prompt i treść. Oceń własną próbkę domenową.

### Tłumaczenie folderu

**Przetłumacz folder wsadowo** domyślnie obejmuje tylko bezpośrednie dzieci; profile zaawansowane mogą to zmienić. Tak samo nazwane źródła kierowane do jednego folderu mogą kolidować. Sprawdź wcześniejsze tłumaczenia i cele przed ponowieniem.

## Ustawienia

| Ustawienie | Wartość początkowa | Działanie |
| --------- | --------- | -------- |
| `language` | `en` | Wybrany język docelowy |
| `translateProvider` | `DeepSeek` | Dostawca przy trasach zadań |
| `translateModel` | `''` | Puste używa modelu dostawcy |
| `useCustomTranslationSuffix` | `false` | Kod języka jako sufiks domyślny |
| `translationCustomSuffix` | `_translated` | Sufiks przy włączonym własnym wariancie |
| `useCustomTranslationSavePath` | `false` | Domyślny zapis obok źródła |
| `translationSavePath` | `''` | Własny folder względem skarbca |
| `batchConcurrency` | `1` | Żądana współbieżność tłumaczenia folderu |

Jeśli nie można utworzyć własnego folderu, zadanie może wrócić do folderu źródłowego. Czytaj rzeczywistą ścieżkę. Pusty własny sufiks może wskazywać źródło; użyj rozróżniającego sufiksu dla osobnego tłumaczenia.

## Przykład

Skopiuj krótką chińską notatkę do folderu testowego, wybierz angielski i przetłumacz plik. Porównaj `_en.md` ze źródłem: terminy, liczby, wzory i linki. Potem rozszerz zakres.

## Anulowanie i kontrola

Anulowanie zatrzymuje obsługiwaną dalszą pracę. Nie cofa gotowych tłumaczeń ani nie gwarantuje zatrzymania naliczania opłat. Sprawdź raport i pliki. Zachowanie Markdown jest instrukcją modelu, nie gwarancją parsera co do zgodności znaczenia.

## Wskazówki

- Kopia źródła i kontrola konfliktów nazw.
- Oddzielny sufiks testowy i folder wyników.
- Ręczna weryfikacja kodu, matematyki, URL-i i nazw własnych.
- Przegląd diagnostyki przed udostępnieniem.
