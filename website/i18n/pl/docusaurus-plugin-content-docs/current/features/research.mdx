# Badanie źródeł i wyszukiwanie w sieci

<TLDR>Research & summarize wyszukuje na podstawie zaznaczenia lub tytułu, zleca LLM podsumowanie dostępnego kontekstu i dopisuje wynik do aktywnego Markdown. Jawnie wybierz Tavily lub DuckDuckGo i zweryfikuj odwołania do źródeł.</TLDR>

## Przegląd

Wyszukiwarka i model podsumowujący są oddzielne. Tavily wymaga klucza; DuckDuckGo nie, lecz używa sieci i może ograniczać ruch. Model lokalny nie sprawia, że badanie internetu działa offline.

## Jak to działa

### Wyszukanie i podsumowanie

1. Otwórz cel w edytorze Markdown; zaznacz temat lub użyj tytułu.
2. Uruchom **Badanie i podsumowanie**.
3. Tavily dostarcza fragmenty; DuckDuckGo może pobierać strony wynikowe.
4. Może zostać dodany dozwolony kontekst lokalny z wybranego zakresu.
5. Model zapisuje podsumowanie pod `Research Summary`, z tematem i rodzajem źródeł.
6. Otwórz ważne URL-e i sprawdź twierdzenia. Pobrany kontekst nie dowodzi każdego wygenerowanego cytatu.

### Tavily czy DuckDuckGo

| Wybór | Przygotowanie | Granica działania |
| -------- | ------- | ---------------------- |
| Tavily | Wybierz Tavily i podaj klucz | Kwoty konta i zwrócone fragmenty |
| DuckDuckGo | Wybierz DuckDuckGo jawnie | Bez klucza; ograniczenia wyszukiwania i dostępność stron |

Pusty lub błędny klucz Tavily nie przełącza automatycznie usługi. Czytaj raport przy małej ilości źródeł sieciowych. Włączone lokalne fragmenty mogą nadal wspierać podsumowanie; oznaczenie źródła odróżnia je od treści opartej na internecie.

### Badanie przy generowaniu z tytułu

**Enable research in "Generate from title"** dodaje badanie także w wariancie wsadowym i jest domyślnie wyłączone. To obsługiwana ścieżka folderowa; nie istnieje osobne ogólne polecenie Research Folder.

## Ustawienia

| Ustawienie | Wartość początkowa | Działanie |
| --------- | --------- | -------- |
| `searchProvider` | `tavily` | Wybór wyszukiwarki |
| `tavilyApiKey` | `''` | Klucz Tavily |
| `tavilyMaxResults` | `5` | Żądana liczba wyników Tavily |
| `tavilySearchDepth` | `basic` | Głębokość wyszukiwania Tavily |
| `ddgMaxResults` | `5` | Żądana liczba wyników DuckDuckGo |
| `ddgFetchTimeout` | `15` | Timeout stron wynikowych w sekundach |
| `maxResearchContentTokens` | `3000` | Przybliżony budżet kontekstu z sieci |
| `researchProvider` | `DeepSeek` | Dostawca podsumowania przy trasach zadań |
| `researchModel` | `''` | Puste używa modelu dostawcy |
| `researchSummarizeLanguage` | `en` | Język wyjściowy dla zadania |
| `enableResearchInGenerateContent` | `false` | Zezwolenie na badanie przy generowaniu z tytułu |
| `enableLocalKnowledgeRetrieval` | `false` | Osobne włączenie wyszukiwania lokalnego |
| `enableLocalKnowledgeForResearchSummarize` | `false` | Lokalny kontekst dla tego zadania |

### Kontekst i model

Limity kontekstu są szacunkami, nie dokładnymi tokenami dostawcy. Obcięcie może usunąć dowody. Zawęź pytanie i dopasuj model/budżet odpowiedzi. Lokalny indeks jest leksykalny, bez domyślnych embeddingów i gwarancji pełnego odnalezienia treści.

## Przykład

Utwórz `Względne kodowanie pozycji`, uruchom badanie i porównaj opis z oryginalnymi publikacjami lub oficjalną dokumentacją. Zachowaj pytanie, rzeczywiste URL-e i poprawki do odtworzenia wniosków. Przykład nie oznacza wykonanego już wyszukiwania w Twoim skarbcu.

## Anulowanie i prywatność

Gotowe dopiski pozostają. Zaakceptowane żądanie modelu/strony może się zakończyć. Wyszukiwarka otrzymuje pytanie, strony żądania, a LLM cały zebrany kontekst wraz z dozwolonymi fragmentami lokalnymi. Przejrzyj diagnostykę przed udostępnieniem.

## Wskazówki

- Rozróżniaj źródło sieciowe, lokalną notatkę i wniosek modelu.
- Sprawdzaj cytaty, daty i ważne twierdzenia w oryginale.
- Testuj wyszukiwanie i LLM osobno małym pytaniem.
- Czytaj istniejące podsumowania, by nie dopisywać ich ponownie.
