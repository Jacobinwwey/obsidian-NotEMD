# Procesare în lot

<TLDR>Acțiunile pe foldere au selecție și progres comune, dar nu aceeași politică de suprascriere. Concurența inițială este unu. Testați un folder mic, verificați domeniul și destinațiile și abia apoi extindeți.</TLDR>

## Prezentare

Panoul și exploratorul oferă linkuri, concepte, titluri, traducere, pasaje originale, Mermaid și formule pentru foldere. Nu există cercetare generală independentă pe folder; o puteți adăuga generării din titluri. Lotul nu este tranzacție de folder: rezultatele finalizate rămân după eroare sau anulare.

## Cum funcționează

### Model de execuție

1. Alegeți sarcina și folderul cu fișierele dorite.
2. Extensiile, selecția și filtrele specifice de rezultate determină candidații.
3. Sarcina folosește propriul furnizor/model și raportează stare, erori și căi.
4. După finalizare/anulare, examinați raportul și fișierele înainte de reluare.

Linkurile, conceptele, titlurile, pasajele originale, Mermaid și formulele includ implicit subfoldere. **Traducerea de folder include implicit numai copiii direcți.** Modul dezvoltator și profilurile avansate pot schimba domeniul/filtrele. Verificați selecția reală.

### Suprascriere

| Sarcină | Control înainte de repetare |
| ------ | ------------------------------------ |
| Linkuri | Rezultat inițial separat; verificați sufixul, folderul și mutarea sursei |
| Concepte | Backlinkurile active completează note existente; duplicatele se tratează separat |
| Generare din titluri | Scrie sursele eligibile și le mută dacă ținta complete este liberă |
| Traducere | Poate suprascrie traducerea existentă; implicit `_<language>.md` |
| Mermaid / formule | Modifică notele selectate; faceți backup și verificați |

Nu există o alegere universală omitere/adăugare/suprascriere. O țintă complete ocupată împiedică mutarea după generare, nu scrierea anterioară a conținutului. Numerele fișierelor generate și mutate sunt distincte.

### Concurență

Păstrați `batchConcurrency: 1` până când eșantionul reușește. Unele căi cer și `enableBatchParallelism`; traducerea de folder folosește concurența direct. Mai multe cereri simultane încarcă furnizorul, memoria și serverul local fără accelerare garantată. Intervalele dintre cereri/grupuri nu elimină toate limitele sau traficul altor clienți ai contului.

## Setări

| Setare | Valoare implicită | Efect |
| --------- | --------- | -------- |
| `batchConcurrency` | `1` | Concurență cerută în căile eligibile |
| `enableBatchParallelism` | `false` | Activează planificarea paralelă suportată |
| `batchSize` | `50` | Mărimea grupului în execuție grupată |
| `batchInterDelayMs` | `1000` | Pauză între grupurile planificate |
| `apiCallIntervalMs` | `500` | Interval dintre cererile API concurente |
| `folderTaskIncludeSubfoldersMode` | `legacy` | Păstrează regulile de subfoldere ale sarcinii |
| `enableStableApiCall` | `false` | Mod stabil de cereri activat explicit |

### Modelele sarcinilor

Folderele urmează modelul acțiunii pe fișier. Verificați rutele private. Contextul local al unui lot de titluri folosește un singur instantaneu de la pornire; modificările intermediare nu se amestecă în căutări ulterioare. Porniți un lot nou pentru a le include.

## Exemplu

Creați `trial-titles` cu două note care conțin titluri. Rulați **Batch generate from titles** și verificați conținutul, `trial-titles_complete` alăturat și numerele generat/mutat/eșuat. Investigați întâi fișierul eșuat. Repetarea folderului sursă nu este reluarea exactă automată a restanțelor.

## Anulare și recuperare

Anularea oprește planificarea nouă și cererile suportate. Sistemele externe pot termina cereri/scrieri acceptate; facturarea aparține furnizorului. Așteptați, comparați rezultatele cu căile de recuperare/conflict și curățați numai după verificare.

## Recomandări

- Examinați selecția efectivă a profilului.
- La 429, reduceți concurența și verificați cotele.
- Separați stările anulat, eșuat și finalizat.
- Păstrați eșantionul fix și backupul.
