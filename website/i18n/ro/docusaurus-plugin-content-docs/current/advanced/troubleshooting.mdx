# Depanare

<TLDR>Reproduceți pe o notă de test cu același furnizor, model și setări. Citiți progresul și calea rezultatului. Separați autentificarea, generarea, parsarea și scrierea; testul conexiunii nu verifică întregul flux.</TLDR>

## Prezentare

Notați versiunile Notemd/Obsidian, sistemul, acțiunea, protocolul, modelul și pașii minimi. Nu reporniți cât anularea se încheie. Păstrați rezultatele și recuperările până le înțelegeți proveniența.

## Diagnostice

### Testul conexiunii

**Test connection** poate verifica doar lista modelelor sau o generare scurtă. Apoi rulați o sarcină mică reală cu modelul și formatul dorit.

### Progres și diagnostic de dezvoltator

Progresul arată starea, erorile și căile; activitatea API distinge așteptarea de finalizare. Activați debug numai când este nevoie. O cerere diagnostică lungă poate consuma cotă. Rapoartele pot conține note, răspunsuri parțiale, endpoint-uri și chei. Verificați și eliminați local datele sensibile înainte de partajare, inclusiv metadatele profilurilor curățate.

## Erori frecvente

### Cheie invalidă sau absentă

401: profilul, endpoint-ul și spațiile accidentale. 403: contul, proiectul, drepturile modelului și facturarea. Reîncercările nu repară autentificarea greșită.

### Rețea

De pe dispozitivul Obsidian, verificați serverul, portul, protocolul și calea. Ollama/LM Studio trebuie să ruleze cu un model disponibil. `localhost` este acest dispozitiv, nu alt calculator. Alegeți profilul potrivit; fallbackul este automat, nu controlat de un comutator general de transport.

### Limită 429

Reduceți cererile simultane și verificați cotele de apeluri/tokenuri și alte utilizări ale cheii. Reîncercările rezolvă doar unele erori tranzitorii.

### Model negăsit

Folosiți **Fetch models** sau un ID cunoscut de model/deployment. Verificați API-ul și regiunea. Exemplele pot expira; Azure cere deployment, iar Ark poate cere endpoint-ID.

### Lipsesc linkuri sau concepte

Verificați fișierul real, sursa utilă, formatul răspunsului și folderul de concepte activ și ales. Extragerea independentă începe cu titluri fără backlinkuri. Comparați promptul implicit dacă lipsesc marcaje.

### Rezultat absent sau în alt loc

Citiți calea raportată `_processed.md`, `_<language>.md` sau complete. O eroare a folderului de traducere poate folosi folderul sursei. Verificați coliziunile și drepturile înainte de repetare.

### Fișiere după anulare

Scrierile finalizate rămân și cererile acceptate pot termina. Verificați fișierele și conflictele de recuperare înainte de ștergere sau reluarea întregului folder.

### Diagramă sau export în aplicație

Folosiți tip/sursă suportată și verificați mediul prezentărilor/CircuitikZ. Previzualizarea nu este test al aplicației țintă. Fără previzualizare vizuală, păstrați textul sursă pentru instrumentul extern potrivit. [Diagrame](../features/diagrams).

## Raportarea problemei

1. Reproduceți cu o notă sintetică și folder de test.
2. Dați versiunile, acțiunea, modelul, setările necesare și rezultatul așteptat/real.
3. Atașați fișiere/jurnale minime fără chei, conținut privat ori metadate inutile de endpoint.
4. Precizați dacă apare cu un singur fișier și prompturi implicite.
5. Deschideți un [GitHub Issue](https://github.com/Jacobinwwey/obsidian-NotEMD/issues).

O captură singură rareori dovedește o eroare de format sau anulare. Oferiți sursa/rezultatul ori pași minimi când este posibil.
