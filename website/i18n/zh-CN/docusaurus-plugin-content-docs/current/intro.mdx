# Notemd 简介

<TLDR>
Notemd 是采用 MIT 许可证的 Obsidian 插件，可把笔记转换为能够检查和保留的文件：带 wiki 链接的 Markdown、概念笔记、研究摘要、译文和图表。由你选择 provider、任务与输出范围；模型结果进入知识库前仍需审核。
</TLDR>

## Notemd 是什么？

Notemd 将 Vault 工作流接入 36 个 provider 预设，涵盖托管 API、网关和本地服务。每个任务按各自的输出契约写文件或更新笔记，既可单独运行，也可组合为侧边栏工作流。

已保存产物位于 Vault 中。使用云端 provider 时，任务内容会发送到相应端点；网络研究也会联网。本地存储与本地推理是两个不同选择。

## 核心能力

### Wiki 链接与概念笔记

让模型识别概念并添加 wiki 链接。添加链接默认生成独立处理后笔记，已配置的概念文件夹可接收概念文件；独立提取默认仅标题且无反向链接。[链接](./features/wiki-links)与[概念笔记](./features/concept-notes)说明二者的区别。

### 研究与本地上下文

选择 Tavily 或 DuckDuckGo 搜索，再把模型摘要追加到活动笔记。可选的限定范围本地检索可为生成任务补充笔记片段；当前索引基于词法，不是 embedding 语义搜索。[研究](./features/research)说明来源和联网边界。

### 翻译与原文提取

将文件或文件夹翻译为所选输出语言。原文提取可依据问题定位源文段落，仍应与原文对照。文件翻译不会因为选中了文本而变成仅翻译选区。[翻译](./features/translation)说明命名与覆盖行为。

### 图表与导出

一次勾选多种图表，每种类型独立选择多种输出格式。取消勾选仍保留该类型的格式偏好；全部取消则自动分析原文。 [图表使用手册: Draw.io, Drawnix, Mermaid, CircuitikZ](./features/diagrams).

### 工作流

默认 **One-Click Extract** 依次添加链接、为概念或所选文件夹内符合条件的笔记生成正文，再修复 complete 文件夹中的 Mermaid。范围可能包括已有概念笔记；自定义工作流也保留每个动作的前置条件与输出行为。准确 DSL 见[工作流](./features/workflows)。

## 开始使用

1. 在目标 Vault [安装 Notemd](./getting-started/installation)。
2. 配置可访问的 provider/model，试运行可丢弃的笔记。
3. 选择概念文件夹，检查输出位置。
4. 核对结果后再扩大批量范围。

不存在保证完成的时长或保证有效的最小笔记长度；初次样本应足够小，便于审核。

## 图表能力方向

当前图表管线使用类型化规格和目标专用渲染，覆盖受支持的目录项。`DiagramSpec` 等开发者契约描述这一边界，并不保证任意语法或所有参考布局都可用。

电路输出限定于受支持的 `circuitikz` 结构。TikZJax 是外部工具，插件预览不证明原生编译成功。Drawnix 的静态关系不保证重排节点后跨分支箭头仍附着。选择后续编辑格式时应保留这些限制。

## 架构

插件将任务路由到其 provider，校验或解析响应，再写入笔记或产物。搜索与本地检索提供可选上下文，预览与导出还受格式自身限制。

源码归属、扩展契约和验证命令见[开发者指南](./developers/overview)。受限公开导出命令见 [Agent 指南](./agents/overview)；内部 operation 注册表不是通用公开自动化 API。

## 工具比较 {#notemd-vs-other-obsidian-ai-plugins}

按实际任务选择工具：文件转换、对话、确定性链接、检索或原生编辑。阅读各项目当前文档，使用同一代表性样本，记录工具版本和启用功能，再比较结果。

## 数据与兼容性边界

云端 provider 接收任务输入，搜索 provider 接收查询；启用本地上下文时，笔记片段也会进入提示词。判断流程是否本地化前应检查任务专用路由。取消在受支持路径停止后续工作并保留完成输出，不保证远端生成或计费停止。

manifest 声明最低 Obsidian `0.15.0`，允许移动端加载；当前发布证据尚未验证实体移动设备及该最低版本。可选原生导出可能需要桌面工具。网站 34 个语言路由、插件 UI 21 个 locale 与模型翻译能力是三个不同维度。
