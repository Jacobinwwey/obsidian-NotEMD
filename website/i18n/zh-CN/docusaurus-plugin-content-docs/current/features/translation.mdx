# 翻译

<TLDR>
Notemd 使用配置的 LLM 翻译活动文件或目录内符合条件的文件，默认生成带语言后缀的独立文件。语言覆盖与翻译质量取决于模型；21 个 UI locale 和 34 个网站 locale 不是翻译能力的限制或保证。
</TLDR>

## 概览

运行前选择输出语言与翻译 provider，使用含代表性术语、链接和代码的笔记副本测试。此功能使用所选 LLM，没有专门集成 Google Translate。

注册的翻译动作面向文件和文件夹。仅需翻译段落时，先复制到临时笔记；编辑器选区不会缩小 **翻译当前文件** 的范围。

## 工作原理

### 翻译命令

1. 在语言控件选择目标语言，默认英文，与界面语言无关。
2. 打开源笔记，运行 **翻译当前文件**。
3. Notemd 将长内容分块发送到翻译 provider/model，再合并响应。
4. 打开报告中的路径，核对含义、术语、引用、Markdown 链接和代码后再使用。

默认将 `Example.md` 翻译到法文时，在源目录生成 `Example_fr.md`，保留原文。同名既有输出会被覆盖；不存在默认追加到源文模式或保证存在的 `Translation` 标题。

### 语言对

模型推断源语言。菜单出现目标语言不证明某个语言对准确；用样本检查术语和混合语言。长笔记分块可能丢失跨块上下文。

### 任务专用模型

开启任务专用模型后使用 `translateProvider`、`translateModel`，否则使用活动 provider。本地模型需运行中的服务和已下载模型；云端 provider 会收到翻译提示词与内容。

不要只凭通用速度或质量排行选择模型，应使用领域小样本并对照原文验证。

### 批量文件夹翻译

运行 **批量翻译文件夹**，选择目录并检查范围。默认仅包含直接子文件，高级选择 profile 可改变范围。输出使用源 basename 和语言后缀；同名源文件汇入一个自定义目录可能冲突。明确选择目标并在重跑前核对既有译文。

## 配置

| 设置 | 默认值 | 作用 |
| --------- | --------- | -------- |
| `language` | `en` | 目标输出语言 |
| `translateProvider` | `DeepSeek` | 任务专用路由启用时的翻译 provider |
| `translateModel` | `''` | 为空时使用该 provider 的模型 |
| `useCustomTranslationSuffix` | `false` | 默认使用语言代码后缀 |
| `translationCustomSuffix` | `_translated` | 开启自定义后缀时使用的值 |
| `useCustomTranslationSavePath` | `false` | 默认保存在源文件旁 |
| `translationSavePath` | `''` | 自定义 Vault 相对输出目录 |
| `batchConcurrency` | `1` | 文件夹翻译请求的并发数 |

自定义目录创建失败时，运行时可回退到源目录，并报告实际路径。以报告为准，不要假定使用了请求的目录。空自定义后缀可能指向源文件本身；需要独立译文时采用不同后缀。

## 示例

输出语言选择英文，把一篇短中文笔记复制到测试目录，执行文件翻译，与原文并排核对 `_en.md`。确认技术术语、数字、公式和链接正确后，再翻译整个目录。

## 取消与审核

取消在受支持路径停止后续任务，不会撤销已写译文，也不保证 provider 停止计费。取消后检查任务报告和文件。要求模型保留 Markdown 只是提示词要求，不是解析器层面的语义等价保证。

## 建议

- 备份源文，检查输出名称冲突。
- 测试时使用独立后缀和目录。
- 人工核对代码标识符、数学符号、来源 URL 与专名。
- 分享诊断前检查私密内容。
