# 工作流

<TLDR>
工作流按顺序运行现有侧边栏动作，可能要求选择文件夹或打开编辑器。它不是文本管道：各动作保留自身输入、输出和副作用。从可丢弃笔记与专用目录开始。
</TLDR>

## 概览

内置 **One-Click Extract** 定义为：

```text
One-Click Extract::process-current-add-links>batch-generate-from-titles>batch-mermaid-fix
```

1. 为活动笔记添加链接，配置概念目录时创建概念笔记。
2. 为概念目录或批量步骤所选目录内符合条件的笔记生成正文，包括已有笔记。
3. 修复批量生成 complete 目录中的 Mermaid 块。

默认工作流不执行网络研究。标题生成仅在独立研究设置开启时使用研究。范围和输出见[批量处理](../advanced/batch-processing)。

## 工作原理

### 执行管线

步骤依次执行，侧边栏报告当前步骤与失败。取消停止后续步骤并传播到受支持请求路径；已完成写入保留，不存在全有或全无回滚。

文件夹上下文明确定义：优先采用概念目录，批量生成记录来源和 complete 目录，后续 Mermaid 修复使用 complete 目录。其他动作仍有各自的活动文件、选区或交互前置条件。

### DSL 格式

每行定义一个有名称按钮，`::` 分隔名称和动作列表，`>` 分隔动作。忽略空行与 `#` 开头行，拒绝未知动作 ID。

```text
提取并生成图表::extract-concepts-current>summarize-as-mermaid
```

可使用设置中的构建器选取动作，或直接编辑 DSL。动作 ID 稳定，显示标签跟随 UI 语言。文件夹动作使用独立 ID，不遵循通用字符串替换规则。

| 标识符 | 动作／前置条件 |
| ------------ | ----------------------- |
| `process-current-add-links` | 为活动笔记添加链接 |
| `process-folder-add-links` | 为所选目录添加链接 |
| `extract-concepts-current` | 提取活动笔记概念 |
| `extract-concepts-folder` | 提取所选目录概念 |
| `generate-from-title` | 根据活动笔记标题生成正文 |
| `batch-generate-from-titles` | 为符合条件的目录笔记生成正文 |
| `research-and-summarize` | 在打开的 Markdown 编辑器中研究选区或标题 |
| `summarize-as-mermaid` | 将活动受支持输入总结为 Mermaid |
| `generate-diagram` | 从受支持输入生成图表产物 |
| `preview-diagram` | 预览受支持图表源或产物 |
| `translate-current-file` | 翻译活动受支持文件 |
| `batch-translate-folder` | 翻译所选文件夹 |
| `extract-original-text` | 提取指定原文段落 |
| `batch-extract-original-text` | 从符合条件的目录文件提取原文 |
| `split-note-by-chapters` | 按章节拆分活动笔记 |
| `batch-mermaid-fix` | 修复所选目录内 Mermaid 代码块 |
| `fix-formula-current` | 规范活动笔记公式分隔符 |
| `batch-fix-formula` | 规范所选目录公式分隔符 |
| `check-duplicates-current` | 检查活动笔记重复项 |
| `check-remove-duplicate-concepts` | 交互审核并移除重复概念 |
| `test-llm-connection` | 测试已配置 provider |
| `probe-slide-export-env` | 检查本地幻灯片导出环境 |
| `export-slides` | 将活动文件导出为幻灯片 |

### 默认与自定义工作流

One-Click Extract 是内置默认，其他按钮由你定义。搜索工作流设置，命名、选择并排序动作，运行前检查侧栏提示。解析错误需先修正，不能假定链条仍会按预期执行。

## 配置

| 设置 | 默认值 | 作用 |
| --------- | --------- | -------- |
| `customWorkflowErrorStrategy` | `stop_on_error` | 首个步骤报告失败后停止 |
| `useMultiModelSettings` | `false` | 启用任务专用路由前使用活动 provider |
| `enableResearchInGenerateContent` | `false` | 默认不在标题生成中执行网络研究 |

使用 `continue_on_error` 时，即使前一步失败，后续步骤也可能运行。只有后续动作能处理剩余输入时才适用；继续执行不代表部分完成的流程成功。

### 工作流中的任务模型

Provider/model 选择归属各任务。启用任务专用模型时，空模型覆盖使用所选 provider 的模型。链条处理私密材料前，检查每个任务的 provider。

## 示例

配置空的 `trial-concepts` 目录，处理一篇可丢弃源笔记，核对概念文件和报告的 complete 目录。若需了解各步位置，先分别执行每个动作，审核后再扩大范围。

## 建议

- 保持流程足够短，便于定位失败与输出归属。
- 避免在无人值守链条加入清理／删除动作，它们仍保留交互确认要求。
- 取消或出现恢复冲突后，重试前检查日志与文件。
- 用流程实际 provider/model 和目录测试；连接成功不证明长批次符合配额。
