# OpenAI Provider

<TLDR>
OpenAI 预设使用共享 OpenAI-compatible Chat Completions 运行时。配置 API key 和支持该协议的模型。默认模型只是起点，不保证账户当前可访问，也不是所有任务的推荐。
</TLDR>

## 设置

选择 **OpenAI**，填写 API key，官方端点保留 `https://api.openai.com/v1`。选择账户可用且支持 chat completions 的模型；只支持其他 API 的模型不会因出现在列表中而自动兼容。

网关应使用匹配预设以获得正确端点和请求头。Azure 部署选择 **Azure OpenAI**，单独设置 deployment 与 API version。

## 端点与认证

| 字段 | 预设值 |
| ------- | -------------- |
| 传输协议 | `openai-compatible` |
| API key | 必填 |
| 基础 URL | `https://api.openai.com/v1` |
| 默认模型 | `gpt-4o` |
| Temperature | `0.5` |
| 连接测试 | `models-then-chat` |

运行时会规范已知基础 URL 形式后构建列表或聊天路由。调试应从预设 URL 开始，检查最终路由，避免猜测并叠加路径段。

## 模型发现

**获取模型** 查询已配置端点，**测试连接** 可在模型列表请求成功后结束，未必验证聊天。测试连通性后，用实际 provider/model 处理可丢弃笔记。

Reasoning、thinking、采样和输出 token 控制取决于预设和模型规则，应验证任务实际组合；模型上榜不保证接受所有参数。

## 故障排查

- `401`／`403`：检查密钥、项目权限、模型授权和账户状态。
- `404`：检查端点、模型 ID，以及 API 是否支持该模型。
- 列表正常但任务失败：检查实际聊天错误和模型／参数。
- 长输出失败或截断：检查输出上限、源文大小和响应；短连接测试不能复现所有长请求失败。

## 适用场景

适用于直接访问实现的 Chat Completions 协议所支持的 OpenAI 模型。先用代表性笔记评估；价格和模型可用性可独立于 Notemd 发布发生变化。
