# Anthropic Provider

<TLDR>
原生 Messages API 使用 Anthropic 预设。OpenAI-compatible 网关中的 Claude 应选择网关预设。执行任务前确认当前模型权限；历史默认值可能需要修改。
</TLDR>

## 设置

选择 **Anthropic**，填写 Anthropic API key，保留原生端点，除非你的部署明确提供同一协议。输入当前可用 Claude ID，运行 **测试连接**，再用可丢弃笔记验证目标任务。

## 端点与认证

| 字段 | 预设值 |
| ------- | -------------- |
| 传输协议 | `anthropic` |
| API key | 必填 |
| 基础 URL | `https://api.anthropic.com` |
| 默认模型 | `claude-3-5-sonnet-20240620` |
| Temperature | `0.5` |
| 连接测试 | `chat-only` |

运行时向 `/v1/messages` 发送请求，使用原生 API key 与 API version 请求头。不要将 OpenAI 聊天路径放进此预设。默认模型记录仓库设置，不表示上游仍提供该模型。

## 模型发现

可用时使用 Anthropic 原生模型列表路由。列表受限时，手动输入可用模型并运行聊天连接测试。长内容和结构化任务需独立验证。

## 故障排查

- `401`／`403`：检查密钥、workspace／project 权限、计费和模型授权。
- `404`：核对端点与当前模型可用性。
- 网关模型 ID 失败：使用对应网关预设与其要求的 ID。
- 长响应失败：增加重试前先检查输出限制与 provider 错误。

## 适用场景

端点提供 Anthropic Messages 协议时使用原生预设。按自己的材料比较模型结果，不将 provider 选择视为通用质量排名；任务专用路由可仅在适合的任务中使用它。
