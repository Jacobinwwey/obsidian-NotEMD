# Forskning och webbsökning

<TLDR>Research & summarize söker utifrån markering eller anteckningstitel, sammanfattar tillgänglig kontext med LLM och lägger till resultatet i aktiv Markdown. Välj Tavily eller DuckDuckGo uttryckligen och verifiera källhänvisningarna.</TLDR>

## Översikt

Sökleverantör och sammanfattningsmodell är separata. Tavily kräver nyckel; DuckDuckGo saknar nyckelkrav men använder nätverk och kan begränsas. Lokal modell gör inte webbforskning offline.

## Så fungerar det

### Sök och sammanfatta

1. Öppna målanteckningen i Markdown-redigeraren; markera ämne eller använd titeln.
2. Kör **Research & summarize**.
3. Tavily ger utdrag; DuckDuckGo kan hämta resultatsidor.
4. Tillåten lokal kontext från valt omfång kan läggas till.
5. Modellen skriver sammanfattning under `Research Summary` med ämne och källtyp.
6. Öppna relevanta URL:er och verifiera påståenden. Hämtad kontext bevisar inte varje genererat citat.

### Tavily eller DuckDuckGo

| Val | Förberedelse | Driftgräns |
| -------- | ------- | ---------------------- |
| Tavily | Välj Tavily och ange nyckel | Kontokvoter och returnerade utdrag |
| DuckDuckGo | Välj DuckDuckGo uttryckligen | Ingen nyckel; sökbegränsningar och sidtillgänglighet |

Tom eller felaktig Tavily-nyckel växlar inte automatiskt. Granska rapporten vid svag webbkontext. Aktiverade lokala utdrag kan ändå stödja sammanfattningen; källetiketten skiljer detta från webbunderlag.

### Forskning vid titelgenerering

**Enable research in "Generate from title"** lägger till forskning, även för batcher, och är av som standard. Detta är mappvägen; ingen fristående generell Research Folder-åtgärd finns.

## Inställningar

| Inställning | Standard | Effekt |
| --------- | --------- | -------- |
| `searchProvider` | `tavily` | Välj sökbackend |
| `tavilyApiKey` | `''` | Tavily-nyckel |
| `tavilyMaxResults` | `5` | Begärt antal Tavily-resultat |
| `tavilySearchDepth` | `basic` | Tavilys sökdjup |
| `ddgMaxResults` | `5` | Begärt antal DuckDuckGo-resultat |
| `ddgFetchTimeout` | `15` | Timeout i sekunder för resultatsidor |
| `maxResearchContentTokens` | `3000` | Ungefärlig webbkontextbudget |
| `researchProvider` | `DeepSeek` | Sammanfattningsleverantör med uppgiftsstyrning |
| `researchModel` | `''` | Tomt använder leverantörens modell |
| `researchSummarizeLanguage` | `en` | Utdata med uppgiftsspecifika språk |
| `enableResearchInGenerateContent` | `false` | Tillåt forskning vid titelgenerering |
| `enableLocalKnowledgeRetrieval` | `false` | Aktivera lokal sökning separat |
| `enableLocalKnowledgeForResearchSummarize` | `false` | Lokal sökning för denna uppgift |

### Kontext och modell

Kontextgränser är uppskattningar, inga exakta providertoken. Trunkering kan ta bort bevis. Avgränsa frågor och modell-/utdatabudgetar. Lokalt index är lexikalt, utan implicita embeddings eller garanterad full återvinning.

## Exempel

Skapa `Relativ positionskodning`, kör forskning och jämför med originalpublikationer eller officiell dokumentation. Bevara fråga, verkliga URL:er och rättelser för spårbarhet. Exemplet är ingen genomförd sökning i ditt valv.

## Avbrott och integritet

Färdiga tillägg bevaras. Redan accepterade modell-/sidanrop kan slutföras. Sökningen får frågan, webbplatser får anrop och LLM får sammanställd kontext inklusive tillåtna lokala utdrag. Granska diagnostik före delning.

## Tips

- Skilj webbkällor, lokala anteckningar och modellslutsatser.
- Kontrollera citat, datum och viktiga påståenden i originalet.
- Testa sökning och LLM separat.
- Läs befintliga sammanfattningar för att undvika dubbla tillägg.
