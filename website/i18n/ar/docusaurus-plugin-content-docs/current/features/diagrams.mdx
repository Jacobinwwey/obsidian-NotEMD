# الرسوم والتصدير

<TLDR>
اختر نوع الرسم الذي تحتاجه ثم صيغة مصدر قابلة للتحرير. افحص النتيجة في Obsidian بما فيها لوحة Drawnix ومرئيات Mermaid المضمنة، وصدّر كل لوحة إلى SVG أو PNG أو PDF.
</TLDR>

## افصل بين الخيارات الثلاثة

| الخيار | ما يحدده | أمثلة |
|---|---|---|
| نوع الرسم | المعنى الذي يمثله | تدفق، تسلسل، دارة، مخطط بيانات |
| صيغة المصدر | الملف القابل للتحرير أو إعادة الاستخدام | Mermaid، JSON Canvas، Draw.io، Drawnix، CircuitikZ |
| صيغة التصدير | الصورة أو الوثيقة للمشاركة | SVG، PNG، PDF |

Draw.io وDrawnix صيغتا مصدر وليستا نوعي رسم. CircuitikZ صيغة للدارات. يمكن تصدير المعاينة نفسها بعدة صيغ؛ اختيار CircuitikZ لا يحصرك في SVG.

## اختيار صيغة المصدر

| الصيغة | الاستخدام | ملف المصدر |
| --- | --- | --- |
| Mermaid | رسوم داخل Markdown مباشرة | كتلة شيفرة Mermaid |
| JSON Canvas | لوحة Obsidian الأصلية | `.canvas` |
| Draw.io | تحرير لاحق في diagrams.net وأدوات متوافقة | `.drawio` |
| Drawnix | تحرير بأسلوب اللوح أو الرسم اليدوي | `.drawnix` |
| CircuitikZ | دارات كهربائية وترانزستورات منظمة | `.tex` |

اترك **Preferred source format** على **Auto** إذا لم تحتج محررًا معينًا؛ تختار الإضافة صيغة متوافقة مع النوع.

## التوليد والتصدير

1. افتح ملاحظة مصدر مدعومة. لفقرة فقط، ضعها في ملاحظة مستقلة؛ تحديد النص لا يحصر فعل توليد الملف.
2. اختر نوع الرسم في الإعدادات أو **Auto-detect**.
3. اختر المصدر أو **Auto**. استخدم **Drawnix** لخريطة معرفية مدعومة بعقد قابلة للتحرير وMermaid مضمن.
4. نفّذ **إنشاء مخطط** من الشريط أو لوحة الأوامر.
5. راجع المعاينة. تظهر لوحة Drawnix وكل لوحات Mermaid بترتيب المصدر في سطح تمرير رأسي واحد، وبالارتفاع المرسوم دون قص Mermaid.
6. استخدم **تصدير SVG** أو **تصدير PNG** أو **Export PDF** للوحة، أو تصدير الصور العلوي لكل اللوحات. حدد مجلد المصدر أو مسارًا نسبيًا للخزنة؛ تُكتب ملفات محددة الأسماء لكل لوحة وتستمر العملية بعد فشل فردي.
7. اختر **حفظ ملف المصدر** للحصول على المنتج القابل للتحرير.

تقدم قائمة التصدير وأعلى كل لوحة الأفعال الثلاثة نفسها. لا تحتاج لتحويل معاينة كبيرة كاملة إلى صورة واحدة غير قابلة للفصل.

افتح **History** لإظهار درج تاريخ الخزنة دون إخفاء المعاينة. يمكنك البحث والتصفية وإعادة فتح رسم مكتمل أو منتج محفوظ. يتوفر مدخل التاريخ أيضًا من لوحة الأوامر والشريط دون ملاحظة نشطة.

تعتمد SVG وPDF على هندسة متجهية؛ يستخدم PDF تخطيط SVG ومقاييس النص بدل تنقيط المعاينة كاملة. PPI يتحكم في PNG فقط: المجال 72–600 والافتراضي 300.

## قراءة الرسوم الكثيفة

تقيس رسوم مسارات HTML/SVG القابلة للتحرير الملخص وتلفه قبل وضع العنوان ورؤوس المسارات. تُحجز مساحة الملخص وتُرسم الخلايا قبل الموصلات والتسميات. تستخدم الروابط المتقاطعة مسارات شبكية متعامدة تتجنب الاصطدام وتحجز مساحة النص والخلايا، كي لا تخفي الأوصاف الطويلة المحتوى أو تفرض تمريرًا أفقيًا.

تُعالج مخططات أرباع Mermaid حسب عائلتها. يتجاوز `quadrantChart` إصلاحات الاقتباس والأشكال الخاصة بالتدفق؛ ويُزال قوس فتح زائد فقط إذا كان آخر محرف غير متوازن في تسمية نقطة. تبقى الأقواس المقصودة في العناوين والمحاور والأرباع.

يحتوي [دليل الأمثلة](https://github.com/Jacobinwwey/obsidian-NotEMD/tree/main/docs/diagram-examples) أدلة خزنة حقيقية لكل نوع تنفيذي، ومدخلات بالإنجليزية والصينية وSVG وPNG وmanifest قابلًا للقراءة آليًا. تعني `passed` التشغيل وهوية الحزمة المسجلين، لا إعادة اختبار كل الأنواع على إصدار لاحق.

هناك 33 مدخلًا تنفيذيًا و21 لغة UI و34 مسار موقع؛ لا تخلط هذه الأبعاد. تبقى خمس قواعد مرجعية دقيقة خارج المحدد حتى تتوفر أدلة تخطيط مستقلة.

## معاينة Drawnix مع Mermaid

عند تضمين Mermaid، ينقّي Notemd ملف SVG ويحفظ مصدر Mermaid في بيانات `.drawnix`. يمكن العرض دون تشغيل Drawnix أو Plait. المسار الافتراضي ذاتي الاكتفاء ولا ينشئ `.assets` منفصلًا. فعّل **Also export complete Mermaid visuals** للحصول على المصدر وSVG وmanifest المصاحب عند التسليم أو التحرير الخارجي. تبقى `.assets` القديمة مدعومة ويمكن إعادة بناء SVG المفقود من المصدر المحفوظ.

تُعرض الصور المحلولة في معاينة SVG مدعومة بالبيانات حيث أمكن. الأولوية للبيانات المضمنة ثم الملفات القديمة ثم إعادة البناء من المصدر المتاح. احتفظ بالملفات المصاحبة ما دامت المنتجات تشير إليها؛ تصدير جديد مستقل لا يثبت أن مجلدًا قديمًا مشتركًا غير مستخدم.

المعاينة سطح تمرير واحد: Drawnix أولًا، ثم Mermaid بترتيب المصدر. تعيد قراءة إدخال محفوظ من التاريخ بناء قائمة اللوحات وأبعادها وأفعال التصدير.

تُحجز مساحة للعناوين والملخصات وتسميات العلاقات وتُوجّه الموصلات الثابتة حول العقد. إذا تعذر تخطيط مقروء مدعوم يظهر خطأ صيغة. أسهم الفروع علاقات ثابتة؛ الأدلة الحالية لا تدعم التصاقها بعد إعادة ترتيب العقد في Drawnix. افحص المنتج في المحرر المقصود.

## حدود الصيغ الأصلية

المصدر والتصدير البصري منتجان مختلفان. جرّب مثالًا ممثلًا في التطبيق النهائي قبل التوزيع. يحفظ تصدير جداول PowerPoint البنية المدعومة القابلة للتحرير، ومنها الفواصل المصححة تحت الخلايا المدمجة. قد تكون Mermaid وSVG صورًا بديلة لا أشكالًا أصلية. معاينة الإضافة أو درجة صورة كاملة ليست بديلًا لاختبار التطبيق.

## رسوم الدارات

اختر **Circuit diagram** و**CircuitikZ source file** للطلبات المدعومة. يُولد وصف دارة منظم أولًا ثم مصدر CircuitikZ، وهو أكثر قابلية للضبط من طلب LaTeX حر من النموذج.

الدعم مقيد عمدًا. يناسب مكبرات NMOS بمصدر مشترك واللبنات المدعومة من CMOS. راجع المعاينة والمصدر قبل استخدام تقني أو منشور.

SVG رفيق مراجعة أنشأه Notemd، لا دليلًا على نجاح تجميع `.tex` بواسطة LaTeX أو TikZJax محليًا.

التجميع الأصلي اختياري. لا تحتاج LaTeX للمعاينة أو SVG وPNG وPDF المرئي. على سطح المكتب افتح **CircuitikZ native compile environment** للحصول على تشخيص أو PDF أصلي. يمكن استخدام `tectonic` أو `pdflatex` من النظام أو ملف تنفيذي مخصص، أو تثبيت Tectonic المثبّت الإصدار عند اختيار **Install** صراحة. تعرض اللوحة التقدم والأخطاء وتسمح بإزالة البيئة المدارة لاحقًا.

## استكشاف الأخطاء

### النوع غير المطلوب

حدد النوع صراحة. للدارات استخدم **Circuit diagram** ثم **إنشاء مخطط**، لا الأمر القديم **تلخيص كمخطط Mermaid**.

### مصدر غير مناسب

أعده إلى **Auto** أو اختر صيغة تناسب النوع. CircuitikZ للدارات، وDraw.io وDrawnix للرسوم المنظمة المدعومة.

### قائمة التصدير غائبة

تحتاج SVG وPNG وPDF معاينة بصرية. إن توفر المصدر فقط، احفظه وافتحه بأداة متوافقة.

### فشل تجميع CircuitikZ خارجيًا

افتح **CircuitikZ native compile environment** وافحص البيئة. أصلح النسخة المدارة أو تأكد من قدرة مترجمك على جلب حزمة `circuitikz`. لا تضم الإضافة توزيعة TeX كاملة.
