# استكشاف الأخطاء وإصلاحها

<TLDR>
أعد المشكلة على ملاحظة مؤقتة بالمزوّد والنموذج والإعدادات نفسها. اقرأ سجل التقدم ومسار الإخراج. افصل المصادقة والتوليد والتحليل والكتابة؛ اختبار اتصال ناجح لا يغطي سير العمل كله.
</TLDR>

## نظرة عامة

سجل نسخ Notemd وObsidian ونظام التشغيل واسم الفعل وبروتوكول المزوّد والنموذج وخطوات صغيرة للإعادة. لا تبدأ عملية ثانية قبل استقرار الإلغاء. احتفظ بالمخرجات والاسترداد حتى تعرف مالك كل ملف.

## آلية التشخيص

### اختبار الاتصال

استخدم **اختبار الاتصال** في إعداد المزوّد. قد تنجح إعدادات من قائمة النماذج فقط، بينما تنفذ أخرى محادثة صغيرة. شغّل مهمة قصيرة فعلية للتحقق من النموذج وعقد الإخراج.

### التقدم وتشخيص المطوّر

يبين التقدم الحالة والأخطاء والوجهات؛ ويمكن لنشاط API التفريق بين انتظار ومحاولة منتهية. فعّل تشخيص أخطاء API عند الحاجة فقط. اختبار المطوّر الطويل قد يستهلك الحصة، ويُستخدم عمدًا حين ينجح الاختبار القصير وتفشل المهمة الحقيقية.

قد تتضمن أجسام التشخيص النص أو مخرجات جزئية أو URLs أو مفاتيح. راجعها ونقحها محليًا قبل المشاركة. حتى ملف مزوّد منقح يحتاج فحص بياناته الوصفية.

## أخطاء شائعة

### مفتاح API مفقود أو غير صالح

في 401 تأكد من أن المفتاح يخص الخدمة والعنوان بلا مسافات زائدة. في 403 افحص صلاحيات الحساب والمشروع والنموذج والفوترة. المحاولات المتكررة لا تصلح بيانات اعتماد خاطئة.

### أخطاء الشبكة والاتصال

تحقق من المضيف والمنفذ والبروتوكول والمسار من جهاز Obsidian. يحتاج Ollama وLM Studio خادمًا يعمل ونموذجًا متاحًا. `localhost` هو الجهاز نفسه لا حاسوب آخر. اختر الإعداد الصحيح؛ يختار التنفيذ مساراته البديلة تلقائيًا لا عبر مفتاح نقل للمستخدم.

### حد الطلبات 429

قلل التزامن وراجع حصة الطلبات وtoken والعملاء الآخرين الذين يستخدمون المفتاح. قد تصلح إعادة المحاولة خطأ عابرًا لكنها لا تضمن تجاوز كل قيد حصة.

### النموذج غير موجود

استخدم القائمة إن توفرت أو أدخل model أو deployment معروفًا للحساب. افحص إصدار API والمنطقة. قد تكون القيمة الجاهزة تاريخية؛ Azure يحتاج اسم deployment، وArk قد يحتاج endpoint ID.

### لا روابط أو مفاهيم

افحص الملف المعالج الفعلي والمصدر وشكل استجابة النموذج وتفعيل مجلد مفاهيم غير فارغ. الاستخراج المستقل افتراضيًا عناوين بلا روابط مصدر. أعد المطالبة المدمجة للمقارنة إن حذف تخصيصك العلامات.

### الناتج مفقود أو في مكان آخر

اتبع المسار المبلّغ عنه. الربط عادة `_processed.md` والترجمة `_<language>.md` والتوليد الدفعي يذكر complete. قد يعود حفظ الترجمة إلى المصدر عند تعذر إنشاء المجلد المخصص. افحص التصادم والصلاحيات قبل التكرار.

### الإلغاء ترك ملفات

يوقف العمل اللاحق حيث يُدعم، ولا يتراجع عن كتابة مكتملة. قد ينتهي طلب خارجي سبق قبوله. افحص نتائج الملفات وتعارضات الاسترداد قبل الحذف أو إعادة المجلد كله.

### فشل الرسم أو التصدير الأصلي

تُولّد الأنواع بالتتابع. فشل نوع لا يوقف البقية؛ والإلغاء يوقف الأنواع المنتظرة ويحفظ الملفات المكتملة. أعد محاولة التصدير من المعاينة أو التاريخ دون طلب جديد للنموذج. أما فشل التوليد فيتطلب توليد ذلك النوع مجددًا. تبقى سجلات v1/v2 قابلة للقراءة.

يحتوي HTML الرسم على شكل قابل للتكبير؛ ويحتوي HTML الملخص المنظم على النص والبنية والمراجع. HTML/SVG القابل للتحرير اسم لمحرّك عرض وليس محررًا داخل المتصفح؛ استخدم المصدر الأصلي للتحرير. يحتفظ تصدير العروض، بما فيه PPTX وMP4، بإعدادات واعتماديات مستقلة. [دليل الرسوم](../features/diagrams).

## الإبلاغ عن مشكلة

1. أعدها بملاحظة اصطناعية قصيرة ومجلد مخصص.
2. سجل النسخ والفعل والنموذج والإعدادات الضرورية والمتوقع والفعلي.
3. أرفق أصغر منتج يثبت المشكلة مع سجل منقح؛ أزل الأسرار والنص الخاص وتفاصيل العنوان غير اللازمة.
4. اذكر إن كانت تتكرر بملف واحد والمطالبة الافتراضية.
5. افتح [GitHub Issues](https://github.com/Jacobinwwey/obsidian-NotEMD/issues).

الصورة وحدها نادرًا ما تثبت عيب تنسيق ملف أو إلغاء. أرفق زوج المصدر والناتج أو تسلسل إعادة صغيرًا حين يمكن.
