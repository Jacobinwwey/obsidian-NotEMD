# مزوّدو النماذج اللغوية

<TLDR>
يوفر Notemd 36 إعدادًا جاهزًا ضمن OpenAI-compatible وAnthropic وGoogle وAzure OpenAI وOllama. طابق البروتوكول مع العنوان وأدخل بيانات الاعتماد، ثم اختبر نموذجًا متاحًا على ملاحظة صغيرة. القيم الجاهزة قابلة للتعديل وليست ضمانًا لاستمرار تقديم النموذج.
</TLDR>

### مزوّدون إقليميون في الصين

راجع [الدليل الإقليمي](./china) لـ DeepSeek وQwen وDoubao وMoonshot وGLM وغيرها. الفئة لا تضمن التوافر الجغرافي أو جودة الصينية؛ طابق منطقة الحساب والعنوان وصلاحيات النموذج.

## اختيار النموذج لكل مهمة

فعّل `useMultiModelSettings` لتخصيص المزوّد والنموذج. بدونه تستخدم المهام `activeProvider`. التجاوز الفارغ يستخدم نموذج المزوّد المختار؛ وتُسوّى الخيارات المحفوظة غير الصالحة مع المزوّد النشط عند تحميل الإعدادات.

| المهمة | حقل المزوّد | تجاوز النموذج |
| ------ | ------------------ | ---------------- |
| إضافة الروابط | `addLinksProvider` | `addLinksModel` |
| التوليد من العنوان | `generateTitleProvider` | `generateTitleModel` |
| خلاصة البحث | `researchProvider` | `researchModel` |
| الترجمة | `translateProvider` | `translateModel` |
| استخراج المفاهيم | `extractConceptsProvider` | `extractConceptsModel` |
| خلاصة Mermaid | `summarizeToMermaidProvider` | `summarizeToMermaidModel` |
| استخراج النص الأصلي | `extractOriginalTextProvider` | `extractOriginalTextModel` |

المزوّد الافتراضي النشط والمزوّدون المحفوظون للمهام هم DeepSeek. تحقق من كل مهمة قبل إرسال مادة خاصة؛ تغيير المزوّد النشط وحده لا يلغي تخصيصات مفعّلة.

## بنية طلبات API

### النقل

تستخدم الإضافة طلبات Obsidian ومسارات بديلة واعية بالبروتوكول. يمكن لسطح المكتب استخدام تدفقات Node HTTP وللبيئات الأخرى fetch. البروتوكول مختلف عن وسيلة النقل؛ Claude عبر بوابة متوافقة يستخدم إعداد البوابة لا Anthropic الأصلي.

### إعادة المحاولة

وضع الطلب المستقر معطل افتراضيًا، وعند انطباق الإعدادات يكون الافتراضي ثلاث محاولات إضافية بفاصل خمس ثوانٍ. قد تُعالج الأخطاء العابرة بمسار مشترك، لكن بيانات اعتماد أو نموذجًا غير صالح يجب إصلاحهما. قد تفشل الطلبات الطويلة بسبب مهلة بعيدة أو حدود النموذج أو الحصة.

### ذاكرة الاستجابات

يمكن إعادة استخدام استجابات ناجحة من ذاكرة مؤقتة محدودة. تشمل هوية الطلب العنوان والنموذج والمعاملات والمطالبة والمحتوى. ليست تخزينًا دائمًا أو عداد تكلفة أو ضمانًا لمنع طلب مدفوع جديد.

### نماذج الاستدلال

تظهر خيارات reasoning وthinking وفق قواعد الإعداد والنموذج. لا تنقل معاملات خاصة ببروتوكول إلى مزوّد آخر. قبول المحادثة لا يثبت قبول كل خيارات الاستدلال أو token أو أخذ العينات.

### تقدير Token

تقدير طول النص وحد الإخراج لا يساويان عدد token الدقيق لدى الخدمة. راجع الاستخدام الفعلي للفوترة؛ لا يوجد تقدير تكلفة عالمي.

## اكتشاف النماذج

يعمل **Fetch models** حيث يدعمه الإعداد؛ بعض النشر يتطلب اسم model أو deployment يدويًا. صلاحيات القائمة والتوليد منفصلة.

يتبع **اختبار الاتصال** نمط الاختبار: يمكن لـ `models-then-chat` النجاح من القائمة فقط، بينما ينفذ `chat-only` توليدًا قصيرًا. استخدم مهمة حقيقية صغيرة للتحقق من النموذج وشكل الإخراج المطلوب.

- لدى Anthropic وGoogle بروتوكولات قائمة أصلية.
- يعرض Ollama الوسوم المنزّلة، وLM Studio النماذج التي يكشفها خادمه.
- يحتاج Azure OpenAI إعداد deployment وإصدار API، ولا تعوضهما قائمة عامة.
- قد تقيد البوابات الاكتشاف مع السماح بمحادثة لنموذج معين.

## بداية سريعة

1. اختر الإعداد الموافق في Notemd.
2. أدخل العنوان والاعتماد والنموذج أو deployment الفعلي.
3. اختبر الاتصال ثم ملاحظة قابلة للحذف.
4. راجع المخرجات والتقدم قبل تفعيل الدفعات أو التوجيه الخاص.

محليًا، نزّل أو حمّل النموذج وشغّل الخادم أولًا. لا يحتاج Ollama مفتاحًا؛ مفتاح LM Studio اختياري وقيمته الجاهزة `EMPTY`، لكن أدخل رمزًا حقيقيًا إذا طلب الخادم المصادقة. البحث الشبكي لا يصبح دون اتصال.
