# مزوّد OpenAI

<TLDR>
يستخدم إعداد OpenAI تنفيذ Chat Completions المتوافق المشترك. أدخل مفتاح API ونموذجًا يقبل البروتوكول. النموذج الافتراضي نقطة بداية، لا ضمان لصلاحيات حسابك الحالية أو توصية لكل مهمة.
</TLDR>

## الإعداد

اختر **OpenAI** وأدخل المفتاح، واستخدم `https://api.openai.com/v1` للعنوان الرسمي. اختر نموذجًا مخوّلًا يقبل chat completions؛ ظهوره في القائمة لا يجعله متوافقًا إن كان متاحًا عبر API آخر فقط.

للبوابات استخدم الإعداد المطابق كي تُطبق العناوين والترويسات الصحيحة. مع Azure اختر **Azure OpenAI** واضبط deployment وAPI version مستقلين.

## العنوان والمصادقة

| الحقل | القيمة الجاهزة |
| ------- | -------------- |
| بروتوكول النقل | `openai-compatible` |
| API key | مطلوب |
| العنوان الأساسي | `https://api.openai.com/v1` |
| النموذج الافتراضي | `gpt-4o` |
| Temperature | `0.5` |
| اختبار الاتصال | `models-then-chat` |

يوحّد التنفيذ صيغ URL المعروفة قبل تركيب مسار النماذج أو المحادثة. ابدأ بالعنوان الجاهز وافحص المسار الفعلي عند التشخيص بدل إضافة أجزاء بالتخمين.

## اكتشاف النماذج

يجلب **Fetch models** قائمة من العنوان المحدد. قد ينجح **اختبار الاتصال** بالقائمة دون توليد محادثة؛ اختبر المزوّد والنموذج الدقيقين على ملاحظة قابلة للحذف.

خيارات reasoning وthinking وأخذ العينات وحدود token تخضع لقواعد الإعداد والنموذج. إدراج النموذج لا يضمن قبول كل المعاملات.

## استكشاف الأخطاء

- `401` أو `403`: افحص المفتاح وصلاحيات المشروع والنموذج وحالة الحساب.
- `404`: افحص العنوان ومعرّف النموذج ودعم API له.
- القائمة تعمل والمهمة تفشل: افحص خطأ المحادثة الفعلي والمعاملات.
- استجابة طويلة تفشل أو تنقطع: راجع حجم المصدر وحد الإخراج والاستجابة؛ الاختبار القصير لا يمثل كل الحالات.

## متى تختاره

استخدمه للوصول المباشر إلى نماذج OpenAI التي تقبل بروتوكول Chat Completions المطبق. قيّم ملاحظة ممثلة؛ الأسعار وتوافر النماذج قد يتغيران مستقلين عن إصدار Notemd.
