# ワークフロー

<TLDR>
既存のサイドバーアクションを順に実行します。フォルダー選択やアクティブエディターを要する場合があります。各アクションは入力、出力、副作用を保持するため、単純なテキストパイプではありません。専用テスト領域から始めます。
</TLDR>

## 概要

付属する **One-Click Extract**：

```text
One-Click Extract::process-current-add-links>batch-generate-from-titles>batch-mermaid-fix
```

1. アクティブノートにリンクを追加し、設定済みなら概念を作成。
2. 概念またはバッチで選んだフォルダーの対象ノートに本文を生成。既存ファイルを含み得ます。
3. 生成後の complete フォルダーの Mermaid を修復。

既定には Web 調査がありません。本文生成の独立設定を有効にした場合だけ調査を使用します。[バッチ処理](../advanced/batch-processing)で範囲と出力を確認します。

## 仕組み

### 実行の流れ

順番に動き、進行ステップと失敗を報告します。キャンセルは後続と対応する要求に伝わりますが、完了書き込みは残り、全体の原子的ロールバックはありません。

概念フォルダーを初期候補にし、本文生成が原フォルダーと complete を記録し、次の Mermaid 修復に渡します。他のアクションはそれぞれのノート、選択、対話条件を維持します。

### DSL

1行にボタン名を定義し、`::` で名前とアクション、`>` で ID を区切ります。空行と `#` 開始行は無視し、未知 ID は拒否します。

```text
抽出と図::extract-concepts-current>summarize-as-mermaid
```

ビルダーでも直接編集でも設定できます。ID は安定しており、表示名は UI 言語に従います。フォルダー版は独自 ID で、一般的な文字列置換規則ではありません。

| ID | 動作／前提 |
| ------------ | ----------------------- |
| `process-current-add-links` | アクティブノートにリンク追加 |
| `process-folder-add-links` | 指定フォルダーにリンク追加 |
| `extract-concepts-current` | 現在のノートから概念抽出 |
| `extract-concepts-folder` | 指定フォルダーから概念抽出 |
| `generate-from-title` | 現在のタイトルから本文生成 |
| `batch-generate-from-titles` | フォルダー内の対象ノートに生成 |
| `research-and-summarize` | Markdown エディターの選択またはタイトルを調査 |
| `summarize-as-mermaid` | 対応するアクティブ入力を Mermaid 要約 |
| `generate-diagram` | 1 回の実行で複数の図表タイプを選び、タイプごとに複数の出力形式を指定できます。選択を解除しても形式の設定は保持されます。すべて解除すると、本文を自動解析します。 |
| `preview-diagram` | 対応する図ソース／成果物をプレビュー |
| `translate-current-file` | アクティブな対応ファイルを翻訳 |
| `batch-translate-folder` | 選択フォルダーを翻訳 |
| `extract-original-text` | 指定した原文を抽出 |
| `batch-extract-original-text` | フォルダーの対象ファイルから原文抽出 |
| `split-note-by-chapters` | 現在のノートを章別に分割 |
| `batch-mermaid-fix` | フォルダー内の Mermaid ブロックを修復 |
| `fix-formula-current` | 現在の数式区切りを正規化 |
| `batch-fix-formula` | フォルダーの数式区切りを正規化 |
| `check-duplicates-current` | 現在のノートで重複確認 |
| `check-remove-duplicate-concepts` | 対話的に重複概念を確認・削除 |
| `test-llm-connection` | プロバイダー接続テスト |
| `probe-slide-export-env` | ローカルのスライド出力環境確認 |
| `export-slides` | 現在のファイルをスライドに出力 |

### 既定とカスタム

One-Click Extract が付属する既定です。追加ボタンは自分で定義します。名前と順番を設定し、サイドバーのツールチップを確認してください。解析エラーを修正してから実行を頼ります。

## 設定

| 設定 | 既定値 | 意味 |
| --------- | --------- | -------- |
| `customWorkflowErrorStrategy` | `stop_on_error` | 最初の報告失敗で停止 |
| `useMultiModelSettings` | `false` | 個別指定を有効にするまでは active provider |
| `enableResearchInGenerateContent` | `false` | タイトル生成での調査は既定で無効 |

`continue_on_error` は失敗後も次を実行できます。残り入力で後続が動ける場合だけ選びます。続行しても部分失敗が成功にはなりません。

### タスク別モデル

各タスクがモデルを選択します。個別モデルの空上書きは指定プロバイダーのモデルを利用します。非公開資料では各ステップの配信先を確認してください。

## 例

空の `trial-concepts` とノート一つで実行し、概念と complete フォルダーを調べます。位置を理解する必要があればアクションを個別に試し、確認してから範囲を増やします。

## ヒント

- 失敗と出力の所有関係を追える短い列にする。
- 無人連続処理に整理／削除を入れない。確認要件は残ります。
- キャンセルや復旧競合後はログとファイルを読む。
- 実モデルとフォルダーで試す。短い接続成功は長いバッチの配額を保証しません。
