# 図の生成と出力

<TLDR>
必要な図の種類を選び、次に編集可能なソース形式を選びます。Drawnix ボードと埋め込まれた Mermaid を含む結果を Obsidian で確認し、各パネルを SVG、PNG、PDF に出力できます。
</TLDR>

## 三つの選択を区別する

| 選択 | 決めること | 例 |
|---|---|---|
| 図の種類 | 図が表す意味 | フロー、シーケンス、回路、データチャート |
| ソース形式 | 編集／再利用するファイル | Mermaid、JSON Canvas、Draw.io、Drawnix、CircuitikZ |
| 出力形式 | 共有用の画像や文書 | SVG、PNG、PDF |

Draw.io と Drawnix は図の種類ではなくソース形式です。CircuitikZ は回路向けソースです。一つのプレビューを複数形式に出せるため、CircuitikZ を選んでも SVG のみに限定されません。

## ソース形式を選ぶ

| 形式 | 用途 | ソース |
| --- | --- | --- |
| Mermaid | Markdown 内に置く図 | Mermaid コードブロック |
| JSON Canvas | Obsidian 標準 Canvas | `.canvas` |
| Draw.io | 後から diagrams.net 等で編集 | `.drawio` |
| Drawnix | 手書き／ホワイトボード風の編集 | `.drawnix` |
| CircuitikZ | 構造化された電気回路・トランジスター回路 | `.tex` |

編集先を指定する必要がなければ **Preferred source format** を **Auto** に保ちます。選択した種類に適合する形式を使います。

## 生成して出力する

1. 対応する源ノートを開きます。段落だけを図にする場合は別ノートに置きます。テキスト選択はファイル生成の範囲を狭めません。
2. 図設定で種類を選ぶか **Auto-detect** のままにします。
3. ソース形式または **Auto** を選びます。対応する編集可能ノードと Mermaid 付き知識図には **Drawnix** を選べます。
4. サイドバー／パレットで **図を生成** を実行します。
5. プレビューを点検します。Drawnix と Mermaid は源順序で一つの縦スクロール領域に並び、Mermaid は描画高で表示されます。
6. 各パネルの **Export SVG／PNG／PDF** で一つを、上部画像出力で全パネルを出します。複数パネルは原フォルダーか Vault 相対パスを選び、決定的な名前で別ファイルに保存します。個別失敗後も残りを進めます。
7. 編集用には **ソースファイルを保存** を使います。

プレビューのエクスポートメニューと各パネルヘッダーは同じ三形式を提供します。大きな結果全体を一枚の画像に固める必要はありません。

**History** はプレビューを閉じず Vault 履歴ドロワーを開きます。完了した図を検索・絞り込み、再表示や保存ファイルの参照ができます。アクティブノートがなくてもコマンドパレットやサイドバーから直接開けます。

SVG と PDF はベクトル幾何に基づき、PDF は SVG のレイアウトと文字メトリクスを使います。プレビュー全体をラスター化しません。PPI は PNG のみに影響し、72–600、既定300です。

## 密度の高い図を読みやすくする

編集可能 HTML/SVG のレーン図は先に要約を測定・折返しし、その領域を避けてタイトルとレーンヘッダーを置きます。セルを先、線とラベルを後に描き、占有領域を避ける直交グリッドで線を引きます。長文で文字を隠したり横方向のパンを必須にしたりしないためです。

Mermaid の象限図は系列別に正規化します。`quadrantChart` にフローチャート専用の引用符／形修復を適用せず、点ラベル末尾の対応しない余分な開き括弧だけを除去します。タイトル、軸、象限名に意図した括弧は残します。

[図の実例](https://github.com/Jacobinwwey/obsidian-NotEMD/tree/main/docs/diagram-examples)には実 Vault の入力、英中説明、SVG／PNG、機械可読 manifest があります。`passed` は記録された実行と bundle に対する結果で、後の版ですべて再実行した証拠ではありません。

実行カタログは33項目、UI は21ロケール、サイトは34ルートで別の面です。五つの厳密な参照文法は独立したレイアウト証拠が揃うまで選択肢に入りません。

## Mermaid を含む Drawnix

Mermaid を持つ成果物では SVG をサニタイズし、`.drawnix` メタデータにソースを保存します。プレビューには Drawnix／Plait 実行環境は不要です。既定は自己完結で `.assets` を別作成しません。引渡し用には **Also export complete Mermaid visuals** でソース、SVG、manifest を付属出力できます。旧 `.assets` をサポートし、欠損した SVG は保存ソースから再構築できる場合があります。

解決済み埋込み画像には可能ならデータを内包した SVG プレビューを使います。埋込みデータ、従来の付属ファイル、利用可能な原ソースの順で読み込みます。既存図が参照するディレクトリを残してください。新規出力が自己完結でも共有旧ディレクトリが不要とは限りません。

一つのスクロール面で、Drawnix ボードの後に源順序の Mermaid パネルを並べます。履歴から再度開くと同じパネル列、寸法、出力操作を復元します。

タイトル、要約、関係ラベルの領域を確保し、静的線はノードを避けます。読みやすい対応レイアウトを作れなければ形式エラーを報告します。枝間の矢印は静的関係で、Drawnix でノードを再配置した後の接続保持は未対応です。目的の編集先で確認してください。

## ネイティブ出力の境界

ソースと画像は別の成果物です。配布前に代表例を対象アプリで確認します。PowerPoint の表は対応する編集可能構造と、修正された結合セル下の罫線を保持しますが、Mermaid／SVG は画像フォールバックの場合があります。プレビューやスライド全体の画像点数はネイティブ検証の代用ではありません。

## 回路図

対応する要求では **Circuit diagram** と **CircuitikZ source file** を選びます。まず構造化回路を生成し、そこからソースを出すため、無制限の LaTeX 生成をモデルに任せるより制御できます。

現在の対応範囲は限定されています。ソース接地 NMOS アンプと対応 CMOS 部品の組合せが中心です。技術資料や出版物に使う前にプレビューとソースを点検してください。

SVG は Notemd が出す確認用の図で、ローカル LaTeX／TikZJax が `.tex` のコンパイルに成功した証拠ではありません。

任意のネイティブコンパイル：プレビューや SVG、PNG、プレビュー PDF に LaTeX は不要です。デスクトップでネイティブ PDF や診断が必要なら **CircuitikZ native compile environment** を開きます。システム `tectonic`／`pdflatex`、独自実行ファイル、または明示的な **Install** による固定 Tectonic を使えます。進捗とエラーを表示し、管理ランタイムは後で削除できます。

## トラブルシューティング

### 図の種類が違う

自動判定ではなく種類を指定します。回路は **Circuit diagram** と **図を生成** を使い、旧 **Mermaid 図として要約** ではありません。

### ソース形式が合わない

**Auto** に戻すか、その種類用の形式を選びます。CircuitikZ は回路、Draw.io／Drawnix は対応した構造図用です。

### 出力メニューがない

SVG、PNG、PDF には視覚プレビューが必要です。ソースだけなら保存して対応ツールで開きます。

### CircuitikZ が外でコンパイルできない

**CircuitikZ native compile environment** で検査し、管理ランタイムを修復するかシステム／独自コンパイラーが `circuitikz` を取得できるか確認します。プラグインに完全な TeX 配布物は含まれません。
