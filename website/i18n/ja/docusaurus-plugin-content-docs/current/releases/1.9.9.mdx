# Notemd 1.9.9 — 複数の図表を個別の形式で出力

<TLDR>
1 回の実行で複数の図表タイプを選び、タイプごとに複数の出力形式を指定できます。選択を解除しても形式の設定は保持されます。すべて解除すると、本文を自動解析します。
</TLDR>

## 複数の図表を個別の形式で出力

チェックボックスで生成対象に含めます。名前をクリックすると、そのタイプを選択して形式設定を開きます。ホバーやキーボードフォーカスでは設定を保存せずプレビューだけ切り替えます。Escape でメニューを閉じ、フォーカスを戻します。

対応形式を先に表示し、非対応の選択肢は表示したまま無効にします。既存の無効な要求は削除できます。形式は各タイプに属します。要求した形式がすべて使えない場合、実際のレンダラーの既定のソース形式を試し、利用できない要求を報告します。

図形 HTML は拡大縮小できる図、構造化要約 HTML は文章・構造・引用を含みます。編集可能な HTML/SVG はレンダラー名であり、ブラウザー内エディターではありません。編集にはネイティブソースを使ってください。PPTX・MP4 などのプレゼンテーション出力は設定と依存関係が独立しています。

Drawnix の概観にはラベル付きの主要な有向関係を最大 6 本、ノードごとに最大 3 本表示します。省略関係はメタデータに残します。PDF の枠内文字も表示され、古い SVG キャッシュにも対応します。枝をまたぐ矢印は静的で、Drawnix で再配置すると接続が外れる場合があります。

## ファイルと復旧

選択したファイルは元のノートと同じフォルダー、または指定した出力フォルダーへ直接、自動保存されます。名前には `topic_drawnix.pdf` や `topic_flowchart.svg` のようにタイプを付けます。同名の場合は `-2`、`-3` などを追加し、既存ファイルを上書きしません。

中間ファイル用に共通の Vault 相対パスを設定できます。空欄なら各ソースの隣の `notemd_assert/` を使います。復旧記録、描画キャッシュ、任意の添付ファイルを保存します。既存の出力が参照するファイルは保持してください。フォルダー変更は新しい実行だけに適用されます。

タイプを順番に生成します。1 つが失敗しても残りは続行し、キャンセルすると待機中のタイプを停止して完成済みファイルを保持します。出力失敗はプレビューや履歴からモデルへの再要求なしで再試行できます。生成失敗はそのタイプの再生成が必要です。旧 v1/v2 復旧記録も読み取れます。

## アップグレード

実行中のタスクを停止し Vault をバックアップします。同じ 1.9.9 Release の `main.js`、`manifest.json`、`styles.css` を入れ、設定と生成ファイルを保持して Obsidian を再読み込みします。大量処理の前に 1 件のノートで確認してください。旧設定は編集時に移行します。翻訳は直接執筆し、翻訳 API や LM Studio は使っていません。
