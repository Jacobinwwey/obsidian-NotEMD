# OpenAI プロバイダー

<TLDR>
OpenAI プリセットは共有の OpenAI-compatible Chat Completions 実装を使います。キーと対応モデルを設定してください。既定モデルは開始値で、現在の利用権や全タスクへの推奨を意味しません。
</TLDR>

## 導入

**OpenAI** を選び、API key と公式 URL `https://api.openai.com/v1` を設定します。アカウントで使える chat completions 対応モデルが必要です。別 API 専用モデルは一覧に出ても互換にはなりません。

ゲートウェイには対応プリセットを使い、適切なヘッダーと URL を適用します。Azure は **Azure OpenAI** で deployment と API version を個別設定します。

## エンドポイントと認証

| 項目 | プリセット値 |
| ------- | -------------- |
| 通信プロトコル | `openai-compatible` |
| API key | 必須 |
| 基本 URL | `https://api.openai.com/v1` |
| 既定モデル | `gpt-4o` |
| Temperature | `0.5` |
| 接続テスト | `models-then-chat` |

既知の基本 URL を正規化して一覧／チャット経路を組み立てます。デバッグではプリセット URL から始め、解決後の経路を確認します。推測でパスを付け足さないでください。

## モデルの発見

**Fetch models** は設定エンドポイントを問い合わせます。**接続をテスト** は一覧取得だけで成功し得るため、続けて正確なモデルでノートを処理します。

Reasoning、thinking、sampling、出力 token はプリセットとモデル別規則に依存します。一覧にあることは全パラメーターの受理を保証しません。

## トラブルシューティング

- `401`／`403`：キー、プロジェクト権限、モデル利用権、アカウントを確認。
- `404`：URL、モデル ID、選択 API の対応を確認。
- 一覧だけ成功：実際のチャットエラーとモデル／設定を見る。
- 長い出力の失敗：上限、入力サイズ、応答を調べる。短い接続テストだけでは再現できない場合があります。

## 選ぶ場面

実装された Chat Completions プロトコルを受け付ける直接 OpenAI モデルに使います。代表ノートで評価してください。料金とモデル提供は Notemd の公開とは独立して変化します。
