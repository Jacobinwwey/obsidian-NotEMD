# トラブルシューティング

<TLDR>
正確なプロバイダー、モデル、タスク設定で破棄可能なノートを試します。進捗と出力パスを読み、認証、生成、解析、保存の失敗を区別してください。接続テストだけでは全ワークフローを検証できません。
</TLDR>

## 概要

プラグイン／Obsidian／OS の版、アクション、プロトコル、モデルと最小再現を記録します。キャンセルが落ち着く前に別タスクを始めず、所有関係が分かるまで出力と復旧ファイルを残します。

## 診断の仕組み

### 接続テスト

プロバイダー設定の **接続をテスト** を使います。一覧だけで成功するプリセットと、小さな生成を行うものがあります。選択モデルと出力契約は実ノートで追加確認します。

### 進捗と開発者診断

進捗は状態、エラー、保存先を示します。API 表示で待機・完了・失敗を区別します。API エラーデバッグは必要時だけ有効にします。長い開発者診断は割当量を消費し得るため、短いテストが通るのにタスクが失敗する場合に意図的に使います。

診断にはノート本文、途中出力、URL、認証情報が含まれ得ます。ローカルで確認して機密を除きます。キー遮蔽済みプロファイルもメタデータの確認が必要です。

## よくある失敗

### API key がない／無効

401 なら選択 URL／サービス用のキーか、余分な空白がないか確認します。403 はアカウント、プロジェクト制限、モデル利用権、課金を調べます。再試行では認証不備を直せません。

### 通信・接続エラー

Obsidian 端末からのホスト、ポート、プロトコル、経路を確認します。Ollama／LM Studio は起動済みモデルが必要。`localhost` は別 PC ではありません。正しいプリセットを選びます。代替通信は自動選択で、利用者向け転送切替ではありません。

### レート制限（429）

並行数を下げ、要求／token 割当量と同じキーを使う他のアプリを調べます。再試行は一時的問題を回復することがありますが、すべての割当量エラーには効きません。

### モデルが見つからない

対応なら一覧を取得し、それ以外は利用可能な model／deployment を入力します。API version と地域も確認します。既定モデルは履歴値かもしれません。Azure は deployment 名、Ark は endpoint ID が必要な場合があります。

### リンク・概念が生成されない

実際の処理後ファイル、入力の内容、要求出力形式、非空で有効な概念フォルダーを確認します。単独抽出の既定はタイトルのみ、バックリンクなし。カスタムがマーカーを除去した場合は既定と比較します。

### 出力がない／場所が違う

タスクのパスを確認します。リンクは通常 `_processed.md`、翻訳は `_<language>.md`、タイトルバッチは complete 先です。翻訳先作成失敗は原フォルダーへ戻る場合があります。衝突や権限を調べてから再実行します。

### キャンセル後にファイルが残る

対応する後続は止まりますが完了書き込みは残り、受理済みの外部要求も終わり得ます。削除や全フォルダー再実行の前に、ファイル別の結果と復旧競合を確認します。

### 図・ネイティブ出力が失敗

タイプを順番に生成します。1 つが失敗しても残りは続行し、キャンセルすると待機中のタイプを停止して完成済みファイルを保持します。出力失敗はプレビューや履歴からモデルへの再要求なしで再試行できます。生成失敗はそのタイプの再生成が必要です。旧 v1/v2 復旧記録も読み取れます。

図形 HTML は拡大縮小できる図、構造化要約 HTML は文章・構造・引用を含みます。編集可能な HTML/SVG はレンダラー名であり、ブラウザー内エディターではありません。編集にはネイティブソースを使ってください。PPTX・MP4 などのプレゼンテーション出力は設定と依存関係が独立しています。 [図表マニュアル](../features/diagrams).

## 報告方法

1. 合成した短いノートと専用フォルダーで再現。
2. 正確な版、アクション、モデル、必要設定、期待と実際を記載。
3. 機密を除いた進捗／エラーと最小成果物を添付。不要な端点情報も削除。
4. 単独ファイルと既定プロンプトでも起きるか明記。
5. [GitHub Issues](https://github.com/Jacobinwwey/obsidian-NotEMD/issues) に投稿。

画像だけでは形式やキャンセルの不具合を証明しにくいため、可能なら原文と出力、または最小の操作列を添えます。
