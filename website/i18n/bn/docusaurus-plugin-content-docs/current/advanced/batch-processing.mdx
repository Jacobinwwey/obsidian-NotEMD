# ব্যাচ প্রক্রিয়াকরণ

<TLDR>Folder tasks selection ও progress ভাগ করে, কিন্তু output/overwrite নিয়ম আলাদা। Default concurrency এক। Test folder-এ scope ও destination যাচাই করে কাজ বাড়ান।</TLDR>

## সারসংক্ষেপ

Sidebar বা file explorer থেকে links, concepts, title generation, translation, original passages, Mermaid ও formula repair চালান। Generic folder research নেই; title generation-এ optional research আছে। Batch পুরো folder-এর transaction নয়; অন্য file fail বা cancel হলেও সম্পন্ন outputs থাকে।

## কীভাবে কাজ করে

### Execution model

1. Task ও শুধু কাঙ্ক্ষিত files-এর folder বাছুন।
2. Extension, selection ও task-specific output exclusions প্রয়োগ হয়।
3. Task-এর provider/model ব্যবহৃত হয়ে progress, failures ও paths জানায়।
4. শেষে বা cancel-এর পরে report ও files দেখে retry করুন।

Links, concepts, titles, original text, Mermaid ও formulas প্রথমে subfolders অন্তর্ভুক্ত করে। **Folder translation প্রথমে শুধু direct children নেয়।** Developer mode ও advanced file selection দুটো চালু থাকলে profile scope/filter পাল্টাতে পারে। প্রকৃত matched files দেখুন।

### Overwrite

| কাজ | পুনরায় চালানোর আগে |
| ------ | ------------------------------------ |
| Links | Default separate outputs; suffix, folder ও original-moving setting দেখুন |
| Concept extraction | Backlinks চালু থাকলে existing note-এ যোগ হতে পারে; duplicate review আলাদা |
| Title generation | যোগ্য source-এ content লিখে complete destination ফাঁকা থাকলে move |
| Translation | Matching translation overwrite হতে পারে; default `_<language>.md` |
| Mermaid / formula | Selected note পরিবর্তন করে; sample ও backup রাখুন |

সবার জন্য skip/append/replace নেই। Complete destination থাকলে move আটকে যায়, আগের generation নয়। Generated ও moved counts আলাদা।

### Concurrency

Sample সফল না হওয়া পর্যন্ত `batchConcurrency: 1` রাখুন। কিছু path-এ `enableBatchParallelism`-ও দরকার, folder translation সরাসরি concurrency নেয়। বেশি parallelism provider, memory ও local server-এর চাপ বাড়ায়, গতি নিশ্চিত করে না। Request/group delay সব quota বা অন্য client-এর চাপ এড়াতে পারে না।

## সেটিংস

| সেটিং | প্রাথমিক মান | প্রভাব |
| --------- | --------- | -------- |
| `batchConcurrency` | `1` | Applicable batch paths-এর requested concurrency |
| `enableBatchParallelism` | `false` | Supported parallel scheduling চালু |
| `batchSize` | `50` | Grouped scheduling-এর size |
| `batchInterDelayMs` | `1000` | Scheduled groups-এর বিরতি |
| `apiCallIntervalMs` | `500` | Concurrent API scheduling interval |
| `folderTaskIncludeSubfoldersMode` | `legacy` | Task অনুযায়ী পুরোনো subfolder scope রাখা |
| `enableStableApiCall` | `false` | Explicit stable request mode |

### Task model

সংশ্লিষ্ট single-file task-এর মতোই provider/model বাছা হয়। Private content-এর আগে দেখুন। Batch titles-এর local retrieval শুরুতে একটি snapshot নেয়; চলার মধ্যে edits পরে পাওয়া context-এর সঙ্গে মেশে না। পরিবর্তন অন্তর্ভুক্ত করতে নতুন batch চালান।

## উদাহরণ

দুটি title note নিয়ে `trial-titles` বানান। **Batch generate from titles** চালিয়ে content, পাশের `trial-titles_complete` ও generated/moved/error counts দেখুন। ব্যর্থ file আগে diagnose করুন; source folder পুনরায় চালানো শুধু অসম্পূর্ণ কাজের exact auto-resume নয়।

## Cancel ও recovery

নতুন scheduling থামে ও supported requests-এ cancel যায়। External system-এর accepted call/write শেষ হতে পারে; billing provider-এর নিয়ন্ত্রণে। Settle হওয়ার পরে complete files ও recovery/conflict paths তুলুন। তুলনা শেষের আগে recovery outputs রাখুন।

## পরামর্শ

- Selection profile-এর প্রকৃত files যাচাই করুন।
- 429 হলে concurrency কমিয়ে quota দেখুন।
- Cancel, failure ও completion আলাদা রাখুন।
- Existing note বদলের আগে untouched sample ও backup রাখুন।
