# কর্মপ্রবাহ

<TLDR>কর্মপ্রবাহ sidebar-এর বিদ্যমান actions ক্রমে চালায়। Folder নির্বাচন বা active editor দরকার হতে পারে। এটি text pipe নয়; প্রতিটি কাজ নিজের input, output ও side effects রাখে। Test note ও আলাদা folder দিয়ে শুরু করুন।</TLDR>

## সারসংক্ষেপ

ডিফল্ট **One-Click Extract**:

```text
One-Click Extract::process-current-add-links>batch-generate-from-titles>batch-mermaid-fix
```

1. Active note-এ link যোগ করে, folder সেট থাকলে concepts বানায়।
2. Concept বা নির্বাচিত folder-এর যোগ্য notes title থেকে পূরণ করে; পুরোনো নোটও অন্তর্ভুক্ত।
3. Generation-এর complete folder-এ Mermaid ঠিক করে।

Default chain-এ web research নেই। Generation-এর আলাদা setting চালু হলে তবেই তা যোগ হয়। [Batch processing](../advanced/batch-processing)।

## কীভাবে কাজ করে

### ক্রমিক চালনা

ধাপগুলো পরপর চলে, sidebar active step ও failures জানায়। Cancel পরের ধাপ থামিয়ে supported requests-এ পৌঁছায়। সম্পন্ন লেখা থাকে; chain-wide rollback নেই। Concept folder প্রথম পছন্দ; generation source/complete folder রাখে, তারপর Mermaid complete ব্যবহার করে। অন্য action-এর active file, selection ও interaction-এর শর্ত অপরিবর্তিত।

### DSL রূপ

প্রতি লাইনে নামসহ একটি button। `::` নাম ও action list, `>` action IDs আলাদা করে। ফাঁকা ও `#` দিয়ে শুরু লাইন উপেক্ষিত; অজানা ID প্রত্যাখ্যাত।

```text
ধারণা ও চিত্র::extract-concepts-current>summarize-as-mermaid
```

Builder ব্যবহার করুন বা DSL সম্পাদনা করুন। IDs স্থায়ী, labels UI ভাষা অনুযায়ী। Folder variants-এর নিজস্ব ID আছে; ইচ্ছামতো string বদলে তৈরি করবেন না।

### Default ও custom

One-Click Extract প্রস্তুত থাকে। অন্যান্য button আপনার সংজ্ঞা। Settings-এ নাম ও action order দিন, sidebar tooltip দেখুন। Parser error ঠিক করার পর chain চালান।

## সেটিংস

| সেটিং | প্রাথমিক মান | প্রভাব |
| --------- | --------- | -------- |
| `customWorkflowErrorStrategy` | `stop_on_error` | প্রথম reported step error-এ থামা |
| `useMultiModelSettings` | `false` | Task routing চালু না হওয়া পর্যন্ত active provider |
| `enableResearchInGenerateContent` | `false` | চালু না করলে title generation-এ research নেই |

`continue_on_error` আগের failure-এর পরেও পরের ধাপ চালাতে পারে। অবশিষ্ট input নিয়ে কাজ সম্ভব হলেই ব্যবহার করুন; continuation আংশিক কাজকে সম্পূর্ণ সফল করে না।

### Task-specific models

Provider/model নির্বাচন কাজের কাছে থাকে। ফাঁকা override নির্বাচিত provider-এর configured model নেয়। ব্যক্তিগত content-এর আগে প্রতিটি route দেখুন।

## উদাহরণ

ফাঁকা `trial-concepts` সেট করে একটি disposable source চালান। তৈরি concepts ও complete folder দেখুন। Destination অস্পষ্ট হলে আগে একেকটি action আলাদা চালান, তারপর scope বাড়ান।

## পরামর্শ

- Error ও output ownership বোঝার মতো ছোট chain রাখুন।
- Cleanup/delete actions-এর interactive confirmation থাকে; unattended chain-এ এড়ান।
- Cancel বা recovery conflict-এর পর log/files দেখুন।
- নির্দিষ্ট provider/model ও folder দিয়ে test করুন; short connection test বড় batch-এর quota প্রমাণ করে না।
