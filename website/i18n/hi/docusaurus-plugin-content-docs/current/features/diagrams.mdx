# आरेख

<TLDR>पहले diagram type, फिर editable source format चुनें। Obsidian में पूरा result देखें, Drawnix board और उसमें Mermaid visuals सहित। हर panel को SVG, PNG या PDF में export कर सकते हैं।</TLDR>

## तीन अलग चुनाव

| चयन | क्या नियंत्रित होता है | उदाहरण |
| --- | --- | --- |
| Diagram type | आरेख का अर्थ | Flowchart, sequence, circuit, data chart |
| Source format | संपादन या पुनः उपयोग योग्य फ़ाइल | Mermaid, JSON Canvas, Draw.io, Drawnix, CircuitikZ |
| Export format | साझा करने का चित्र या document | SVG, PNG, PDF |

Draw.io और Drawnix source formats हैं, diagram types नहीं। CircuitikZ circuits का source है; उसे चुनने से visual export केवल SVG तक सीमित नहीं होता।

## Source format चुनें

| Format | उपयुक्त काम | Source file |
| --- | --- | --- |
| Mermaid | Markdown के भीतर diagrams | Mermaid code block वाला पाठ |
| JSON Canvas | Native Obsidian canvas | `.canvas` |
| Draw.io | diagrams.net या compatible editor में आगे संपादन | `.drawio` |
| Drawnix | Whiteboard या हाथ से बने जैसा संपादन | `.drawnix` |
| CircuitikZ | संरचित electrical/transistor circuits | `.tex` |

विशिष्ट editor न चाहिए तो **Preferred source format** को **Auto** रखें; सही diagram type का compatible format चुना जाता है।

## बनाना और export करना

1. Supported source note खोलें। Passage हेतु अलग note बनाएँ; selection file action नहीं घटाती।
2. Type या **Auto-detect** चुनें।
3. Source या **Auto** चुनें; Drawnix editable nodes और embedded Mermaid वाला supported map देता है।
4. **Generate diagram** चलाएँ।
5. एक vertical scroll preview में board तथा source-order Mermaid panels देखें; panels actual rendered height लेते हैं।
6. हर panel का **Export SVG**, **Export PNG**, **Export PDF** या ऊपर का all-panel export लें। Source folder या custom vault-relative folder चुनें; हर panel का deterministic नाम और individual error के बाद continuation है।
7. Editable artifact हेतु **Save source file** करें।

Export menu और panel header वही तीन actions देते हैं। **History** preview छिपाए बिना search, filters, reopen और saved artifacts खोलता है। Active note न हो तब भी palette/sidebar से history मिलती है।

SVG/PDF vector geometry से बनते हैं। PDF SVG layout और text metrics उपयोग करता है, पूरी preview को rasterize नहीं। PPI केवल PNG पर लागू: 72–600, default 300।

## घने आरेख की पठनीयता

Editable HTML/SVG lane-grid पहले summary मापकर wrap करता, फिर title/header रखता है। Cells connectors और edge labels से पहले paint होते हैं; orthogonal routing occupied cells और text areas बचाती है।

`quadrantChart` पर अलग normalization होता है, flowchart-specific quote/shape fixes नहीं। Copied opening bracket केवल point label का unmatched आखिरी character हो तो हटता है। Titles, axes और quadrant names के जानबूझकर दिए brackets रहते हैं।

[Example set](https://github.com/Jacobinwwey/obsidian-NotEMD/tree/main/docs/diagram-examples) bilingual inputs, SVG/PNG और manifest रखता है। `passed` उसी run और bundle identity का है, बाद की release में हर type के नए परीक्षण का नहीं। Catalog 33 rows, UI 21 locales और website 34 locales अलग surfaces हैं। पाँच exact reference grammars independent layout evidence तक selector से बाहर हैं।

## Drawnix में Mermaid

SVG sanitize होकर Mermaid source `.drawnix` metadata में रहता है; preview को Drawnix/Plait runtime नहीं चाहिए। Default self-contained है, अलग `.assets` नहीं। **Also export complete Mermaid visuals** से source, SVG और manifest companions बनते हैं। पुराने `.assets` समर्थित हैं और missing SVG saved source से पुनः बन सकता है।

Resolved image embeds जहाँ संभव data-backed SVG लेते हैं। पहले embedded data, फिर पुराने companion files और फिर available source rebuild लोड होता है। Referenced पुरानी files रखें; नया self-contained export पुरानी shared directory बेकार होने का प्रमाण नहीं।

एक scrolling surface पहले Drawnix, फिर source-order Mermaid दिखाती है। Saved history reopen पर panels, dimensions और export actions लौटते हैं। Titles, summary और relationship labels की जगह सुरक्षित है। Supported readable layout न बन सके तो format error आता है। Cross-branch arrows static relations हैं; Drawnix rearrangement बाद attachment वर्तमान evidence से supported नहीं। Target editor में देखें।

## Native export सीमाएँ

Source और visual export अलग deliverables हैं। बाँटने से पहले target app में sample जाँचें। PowerPoint supported editable tables और merged cells के नीचे सुधरे separators रखता है; Mermaid/SVG image fallback हो सकते हैं। Preview या पूरे पृष्ठ की screenshot score native verification नहीं है।

## Circuit diagrams

**Circuit diagram** और **CircuitikZ source file** चुनें। पहले structured description, फिर source बनता है, unrestricted LaTeX नहीं। Support जानबूझकर सीमित है, खासकर common-source NMOS और supported CMOS blocks। Technical/publication use से पहले source और preview जाँचें।

SVG एक review साथी है, local LaTeX/TikZJax compile proof नहीं। Preview, SVG, PNG और preview PDF को LaTeX नहीं चाहिए। Desktop पर native PDF/diagnostics हेतु **CircuitikZ native compile environment** खोलें: system `tectonic`/`pdflatex`, custom executable या स्पष्ट **Install** के बाद pinned managed Tectonic। Panel progress/errors और managed runtime removal देता है।

## समस्या निवारण

### गलत type

Type स्पष्ट चुनें। Circuit के लिए **Circuit diagram** तथा **Generate diagram**, पुराना **Summarise as Mermaid diagram** नहीं।

### अनुपयुक्त source

**Auto** पर लौटें या type-compatible format लें। CircuitikZ circuits के लिए, Draw.io/Drawnix supported structures के लिए हैं।

### Export menu नहीं

SVG/PNG/PDF को visual preview चाहिए। केवल text हो तो source बचाकर matching बाहरी tool में खोलें।

### CircuitikZ compile नहीं होता

**CircuitikZ native compile environment** जाँचें। Managed runtime repair करें या custom/system compiler का `circuitikz` package access देखें। Plugin file में पूरी TeX distribution नहीं आती।
