# आरेख

<TLDR>
एक बार में कई आरेख प्रकार चुनें और हर प्रकार के लिए अलग-अलग कई आउटपुट प्रारूप तय करें। प्रकार का चयन हटाने पर उसके प्रारूप सुरक्षित रहते हैं; कोई प्रकार न चुना हो तो सामग्री का अपने-आप विश्लेषण होता है।
</TLDR>


हर आरेख के पूर्वावलोकन में अलग ज़ूम, पैन, फिट और वास्तविक आकार के नियंत्रण हैं। Ctrl/Command + माउस व्हील ज़ूम करता है; सामान्य व्हील स्क्रॉल करता है। बड़े PNG निर्यात चुने हुए 72–600 PPI को बनाए रखते हैं (डिफ़ॉल्ट 300)। SVG वेक्टर प्रारूप है; PPI केवल रास्टर निर्यात पर लागू होता है।


**Obsidian के अनुकूल चित्र बनाएँ** — डिफ़ॉल्ट रूप से चालू। Obsidian में PNG डिकोडिंग जाँचता है; विफल होने पर मूल चित्र सुरक्षित रखकर कम PPI की प्रति जोड़ता है। दोनों फ़ाइल नामों में PPI होता है। बंद होने पर केवल अनुरोधित मूल चित्र निर्यात होता है। (`note_drawnix_300ppi.png`, `note_drawnix_obsidian_87ppi.png`).

## तीन अलग चुनाव

| चयन | क्या नियंत्रित होता है | उदाहरण |
| --- | --- | --- |
| Diagram type | आरेख का अर्थ | Flowchart, sequence, circuit, data chart |
| Source format | संपादन या पुनः उपयोग योग्य फ़ाइल | Mermaid, JSON Canvas, Draw.io, Drawnix, CircuitikZ |
| Export format | साझा करने का चित्र या document | SVG, PNG, PDF |

आरेख HTML में ज़ूम करने योग्य चित्र होता है; संरचित सारांश HTML में पाठ, संरचना और संदर्भ होते हैं। संपादन योग्य HTML/SVG रेंडरर का नाम है, ब्राउज़र संपादक नहीं। संपादन के लिए मूल स्रोत फ़ाइल लें। PPTX और MP4 सहित प्रस्तुति निर्यात की सेटिंग और निर्भरताएँ अलग रहती हैं।

## Source format चुनें

| Format | उपयुक्त काम | Source file |
| --- | --- | --- |
| Mermaid | Markdown के भीतर diagrams | Mermaid code block वाला पाठ |
| JSON Canvas | Native Obsidian canvas | `.canvas` |
| Draw.io | diagrams.net या compatible editor में आगे संपादन | `.drawio` |
| Drawnix | Whiteboard या हाथ से बने जैसा संपादन | `.drawnix` |
| CircuitikZ | संरचित electrical/transistor circuits | `.tex` |

समर्थित प्रारूप पहले दिखते हैं; असंगत विकल्प दिखाई देते हैं लेकिन निष्क्रिय रहते हैं। पहले से सहेजे निष्क्रिय अनुरोध हटाए जा सकते हैं। हर प्रकार अपने प्रारूप रखता है। कोई अनुरोधित प्रारूप उपलब्ध न हो तो सक्रिय रेंडरर का डिफ़ॉल्ट स्रोत प्रारूप आज़माया जाता है और अनुपलब्ध अनुरोध बताए जाते हैं।

## बनाना और export करना

1. Supported source note खोलें। Passage हेतु अलग note बनाएँ; selection file action नहीं घटाती।
2. एक बार में कई आरेख प्रकार चुनें और हर प्रकार के लिए अलग-अलग कई आउटपुट प्रारूप तय करें। प्रकार का चयन हटाने पर उसके प्रारूप सुरक्षित रहते हैं; कोई प्रकार न चुना हो तो सामग्री का अपने-आप विश्लेषण होता है।
3. चेकबॉक्स प्रकार को निर्माण में शामिल करता है। नाम पर क्लिक करके प्रकार चुनें और उसके प्रारूप बदलें। माउस ले जाने या कीबोर्ड फ़ोकस से सेटिंग सहेजे बिना पूर्वावलोकन बदलता है। Escape मेनू बंद करके फ़ोकस लौटाता है।
4. **Generate diagram** चलाएँ।
5. चुनी फ़ाइलें अपने-आप स्रोत नोट के पास या सीधे तय आउटपुट फ़ोल्डर में निर्यात होती हैं। नाम में प्रकार होता है, जैसे `topic_drawnix.pdf` और `topic_flowchart.svg`। नाम टकराने पर `-2`, `-3` आदि जुड़ते हैं; पुरानी फ़ाइल नहीं बदलती।
6. एक vertical scroll preview में board तथा source-order Mermaid panels देखें; panels actual rendered height लेते हैं।
7. हर panel का **Export SVG**, **Export PNG**, **Export PDF** या ऊपर का all-panel export लें। Source folder या custom vault-relative folder चुनें; हर panel का deterministic नाम और individual error के बाद continuation है। Editable artifact हेतु **Save source file** करें।

मध्यवर्ती फ़ाइलों के लिए Vault के सापेक्ष साझा फ़ोल्डर तय करें, या हर स्रोत के पास `notemd_assert/` इस्तेमाल करने के लिए खाली छोड़ें। इसमें पुनर्प्राप्ति रिकॉर्ड, रेंडर कैश और वैकल्पिक संलग्नक रहते हैं। जिन फ़ाइलों के संदर्भ अभी उपयोग में हैं उन्हें रखें; फ़ोल्डर बदलने का असर केवल नए रन पर है।

प्रकार क्रम से बनते हैं। एक की विफलता बाकी को नहीं रोकती; रद्द करने पर लंबित प्रकार रुकते हैं और पूरी फ़ाइलें बची रहती हैं। पूर्वावलोकन या इतिहास से मॉडल को नया अनुरोध भेजे बिना निर्यात फिर आज़माएँ। निर्माण विफल हो तो उस प्रकार को दोबारा बनाना होगा। v1/v2 रिकॉर्ड अब भी पढ़े जा सकते हैं।

Export menu और panel header वही तीन actions देते हैं। **History** preview छिपाए बिना search, filters, reopen और saved artifacts खोलता है। Active note न हो तब भी palette/sidebar से history मिलती है।

SVG/PDF vector geometry से बनते हैं। PDF SVG layout और text metrics उपयोग करता है, पूरी preview को rasterize नहीं। PPI केवल PNG पर लागू: 72–600, default 300।

## घने आरेख की पठनीयता

Editable HTML/SVG lane-grid पहले summary मापकर wrap करता, फिर title/header रखता है। Cells connectors और edge labels से पहले paint होते हैं; orthogonal routing occupied cells और text areas बचाती है।

`quadrantChart` पर अलग normalization होता है, flowchart-specific quote/shape fixes नहीं। Copied opening bracket केवल point label का unmatched आखिरी character हो तो हटता है। Titles, axes और quadrant names के जानबूझकर दिए brackets रहते हैं।

[Example set](https://github.com/Jacobinwwey/obsidian-NotEMD/tree/main/docs/diagram-examples) bilingual inputs, SVG/PNG और manifest रखता है। `passed` उसी run और bundle identity का है, बाद की release में हर type के नए परीक्षण का नहीं। Catalog 33 rows, UI 21 locales और website 34 locales अलग surfaces हैं। पाँच exact reference grammars independent layout evidence तक selector से बाहर हैं।

## Drawnix में Mermaid

SVG sanitize होकर Mermaid source `.drawnix` metadata में रहता है; preview को Drawnix/Plait runtime नहीं चाहिए। Default self-contained है, अलग `.assets` नहीं। **Also export complete Mermaid visuals** से source, SVG और manifest companions बनते हैं। पुराने `.assets` समर्थित हैं और missing SVG saved source से पुनः बन सकता है।

Resolved image embeds जहाँ संभव data-backed SVG लेते हैं। पहले embedded data, फिर पुराने companion files और फिर available source rebuild लोड होता है। Referenced पुरानी files रखें; नया self-contained export पुरानी shared directory बेकार होने का प्रमाण नहीं।

Drawnix सभी स्पष्ट दिशात्मक संबंध रखता है; कुल संख्या या प्रति नोड की कोई तय सीमा नहीं है। केवल समान कथनों के दोहराव हटाए जाते हैं; अलग विधेय और उलटी दिशाएँ बनी रहती हैं। बाहरी मार्गों के क्षेत्र ओवरलैप होने पर अलग ट्रैक मिलते हैं, अन्य मार्ग ट्रैक दोबारा इस्तेमाल करते हैं। लेबल को उनके आकार के अनुसार पंक्तियाँ मिलती हैं और कैनवास आवश्यकता पर बढ़ता है। बिना लेबल, सामान्य या पदानुक्रम को दोहराने वाले तीर कारण सहित मेटाडेटा में रहते हैं। संबंध बॉक्स का पाठ PDF में दिखता है, पुराने SVG कैश से भी। शाखाओं के बीच तीर स्थिर रहते हैं और Drawnix में पुनर्व्यवस्था के बाद अलग हो सकते हैं।

## Native export सीमाएँ

Source और visual export अलग deliverables हैं। बाँटने से पहले target app में sample जाँचें। PowerPoint supported editable tables और merged cells के नीचे सुधरे separators रखता है; Mermaid/SVG image fallback हो सकते हैं। Preview या पूरे पृष्ठ की screenshot score native verification नहीं है।

## Circuit diagrams

**Circuit diagram** और **CircuitikZ source file** चुनें। पहले structured description, फिर source बनता है, unrestricted LaTeX नहीं। Support जानबूझकर सीमित है, खासकर common-source NMOS और supported CMOS blocks। Technical/publication use से पहले source और preview जाँचें।

SVG एक review साथी है, local LaTeX/TikZJax compile proof नहीं। Preview, SVG, PNG और preview PDF को LaTeX नहीं चाहिए। Desktop पर native PDF/diagnostics हेतु **CircuitikZ native compile environment** खोलें: system `tectonic`/`pdflatex`, custom executable या स्पष्ट **Install** के बाद pinned managed Tectonic। Panel progress/errors और managed runtime removal देता है।

## समस्या निवारण

### गलत type

Type स्पष्ट चुनें। Circuit के लिए **Circuit diagram** तथा **Generate diagram**, पुराना **Summarise as Mermaid diagram** नहीं।

### अनुपयुक्त source

समर्थित प्रारूप पहले दिखते हैं; असंगत विकल्प दिखाई देते हैं लेकिन निष्क्रिय रहते हैं। पहले से सहेजे निष्क्रिय अनुरोध हटाए जा सकते हैं। हर प्रकार अपने प्रारूप रखता है। कोई अनुरोधित प्रारूप उपलब्ध न हो तो सक्रिय रेंडरर का डिफ़ॉल्ट स्रोत प्रारूप आज़माया जाता है और अनुपलब्ध अनुरोध बताए जाते हैं।

### Export menu नहीं

SVG/PNG/PDF को visual preview चाहिए। केवल text हो तो source बचाकर matching बाहरी tool में खोलें।

### CircuitikZ compile नहीं होता

**CircuitikZ native compile environment** जाँचें। Managed runtime repair करें या custom/system compiler का `circuitikz` package access देखें। Plugin file में पूरी TeX distribution नहीं आती।

## 1.9.10 — सुरक्षित पूर्वावलोकन और Vault स्थानीय सेटिंग

आयातित SVG पूर्वावलोकन सक्रिय सामग्री और बाहरी संसाधन हटाता है, लेकिन चीनी लेबल और पैनल शैली बनाए रखता है। स्थानीय प्रदाता अब प्रत्येक Vault में अलग हैं; सेटिंग में पुरानी सूची स्पष्ट रूप से आयात करें, जिससे मूल सूची और मौजूदा कॉन्फ़िगरेशन सुरक्षित रहें। प्रस्तुति पूर्वावलोकन साझा उपयोगकर्ताओं का प्रबंधन करने वाला loopback सर्वर उपयोग करता है। पसंदीदा सहेजने और कॉपी करने की विफलता बताई जाती है; हटाना Vault की प्राथमिकताओं का पालन करता है। PNG संगतता चालू रहती है: मूल चित्र सुरक्षित रहता है और आवश्यकता पर ही सत्यापित कम PPI प्रति जुड़ती है। Drawnix संबंधों की निश्चित सीमा नहीं है; प्रस्तुति सेटिंग अलग रहती हैं। समान संस्करण की फ़ाइलें इंस्टॉल करके पुनः लोड करें और बैच से पहले एक नोट जाँचें।

## 1.9.11 — अधिक स्पष्ट आरेख और भरोसेमंद PDF निर्यात

Drawnix निकट संबंध वाली शाखाओं को पास रखता है और जोड़ने वाली रेखाओं का एक-दूसरे पर चढ़ना और कटना कम करता है। सभी नोड और स्पष्ट संबंध सुरक्षित रहते हैं। पुनर्व्यवस्था के बाद शाखाओं के बीच के तीर स्थिर रहते हैं।

PDF निर्यात सफ़ाई के बाद जटिल SVG चयनकों और विरासत में मिली शैलियों को संभालता है। अनुपस्थित viewBox पूरे किए जाते हैं; बहुत बड़े पृष्ठ वेक्टर बनाए रखते हुए समान अनुपात में छोटे किए जाते हैं।

निदान टैग के अनुसार समूहों में होते हैं और डिफ़ॉल्ट रूप से बंद रहते हैं। प्रत्येक संदेश और सुझाव पढ़ने के लिए समूह खोलें; गंभीरता के अनुसार गिनती दिखाई देती रहती है।

प्लगइन सत्र के दौरान कार्य के चरणों और पूर्वावलोकन दोबारा खोलने के बीच लॉग जमा रहते हैं। रीसेट करने के लिए लॉग साफ़ करें का उपयोग करें; प्लगइन दोबारा लोड करने पर इतिहास नहीं रहता।

## 1.9.12 — अधिक साफ़-सुथरा निदान पूर्वावलोकन

कोई त्रुटि न होने पर पूरा निदान पैनल डिफ़ॉल्ट रूप से बंद रहता है और केवल शीर्षक तथा गंभीरता के अनुसार गिनती दिखाई देती है। त्रुटियाँ होने पर पैनल अपने आप खुलता है। सभी संदेश और सुझाव पढ़ने के लिए पैनल और टैग समूह खोलें। कोई निदान रिकॉर्ड हटाया नहीं जाता। केवल त्रुटि समूह अपने आप खुलते हैं; चेतावनी और जानकारी के समूह एक ही टैग होने पर भी बंद रहते हैं।
