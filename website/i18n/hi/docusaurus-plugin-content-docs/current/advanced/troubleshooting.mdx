# समस्या निवारण

<TLDR>एक अस्थायी नोट पर समान provider, model और settings से समस्या दोहराएँ। Progress log और output path देखें। Authentication, generation, parsing और writing अलग चरण हैं; connection success पूरा workflow सत्यापित नहीं करता।</TLDR>

## अवलोकन

Notemd/Obsidian संस्करण, OS, action, protocol, model और न्यूनतम क्रम लिखें। Cancellation समाप्त होने तक अगला काम न शुरू करें। Output/recovery तब तक बचाएँ जब तक स्रोत स्पष्ट न हो।

## निदान

### Connection test

**Test connection** प्रोफ़ाइल अनुसार केवल list या छोटी generation देखता है। चुने model और output contract के लिए एक वास्तविक छोटा काम करें।

### प्रगति और developer diagnostics

प्रगति status, errors और पथ दिखाती है; API activity pending और समाप्त प्रयास अलग करती है। Debug ज़रूरत पर चालू करें। लंबा diagnostic quota खर्च कर सकता है। Body में नोट, partial answer, endpoint या credentials हो सकते हैं; साझा करने से पहले स्थानीय रूप से साफ़ करें। Redacted profile की metadata भी देखें।

## सामान्य त्रुटियाँ

### कुंजी अमान्य या गायब

401: सही provider/endpoint की कुंजी और अतिरिक्त spaces। 403: खाता/परियोजना अधिकार, मॉडल अनुमति तथा बिलिंग। Retry गलत credentials ठीक नहीं करता।

### नेटवर्क

Obsidian उपकरण से host, port, protocol और route देखें। Ollama/LM Studio सर्वर और मॉडल तैयार हों। `localhost` यही उपकरण है, दूसरा कंप्यूटर नहीं। सही profile चुनें; runtime fallback स्वतः है, कोई UI transport switch नहीं।

### 429 सीमा

Concurrency घटाएँ, request/token quota और वही कुंजी उपयोग करने वाले clients देखें। Retry कुछ अस्थायी विफलताएँ ही सुधारता है।

### मॉडल नहीं मिलता

**Fetch models** या ज्ञात model/deployment ID दें। API version और region देखें; पुराना preset model हट चुका हो सकता है। Azure में deployment और Ark में endpoint ID लग सकता है।

### लिंक या अवधारणाएँ नहीं

असल output, उपयोगी स्रोत, अपेक्षित response format और गैरखाली सक्रिय concept folder देखें। स्वतंत्र extraction पहले केवल title, backlinks बंद देता है। Custom prompt से marker हटे हों तो built-in से तुलना करें।

### Output गायब या अन्य जगह

बताया `_processed.md`, `_<language>.md` या complete path देखें। Translation folder creation विफल होने पर मूल फ़ोल्डर fallback हो सकता है। पुनः चलाने से पहले collision और permissions जाँचें।

### Cancel के बाद फ़ाइलें

पूरी writing बनी रहती और accepted request/write समाप्त हो सकती है। हटाने या पूरा फ़ोल्डर फिर चलाने से पहले प्रति-फ़ाइल results तथा recovery conflicts देखें।

### Diagram या native export

समर्थित type/source चुनें और slide/CircuitikZ environment जाँचें। Preview native verification नहीं। केवल text हो तो source बचाकर संबंधित बाहरी tool में खोलें। [आरेख](../features/diagrams)।

## रिपोर्ट देना

1. कृत्रिम छोटी नोट और अलग फ़ोल्डर से दोहराएँ।
2. संस्करण, action, model, आवश्यक settings, अपेक्षित और वास्तविक परिणाम दें।
3. secrets, private content और अनावश्यक endpoint details हटाकर न्यूनतम artifact/log दें।
4. बताएँ कि एक फ़ाइल और default prompt पर भी होता है या नहीं।
5. [GitHub Issues](https://github.com/Jacobinwwey/obsidian-NotEMD/issues) खोलें।

Screenshot अकेला format या cancellation समस्या कम ही सिद्ध करता है। संभव हो तो source/output जोड़ा या छोटा reproducing क्रम दें।
