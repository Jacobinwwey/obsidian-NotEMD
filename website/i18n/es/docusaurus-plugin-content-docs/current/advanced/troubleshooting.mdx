# Solución de problemas

<TLDR>
Reproduce con una nota desechable, proveedor/modelo exactos y los mismos ajustes. Lee progreso y destino. Distingue autenticación, generación, análisis y escritura; la conexión no valida todo el flujo.
</TLDR>

## Visión general

Registra versiones Notemd/Obsidian, SO, acción, protocolo, modelo y pasos mínimos. Espera a que termine la cancelación antes de otra tarea. Conserva salidas y recuperación hasta entender qué las produjo.

## Diagnósticos

### Conexión

**Probar conexión** prueba lista o conversación corta según perfil. Después ejecuta una tarea real para verificar modelo y formato.

### Progreso y modo desarrollador

El progreso informa estado, errores y rutas. Actividad API distingue solicitudes pendientes y terminadas. Activa diagnóstico API solo cuando haga falta. Las pruebas largas pueden consumir cuota; úsalas deliberadamente.

Los informes pueden incluir notas, respuestas parciales, endpoints o credenciales. Revisa y expurga localmente; incluso perfiles enmascarados requieren control de metadatos.

## Errores frecuentes

### Clave inválida o ausente

`401`: clave del proveedor y endpoint correctos, sin espacios. `403`: permisos, proyecto, acceso al modelo y facturación. Reintentar no repara credenciales.

### Red o conexión

Comprueba host, puerto, protocolo y ruta desde el dispositivo Obsidian. Ollama/LM Studio necesitan servidor y modelo disponibles. `localhost` es este dispositivo. Elige perfil adecuado; los fallbacks de transporte son automáticos, no un selector de usuario.

### Cuota 429

Reduce concurrencia y revisa límites de solicitudes/tokens y otros clientes con la misma clave. Reintentos ayudan en errores transitorios, no garantizan superar cuotas.

### Modelo no encontrado

Usa descubrimiento o un nombre de modelo/despliegue conocido. Verifica versión API y región. Los valores predeterminados históricos pueden desaparecer. Azure necesita nombre de despliegue; Ark puede requerir endpoint ID.

### Sin enlaces ni conceptos

Abre la salida real; verifica fuente útil, formato exigido y carpeta conceptual no vacía habilitada. Extracción independiente solo crea títulos sin backlinks por defecto. Recupera el prompt integrado para comparar si faltan marcadores.

### Salida ausente o inesperada

Consulta destino comunicado: `_processed.md`, `_<language>.md` o complete según tarea. Fallos al crear carpeta de traducción pueden usar el directorio fuente. Revisa colisiones y permisos antes de repetir.

### Archivos tras cancelar

Se conservan escrituras terminadas y las ya aceptadas pueden concluir. Revisa resultados por archivo, recuperación y conflictos antes de borrar o relanzar toda la carpeta.

### Diagrama o exportación nativa fallidos

Los tipos se generan en secuencia. Un fallo no bloquea los demás; cancelar detiene los pendientes y conserva los archivos completados. Reintenta exportaciones desde la vista previa o el historial sin otra solicitud al modelo. Si falla la generación, genera de nuevo ese tipo. Los registros v1/v2 siguen siendo legibles.

El HTML de diagrama contiene un gráfico ampliable; el HTML de resumen estructurado contiene texto, estructura y referencias. HTML/SVG editable nombra un renderizador, no un editor web. Para editar, usa el archivo fuente nativo. Las presentaciones, incluidos PPTX y MP4, mantienen ajustes y dependencias separados. [Manual de diagramas](../features/diagrams).

## Informar un problema

1. Usa nota sintética y carpeta dedicada.
2. Anota versiones, acción, modelo, ajustes y resultado esperado/real.
3. Adjunta mínimos registros y artefactos expurgados; elimina secretos y metadatos innecesarios.
4. Indica si ocurre con un solo archivo y prompts predeterminados.
5. Abre [GitHub Issues](https://github.com/Jacobinwwey/obsidian-NotEMD/issues).

Una captura sola rara vez demuestra un fallo de formato o cancelación. Incluye fuente/salida o secuencia mínima cuando sea posible.
