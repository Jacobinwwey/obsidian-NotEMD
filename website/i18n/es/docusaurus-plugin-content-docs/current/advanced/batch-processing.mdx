# Procesamiento por lotes

<TLDR>
Las tareas de carpeta comparten selección y progreso, pero mantienen escrituras distintas. La concurrencia inicial es uno. Usa una carpeta dedicada, inspecciona alcance y destinos y amplía gradualmente.
</TLDR>

## Visión general

Barra y explorador permiten enlaces, conceptos, títulos, traducción, texto original y reparación Mermaid/fórmulas. No hay investigación genérica de carpetas; títulos puede incluirla opcionalmente.

Un lote no es una transacción de toda la carpeta. Los resultados escritos siguen presentes tras fallo de otro archivo o cancelación.

## Funcionamiento

### Ejecución

1. Seleccionar tarea y carpeta con solo los archivos previstos.
2. Recoger archivos aptos según extensiones, perfiles y exclusiones de salida propias.
3. Utilizar proveedor/modelo de la tarea e informar progreso, fallos y rutas.
4. Revisar informe y archivos al terminar o cancelar.

Enlaces, conceptos, títulos, texto original y reparaciones incluyen subcarpetas por defecto. **Traducción solo incluye hijos directos.** Con modo desarrollador y selección avanzada pueden cambiarse alcance y filtros. Comprueba el perfil real.

### Sobrescritura

| Tarea | Qué revisar antes de repetir |
| ------ | ------------------------------------ |
| Enlaces | Salida separada; sufijo, carpeta y movimiento del original |
| Conceptos | Notas existentes pueden recibir backlinks; duplicados aparte |
| Títulos | Escritura en fuentes aptas y traslado a complete si está libre |
| Traducción | Puede reemplazar la traducción coincidente; `_<language>.md` por defecto |
| Mermaid / fórmulas | Modifica notas seleccionadas; prueba una muestra y respalda |

No hay ajuste universal omitir/anexar/reemplazar. Un destino complete ocupado impide mover, no la generación previa. Los recuentos de generados y movidos son distintos.

### Concurrencia

Mantén `batchConcurrency: 1` hasta validar una muestra. Algunas rutas requieren `enableBatchParallelism`; traducción usa concurrencia directamente. Aumentarla carga proveedor, memoria y servidor sin garantizar mayor rapidez.

Intervalos API y entre grupos reducen ráfagas, pero no garantizan evitar cuotas ni interferencia de otros clientes.

## Ajustes

| Ajuste | Predeterminado | Efecto |
| --------- | --------- | -------- |
| `batchConcurrency` | `1` | Concurrencia solicitada en rutas aplicables |
| `enableBatchParallelism` | `false` | Planificación paralela compatible |
| `batchSize` | `50` | Tamaño de grupos en rutas agrupadas |
| `batchInterDelayMs` | `1000` | Espera entre grupos cuando aplica |
| `apiCallIntervalMs` | `500` | Intervalo de llamadas concurrentes |
| `folderTaskIncludeSubfoldersMode` | `legacy` | Conservar alcance predeterminado de cada tarea |
| `enableStableApiCall` | `false` | Modo estable explícito |

### Modelos y contexto

Se usa la configuración de la tarea individual; revísala para material privado. La recuperación local en lotes de títulos usa una instantánea creada al inicio. Las ediciones posteriores no se mezclan; inicia otro lote para incluirlas.

## Ejemplo

Crea dos notas de títulos en `trial-titles` sin archivos ajenos. Ejecuta **Generación por lotes desde títulos**, revisa contenido, `trial-titles_complete` y recuentos generados/movidos/fallos. Diagnostica cada fallo: repetir toda la carpeta no reanuda exactamente solo lo pendiente.

## Cancelación y recuperación

Cancelar detiene nueva planificación y peticiones compatibles. Llamadas o escrituras aceptadas pueden terminar; la facturación es remota. Espera, revisa resultados y conflictos, y conserva copias de recuperación hasta compararlas.

## Consejos

- Verificar archivos realmente seleccionados por perfiles.
- Reducir concurrencia y consultar cuotas ante 429.
- Separar cancelación, fallo y finalización.
- Mantener muestra intacta y respaldo antes de modificar notas.
