# Penyelesaian masalah

<TLDR>Hasilkan semula masalah pada satu nota ujian dengan penyedia, model dan tetapan tepat. Periksa log kemajuan serta laluan hasil. Bezakan kegagalan pengesahan, penjanaan, penghuraian dan penulisan; ujian sambungan berjaya tidak mengesahkan seluruh aliran.</TLDR>

## Gambaran keseluruhan

Catat versi Notemd/Obsidian, OS, tindakan, protokol penyedia, model dan reproduksi minimum. Jangan mulakan tugas baharu semasa pembatalan belum stabil. Simpan hasil serta fail pemulihan sehingga jelas operasi yang menghasilkannya.

## Cara kerja: diagnostik

### Ujian sambungan

Gunakan **Test connection** dalam tetapan penyedia. Sesetengah pratetap menguji senarai model dahulu dan boleh lulus tanpa permintaan sembang; yang lain membuat sembang kecil. Ikuti dengan tugas sebenar kecil untuk menguji model dan kontrak hasil.

### Kemajuan dan diagnostik pembangun

Paparan kemajuan melaporkan keadaan, ralat serta destinasi. Aktiviti API membantu membezakan permintaan menunggu daripada selesai/gagal. Aktifkan penyahpepijatan ralat API hanya apabila perlu. Diagnostik penyedia pembangun menggunakan permintaan lebih panjang dan boleh menggunakan kuota; gunakan dengan sengaja apabila ujian kecil berjaya tetapi tugas sebenar gagal.

Badan diagnostik boleh mengandungi teks nota, keluaran model separa, titik akhir atau kelayakan. Semak dan samarkan secara setempat sebelum berkongsi. Eksport profil tersamar masih memerlukan semakan metadata.

## Ralat lazim

### Kunci API tidak sah atau tiada

Untuk HTTP 401, semak kunci milik penyedia/titik akhir pilihan dan tiada ruang tidak sengaja. Untuk 403, semak izin akaun, sekatan projek, akses model dan bil. Percubaan berulang tidak membaiki kelayakan tidak sah.

### Ralat rangkaian atau sambungan

Semak hos, port, protokol dan laluan rangkaian daripada peranti Obsidian. Bagi Ollama/LM Studio, pastikan pelayan berjalan dan model tersedia. `localhost` merujuk peranti Obsidian, bukan komputer lain. Gunakan pratetap betul; pemilihan laluan penghantaran gantian automatik, bukan suis pengguna.

### Had kadar (429)

Kurangkan keserentakan, periksa kuota permintaan/token dan penggunaan kunci sama oleh klien lain. Percubaan semula boleh memulihkan sesetengah ralat sementara tetapi tidak menjamin semua kegagalan kuota berjaya.

### Model tidak ditemui

Gunakan **Fetch models** jika ada atau masukkan model/deployment tersedia untuk akaun. Semak versi API dan rantau. Lalai pratetap mungkin lama; kewujudannya tidak membuktikan model huluan masih tersedia. Azure OpenAI memerlukan nama deployment; Ark mungkin memerlukan ID titik akhir.

### Tiada pautan atau konsep dijana

Periksa fail hasil sebenar. Pastikan sumber berguna, model mengembalikan format diperlukan dan folder konsep tidak kosong serta aktif. Ekstraksi kendiri lalai menghasilkan tajuk sahaja, tanpa pautan balik. Pulihkan prompt terbina untuk perbandingan terkawal jika penanda wajib terbuang.

### Hasil hilang atau dalam folder tidak dijangka

Baca destinasi dilaporkan. Tambah pautan biasanya mencipta `_processed.md` di sebelah sumber, terjemahan `_<language>.md` dan kelompok penjanaan tajuk melaporkan folder complete. Kegagalan mencipta folder terjemahan tersuai boleh kembali ke folder sumber. Semak pertembungan serta izin sebelum mengulang.

### Tugas dibatalkan meninggalkan fail

Pembatalan menghentikan kerja seterusnya apabila disokong; penulisan selesai kekal dan tidak diundur secara automatik. Permintaan/penulisan jauh yang sudah diterima boleh selesai. Semak hasil setiap fail dan laluan pemulihan/konflik sebelum memadam atau mengulang folder.

### Rajah atau eksport natif gagal

Jenis dijana mengikut turutan. Kegagalan satu jenis tidak menyekat yang lain; pembatalan menghentikan jenis menunggu dan mengekalkan fail siap. Cuba semula eksport melalui pratonton atau sejarah tanpa permintaan model baharu. Kegagalan penjanaan memerlukan jenis itu dijana semula. Rekod v1/v2 masih boleh dibaca.

HTML rajah mengandungi grafik yang boleh dizum; HTML ringkasan berstruktur mengandungi teks, struktur dan rujukan. HTML/SVG boleh sunting ialah nama pemapar, bukan penyunting web. Gunakan sumber asal untuk menyunting. Eksport persembahan, termasuk PPTX dan MP4, mengekalkan tetapan serta kebergantungan berasingan. [Manual rajah](../features/diagrams).

## Cara melaporkan isu

1. Hasilkan semula dengan nota sintetik kecil dan folder khusus.
2. Catat versi tepat, tindakan, model, tetapan, jangkaan dan hasil sebenar.
3. Lampirkan butiran kemajuan/ralat dibersihkan serta artifak minimum. Buang rahsia, kandungan peribadi dan metadata titik akhir tidak perlu.
4. Nyatakan sama ada masalah berlaku pada satu fail dengan prompt lalai.
5. Buka [GitHub Issues](https://github.com/Jacobinwwey/obsidian-NotEMD/issues).

Tangkapan skrin sahaja jarang membuktikan masalah format atau pembatalan. Sertakan pasangan sumber/hasil atau urutan minimum apabila boleh.
