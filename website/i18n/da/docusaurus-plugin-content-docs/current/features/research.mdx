# Research og websøgning

<TLDR>Research & summarize søger ud fra markering eller notetitel, lader LLM opsummere tilgængelig kontekst og føjer resultatet til aktiv Markdown. Vælg Tavily eller DuckDuckGo eksplicit, og verificér kildereferencer.</TLDR>

## Overblik

Søgeudbyder og opsummeringsmodel er separate. Tavily kræver nøgle; DuckDuckGo er uden nøglekrav, men bruger netværk og kan begrænses. Lokal model gør ikke webresearch offline.

## Sådan virker det

### Søg og opsummér

1. Åbn målet i Markdown-editor, og vælg emne eller brug titel.
2. Kør **Research & summarize**.
3. Tavily leverer uddrag; DuckDuckGo kan hente resultatsider.
4. Tilladt lokal kontekst kan tilføjes fra valgt omfang.
5. Modellen skriver under `Research Summary` med emne og kildetype.
6. Åbn relevante URL’er, og kontrollér påstande. Hentet kontekst beviser ikke ethvert genereret citat.

### Tavily eller DuckDuckGo

| Valg | Forberedelse | Driftsgrænse |
| -------- | ------- | ---------------------- |
| Tavily | Vælg Tavily, og angiv nøgle | Kontokvoter og returnerede uddrag |
| DuckDuckGo | Vælg DuckDuckGo udtrykkeligt | Ingen nøgle; søgebegrænsning og sidetilgængelighed |

En tom eller forkert Tavily-nøgle skifter ikke automatisk. Kontrollér rapporten ved svagt webgrundlag. Aktive lokale uddrag kan stadig understøtte en opsummering; kildemærkningen skelner den fra webunderbygget tekst.

### Research ved titelgenerering

**Enable research in "Generate from title"** tilføjer research, også i batchvarianten, og er fra som standard. Dette er mapperuten; der findes ingen selvstændig generel Research Folder-handling.

## Indstillinger

| Indstilling | Startværdi | Virkning |
| --------- | --------- | -------- |
| `searchProvider` | `tavily` | Søgebackend |
| `tavilyApiKey` | `''` | Tavily-nøgle |
| `tavilyMaxResults` | `5` | Ønsket antal Tavily-resultater |
| `tavilySearchDepth` | `basic` | Tavily-søgedybde |
| `ddgMaxResults` | `5` | Ønsket antal DuckDuckGo-resultater |
| `ddgFetchTimeout` | `15` | Timeout for resultatsider i sekunder |
| `maxResearchContentTokens` | `3000` | Omtrentligt webkontekstbudget |
| `researchProvider` | `DeepSeek` | Opsummeringsudbyder med opgaverouting |
| `researchModel` | `''` | Tomt bruger udbyderens model |
| `researchSummarizeLanguage` | `en` | Output med opgavespecifikke sprog |
| `enableResearchInGenerateContent` | `false` | Tillad research ved titelgenerering |
| `enableLocalKnowledgeRetrieval` | `false` | Aktivér lokal søgning særskilt |
| `enableLocalKnowledgeForResearchSummarize` | `false` | Lokal søgning for denne opgave |

### Kontekst og model

Kontekstgrænser er skøn, ikke præcise udbydertokens. Afkortning kan fjerne evidens. Afgræns spørgsmål og model-/outputbudget. Det lokale indeks er leksikalt uden implicitte embeddings eller fuldstændighedsgaranti.

## Eksempel

Opret `Relativ positionskodning`, kør research, og sammenlign med originale publikationer eller officiel dokumentation. Gem spørgsmål, faktiske URL’er og rettelser for efterprøvning. Eksempelteksten er ikke en allerede udført søgning i din vault.

## Annullering og privatliv

Færdige tilføjelser bevares. Accepterede model-/sideanmodninger kan afsluttes. Søgningen får forespørgslen, websteder får anmodninger og LLM får samlet kontekst inklusive tilladte lokale uddrag. Kontrollér diagnostik før deling.

## Tips

- Skeln webkilde, lokal note og modelslutning.
- Kontrollér citater, datoer og vigtige påstande i originalmaterialet.
- Test søgning og LLM separat med et lille spørgsmål.
- Læs eksisterende opsummeringer for at undgå dobbelte tilføjelser.
