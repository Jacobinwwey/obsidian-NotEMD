# Elaborazione in lotto

<TLDR>
Le attività di cartella condividono selezione e progresso ma hanno scritture diverse. La concorrenza iniziale è uno. Prova una cartella dedicata, verifica ambito e destinazioni e poi amplia.
</TLDR>

## Panoramica

Barra ed esploratore offrono link, concetti, titoli, traduzione, testo originale e correzioni Mermaid/formule. Non esiste ricerca generica di cartella; la generazione dai titoli può includerla.

Un lotto non è una transazione di tutta la cartella. Le scritture riuscite restano dopo errori altrui o annullamento.

## Funzionamento

### Esecuzione

1. Scegli attività e cartella con i soli file voluti.
2. Raccogli file idonei secondo estensioni, profili ed esclusioni specifiche.
3. Usa provider/modello della relativa attività e registra progresso, fallimenti e percorsi.
4. Controlla report e file alla fine o dopo annullamento.

Link, concetti, titoli, testo originale e correzioni includono sottocartelle inizialmente. **La traduzione comprende solo figli diretti.** I profili avanzati possono cambiare l’ambito quando modalità sviluppatore e selezione avanzata sono attive. Verifica il profilo reale.

### Sovrascritture

| Attività | Controllo prima di ripetere |
| ------ | ------------------------------------ |
| Link | Output separati; suffissi, cartelle e movimento dell’originale |
| Concetti | Note esistenti possono ricevere backlink; duplicati separati |
| Titoli | Scrive nelle fonti idonee e sposta in complete se libero |
| Traduzione | Può sostituire traduzione corrispondente; `_<language>.md` iniziale |
| Mermaid / formule | Modifica le note scelte; provare campione e salvare copia |

Non esiste impostazione universale salta/aggiungi/sostituisci. Un complete occupato blocca lo spostamento, non la generazione precedente. I conteggi generati e spostati sono distinti.

### Concorrenza

Mantieni `batchConcurrency: 1` fino a una prova riuscita. Alcuni percorsi richiedono anche `enableBatchParallelism`; traduzione usa direttamente il valore. Aumentare carica provider, memoria e server senza garantire velocità.

Intervalli API e tra gruppi riducono picchi, senza garantire quote o isolamento da altri client.

## Impostazioni

| Impostazione | Valore iniziale | Effetto |
| --------- | --------- | -------- |
| `batchConcurrency` | `1` | Concorrenza richiesta dove applicabile |
| `enableBatchParallelism` | `false` | Pianificazione parallela supportata |
| `batchSize` | `50` | Dimensione gruppi nei percorsi raggruppati |
| `batchInterDelayMs` | `1000` | Attesa tra gruppi dove applicabile |
| `apiCallIntervalMs` | `500` | Intervallo richieste concorrenti |
| `folderTaskIncludeSubfoldersMode` | `legacy` | Preservare ambito iniziale per attività |
| `enableStableApiCall` | `false` | Modalità stabile esplicita |

### Modelli e contesto

Valgono le scelte dell’attività singola. La ricerca locale per titoli in lotto usa un’istantanea creata all’inizio. Le modifiche successive non vengono mescolate; avvia un altro lotto per includerle.

## Esempio

Crea due note di titoli in `trial-titles` senza altri file. Avvia **Generazione batch dai titoli** e controlla contenuto, `trial-titles_complete` e conteggi. Ripetere la cartella non riprende esattamente le sole attività incompiute.

## Annullamento e recupero

Annullare blocca nuova pianificazione e richieste supportate. Operazioni già accettate possono terminare; gli addebiti dipendono dal provider. Attendi e confronta output e conflitti. Conserva le copie di recupero finché non le hai esaminate.

## Consigli

- Controlla i file effettivamente selezionati dai profili.
- Riduci concorrenza e verifica quote con 429.
- Distingui annullamento, fallimento e completamento.
- Conserva campione intatto e backup prima di modificare.
