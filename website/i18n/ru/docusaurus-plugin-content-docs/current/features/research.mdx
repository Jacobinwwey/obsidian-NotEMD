# Исследование и веб-поиск

<TLDR>Research & summarize ищет выделенную тему или заголовок, просит LLM обобщить контекст и добавляет результат в активную Markdown-заметку. Явно выберите Tavily или DuckDuckGo. Проверяйте результаты поиска и сгенерированные ссылки.</TLDR>

## Обзор

Поисковый сервис отделён от модели сводки. Tavily требует ключ; DuckDuckGo — нет, но использует сеть и ограничения запросов. Локальная модель не делает веб-исследование автономным.

## Как это работает

### Поиск и сводка

1. Откройте целевую заметку в редакторе и выделите тему либо используйте заголовок.
2. Выполните **Исследовать и суммировать**.
3. Tavily предоставляет фрагменты, DuckDuckGo может загружать страницы результатов.
4. При разрешённом локальном поиске добавляются фрагменты выбранной области.
5. Модель пишет сводку под `Research Summary` с темой и типом источника.
6. Откройте URL и сопоставьте утверждения. Полученный контекст не доказывает обоснованность каждого предложения.

### Tavily и DuckDuckGo

| Выбор | Настройка | Рабочая граница |
| -------- | ------- | ---------------------- |
| Tavily | Выбрать Tavily и ввести ключ | Квота аккаунта и возвращённые фрагменты |
| DuckDuckGo | Явно выбрать DuckDuckGo | Без ключа; ограничения поиска и доступности страниц |

Пустой/ошибочный ключ Tavily не переключает сервис. При отсутствии полезного веб-контекста смотрите отчёт. Включённые доступные локальные материалы могут поддержать сводку; её метка отличает локальную основу от веб-исследования.

### Исследование при генерации заголовков

**Enable research in "Generate from title"** включает исследование и для пакетной генерации. Изначально выключено. Это поддерживаемый путь работы с папкой; универсального отдельного Research Folder нет.

## Настройки

| Настройка | Начальное значение | Эффект |
| --------- | --------- | -------- |
| `searchProvider` | `tavily` | Выбор поискового сервиса |
| `tavilyApiKey` | `''` | Ключ для Tavily |
| `tavilyMaxResults` | `5` | Запрошенное число результатов Tavily |
| `tavilySearchDepth` | `basic` | Глубина поиска Tavily |
| `ddgMaxResults` | `5` | Запрошенное число результатов DuckDuckGo |
| `ddgFetchTimeout` | `15` | Таймаут получения страницы, секунды |
| `maxResearchContentTokens` | `3000` | Приблизительный бюджет веб-контекста |
| `researchProvider` | `DeepSeek` | Модель сводки при индивидуальных профилях |
| `researchModel` | `''` | Пустое поле использует модель провайдера |
| `researchSummarizeLanguage` | `en` | Язык при индивидуальной настройке |
| `enableResearchInGenerateContent` | `false` | Исследование в генерации по заголовкам |
| `enableLocalKnowledgeRetrieval` | `false` | Отдельное включение локального поиска |
| `enableLocalKnowledgeForResearchSummarize` | `false` | Локальный поиск для этой задачи |

### Контекст и модель

Ограничения приблизительны, не равны точной токенизации провайдера. Усечение может убрать доказательства. Сужайте вопрос и выбирайте модель/бюджет по материалу. Локальный индекс лексический, не embedding-поиск и не гарантия полной выборки.

## Пример

Создайте заметку `Относительное позиционное кодирование`, исследуйте тему и сверьте объяснение с исходными статьями или официальными документами. Храните вопрос, реальные URL и исправления для проверки. Пример в руководстве не является результатом исполнения в вашем хранилище.

## Отмена и конфиденциальность

Готовые добавления сохраняются, принятый запрос провайдера или страницы может завершиться. Поиск получает тему, сайты — запросы, модель — собранный контекст, включая разрешённые локальные фрагменты. Проверяйте диагностические отчёты перед передачей.

## Практика

- Отличайте веб-источник, локальную заметку и вывод модели.
- Проверяйте цитаты, даты и значимые утверждения по оригиналам.
- Маленьким запросом диагностируйте поиск и LLM отдельно.
- Осматривайте прежние сводки, чтобы не дублировать добавления.
