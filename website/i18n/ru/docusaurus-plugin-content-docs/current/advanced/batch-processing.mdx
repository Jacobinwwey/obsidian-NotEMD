# Пакетная обработка

<TLDR>Папочные действия используют общие выбор и прогресс, но различаются выводом и перезаписью. Параллелизм изначально 1. На отдельной тестовой папке проверьте область и назначения, затем расширяйте пакет.</TLDR>

## Обзор

Панель и меню проводника предлагают ссылки, понятия, генерацию по заголовкам, перевод, оригинальные отрывки и исправление Mermaid/формул. Универсального исследования папки нет: оно отдельно включается в генерации. Пакет не является общей транзакцией; успешные записи переживают ошибки других файлов и отмену.

## Как это работает

### Модель исполнения

1. Выберите задачу и папку с нужными файлами.
2. Применяются расширения, профили выбора и исключения выходов конкретной задачи.
3. Используется её провайдер/модель, сообщаются прогресс, ошибки и пути.
4. После завершения/отмены проверьте отчёт и файлы перед повтором.

Ссылки, понятия, заголовки, оригинальные отрывки, Mermaid и формулы по умолчанию включают подпапки. **Перевод папки берёт только прямых детей.** При включённых режиме разработчика и расширенном выборе профили могут менять область/фильтры. Проверяйте реальные совпадения.

### Перезапись

| Задача | Что проверить до повтора |
| ------ | ------------------------------------ |
| Ссылки | Отдельные результаты по умолчанию; суффикс, папку и перемещение оригинала |
| Понятия | Обратные ссылки в существующих файлах при включении; дубликаты проверяются отдельно |
| Генерация по заголовкам | Запись в подходящие источники и перенос в complete при свободном назначении |
| Перевод | Совпадающий результат может заменяться; обычно `_<language>.md` |
| Mermaid / формулы | Изменяют выбранные заметки; нужна проверка образца и backup |

Общего пропустить/добавить/заменить нет. Занятое complete-назначение блокирует перенос, а не предшествующую генерацию. Счётчики созданного содержимого и перемещений различаются.

### Параллелизм

Держите `batchConcurrency: 1` до успешной выборки. Некоторые пути требуют также `enableBatchParallelism`; перевод использует число напрямую. Параллельность увеличивает нагрузку на провайдера, память и сервер, не гарантируя ускорения. Интервалы запросов/групп не устраняют все квоты или нагрузку других клиентов.

## Настройки

| Настройка | Начальное значение | Эффект |
| --------- | --------- | -------- |
| `batchConcurrency` | `1` | Запрошенный параллелизм применимых задач |
| `enableBatchParallelism` | `false` | Параллельное планирование поддерживаемых путей |
| `batchSize` | `50` | Размер группы при групповом планировании |
| `batchInterDelayMs` | `1000` | Пауза между группами |
| `apiCallIntervalMs` | `500` | Интервал параллельных API-запросов |
| `folderTaskIncludeSubfoldersMode` | `legacy` | Сохранить исходную область подпапок каждой задачи |
| `enableStableApiCall` | `false` | Явный стабильный режим |

### Модели в пакетах

Используются те же индивидуальные маршруты, что у однофайловой задачи. Проверьте их для частных материалов. Локальный поиск пакетных заголовков использует один снимок начала запуска; редактирование не смешивается с последующими результатами. Чтобы включить новые правки, запустите новый пакет.

## Пример

Создайте `trial-titles` с двумя заголовками, выполните **Пакетная генерация по заголовкам**, проверьте содержимое, соседнюю `trial-titles_complete` и счётчики генерации/переноса/ошибок. Диагностируйте конкретный сбой. Повтор исходной папки не означает точное автоматическое продолжение незавершённых файлов.

## Отмена и восстановление

Отмена прекращает новое планирование и поддерживаемые запросы. Уже принятые внешние вызовы/записи могут закончиться; оплатой управляет провайдер. Дождитесь окончания, проверьте готовые файлы и конфликты, сохраняйте восстановленные копии до сравнения.

## Практика

- Проверяйте фактическую выборку профиля.
- При 429 уменьшите параллелизм и проверьте квоты.
- Различайте отмену, ошибку и завершение.
- Сохраняйте нетронутый образец и backup до изменения файлов.
