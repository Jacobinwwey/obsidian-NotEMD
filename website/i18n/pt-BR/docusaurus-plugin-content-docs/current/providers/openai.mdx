# Fornecedor OpenAI

<TLDR>
O perfil usa a implementação partilhada OpenAI-compatible Chat Completions. Definir chave e modelo que aceite o protocolo. O valor inicial não garante acesso atual nem é recomendação universal.
</TLDR>

## Preparação

Selecionar **OpenAI**, introduzir chave e conservar `https://api.openai.com/v1` para o serviço oficial. Aparecer na lista não torna compatível um modelo disponível apenas noutra API.

Para gateways usar o perfil correspondente e os seus cabeçalhos. Azure usa **Azure OpenAI** com deployment e versão API.

## Endpoint e autenticação

| Campo | Valor inicial |
| ------- | -------------- |
| Transporte | `openai-compatible` |
| Chave API | Obrigatória |
| URL base | `https://api.openai.com/v1` |
| Modelo | `gpt-4o` |
| Temperatura | `0.5` |
| Teste de conexão | `models-then-chat` |

A execução normaliza formas conhecidas de URL antes de criar rotas. Partir do endereço inicial e verificar caminho resolvido, sem acrescentar segmentos por tentativa.

## Modelos

**Fetch models** consulta o endpoint. **Testar conexão** pode aprovar apenas pela lista. Testar depois uma nota no fornecedor/modelo exatos.

Reasoning, thinking, amostragem e limites seguem regras do perfil/modelo. Um modelo listado não aceita necessariamente todos os parâmetros.

## Problemas

- `401`/`403`: chave, projeto, direitos do modelo e conta.
- `404`: endereço, ID e API compatível.
- Lista válida mas tarefa falha: analisar erro chat e ajustes.
- Resposta longa truncada: verificar orçamento, origem e erro; teste curto não cobre tudo.

## Quando utilizar

Para modelos OpenAI diretos compatíveis com Chat Completions. Avaliar as próprias notas; preços e disponibilidade podem mudar sem nova versão do Notemd.
