# Діаграми

<TLDR>
Виберіть **тип діаграми**, яка вам потрібна, а потім — її **редаговуваний формат вихідних даних**. Перегляньте готовий результат у Obsidian, включаючи дошку Drawnix та вбудовані візуалізації Mermaid, а також експортуйте кожен елемент як SVG, PNG чи PDF.
</TLDR>

## Зрозуміти три варіанти вибору

| Варіант | Що він контролює | Приклади |
|---|---|---|
| Тип діаграми | Що означає діаграма | Діаграма потоків, послідовна діаграма, схема електронних ланцюгів, графік даних |
| Формат вихідних даних | Редаговуваний або повторно використовуваний файл, який створює Notemd | Mermaid, JSON Canvas, Draw.io, Drawnix, CircuitikZ |
| Формат експорту | Зображення чи документ, які використовуються для обміну | SVG, PNG, PDF |

Draw.io та Drawnix є **форматами вихідних даних**, а не типами діаграм. CircuitikZ — це формат вихідних даних, призначений для схем електронних ланцюгів. Одну й ту саму попередню версію можна експортувати у кілька візуальних форматів, тому вибір CircuitikZ не обмежує вас лише SVG.

## Виберіть формат вихідних даних

| Формат | Для чого підходить | Файл вихідних даних |
|---|---|---|
| Mermaid | Діаграми, які зберігаються безпосередньо у Markdown | Блок коду Mermaid |
| JSON Canvas | Робота з нативними інструментами Obsidian canvas | `.canvas` |
| Draw.io | Редагування пізніше у diagrams.net або сумісних програмах | `.drawio` |
| Drawnix | Редагування вручну або у стилі дошки для записів | `.drawnix` |
| CircuitikZ | Структуровані електричні та транзисторні схеми | `.tex` |

Якщо вам не потрібен певний редактор, залиште поле **Preferred source format** у значенні **Auto**. Notemd сам обере сумісний формат для обраного типу діаграми.

## Створення та експорт діаграми

1. Відкрийте нотатку або виберіть текст, який потрібно візуалізувати.
2. У бічній панелі Notemd або палітрі команд оберіть опцію **Створити діаграму**.
3. Виберіть тип **діаграми**, або залиште його на значенні **Автоматичне виявлення**.
4. Виберіть **формат вихідних даних**, або залиште його на значенні **Авто**. Оберіть **Drawnix**, якщо потрібна карта знань із редаговуваними вузлами та вбудованими візуалізаціями Mermaid.
5. Перегляньте попередній перегляд. Результат у кількох панелях зберігає дошку Drawnix та кожну панель Mermaid у початковому порядку всередині одного вертикально прокручуваного вікна перегляду; панелі Mermaid використовують свою розмірність після обробки, а не обрізаються.
6. Для кожної візуалізації оберіть дію **Експортувати SVG**, **Експортувати PNG** чи **Експортувати PDF**, або використайте експорт зображення на верхньому рівні для всіх панелей. Для кількох панелей виберіть джерельну папку або власну папку відносно Vault; Notemd створює по одному файлу на кожну панель та продовжує роботу навіть у разі окремих помилок.
7. Використайте опцію **Зберегти вихідний файл**, якщо вам також потрібен редаговуваний артефакт.

Меню «Експорт» пропонує дії **Експортувати SVG**, **Експортувати PNG** та **Експортувати PDF** для поточного візуального перегляду. Кожен заголовок панелі містить такі ж дії для окремої візуалізації Mermaid чи Drawnix, тому не обов’язково експортувати великий перегляд як одне непрозоре зображення.

У перегляді оберіть **Історія**, щоб відкрити вікно історії Vault, не приховуючи діаграму. Ви можете шукати та фільтрувати завершені діаграми, знову відкрити перегляд або відкрити збережені артефакти. Історія діаграм також доступна безпосередньо з палітри команд та бічної панелі Notemd, навіть коли жодна нотатка не активна.

SVG та PDF створюються на основі векторної геометрії; PDF використовує ту саму структуру SVG та параметри тексту, замість того щоб растеризувати всю діаграму. Параметр PPI для експорту зображення у налаштуваннях Notemd контролює лише растеризацію PNG (72–600 PPI, за замовчуванням 300).

## Читабельні попередні перегляди щільних діаграм

Редаговані HTML/SVG lane-grid діаграми спочатку вимірюють і переносять підсумок, а вже потім розміщують заголовок і заголовок lane. Заголовок переміщується під захищену область підсумку, а комірки малюються до з’єднувачів і підписів ребер. Ребра між lane використовують ортогональні маршрути сіткою з урахуванням колізій і резервують місце для підписів lane та зайнятих комірок, тому довгі описи не закривають текст і не потребують горизонтального панорамування.

Квадрантні діаграми Mermaid проходять нормалізацію для відповідного family. Для `quadrantChart` пропускаються лише виправлення лапок і форм, призначені для flowchart; навмисні квадратні дужки в заголовках, осях і назвах квадрантів зберігаються. Відкривальна дужка, скопійована provider, видаляється лише тоді, коли це невідповідний останній символ підпису точки.

Репозиторій містить набір навчання та доказів із реального Vault для кожного виконуваного типу діаграми. Двомовні вхідні нотатки, результати SVG/PNG і машиночитний manifest стану доступні в [`docs/diagram-examples/`](https://github.com/Jacobinwwey/obsidian-NotEMD/tree/main/docs/diagram-examples). Записи `passed` означають запуск через завантажений plugin bundle, а не статичний screenshot fixture.

## Попередні перегляди Drawnix із вбудованими елементами Mermaid

Коли артефакт Drawnix містить візуалізації у форматі Mermaid, Notemd очищує генероване SVG та зберігає вихідний код Mermaid разом із ним у метаданих `.drawnix`. Таким чином попередній перегляд може відображати зображення Mermaid всередині карти знань Drawnix без необхідності використання середовища виконання Drawnix чи Plait. Типовий шлях є самодостатнім та не створює окремого каталогу `.assets`. Увімкніть опцію **Also export complete Mermaid visuals**, якщо вам потрібні вихідний код Mermaid, файл SVG та супровідні маніфести для передачі чи зовнішньої редагування. Існуючі артефакти з каталогом `.assets` залишаються підтримуваними, а відсутнє SVG у форматі Mermaid можна перебудувати на основі текстового коду, що зберігається в метаданах.

Елементи зображень, які вже були оброблені, також отримують перегляд SVG із підтримкою даних, коли це можливо; тому видалення старого супровідного каталогу не призводить до зникнення збереженого перегляду Drawnix. Під час завантаження перегляду спочатку використовуються вбудовані дані, потім старі супровідні файли, а якщо це неможливо — метод перебудови на основі текстового коду.

Перегляд навмисно реалізований як єдиний поверх для прокручування: спочатку відображається основна площадка Drawnix, а потім кожен вбудований панель Mermaid у порядку їх появи. Закриття та повторне відкриття збереженої запису історії відновлює той самий список панелей, розміри та дії експорту.

Пояснення взаємозв’язків у Drawnix представлені як повноцінні візуальні елементи. Механізм відображення прокладає пунктирні стрілки навколо прямокутників вузлів та виділяє захищену зону у вигляді заголовка з назвою чи коротким описом. Довгі описи та позначки взаємозв’язків розгортаються по окремих рядках, «ліс» елементів розташовується нижче висоти цього заголовка, а після шару вузлів наноситься непрозора рамка з позначкою. Заголовок відображається останнім із непрозорим фоном, тому зовнішні маршрути не можуть закрити текст на кшталт `以 Notemd 插件为对象的知识地图，覆盖系统架构、LLM 调用管道、图表渲染平台、模块地图、CLI 边界现实、关键设计决策与验证。` чи пояснення взаємозв’язку на кшталт `RendererRegistry feeds Vault files, preview modal, and export`. Вбудована стрілка у форматі `.drawnix` використовує параметри `shape`, `texts[]`, маркери та поля для ліній, сумісні з Plait, при цьому зберігаючи старі метадані для користувачів старішої версії. Якщо запитаний мапа Drawnix не може знайти маршрут чи положення позначки без зіткнень, процес генерації завершується з помилкою формату, замість того щоб тихо зберегти альтернативний варіант у форматі Mermaid у файлі `.drawnix`.

## Схеми електричних колій

Для обробки запитів на створення схем використовуйте опцію **Схема електричного кола** з вихідним файлом у форматі **CircuitikZ**. Notemd спочатку генерує структурований опис схеми, а потім записує вихідний код у форматі CircuitikZ. Цей підхід є надійнішим, ніж просити модель створювати LaTeX без жодних обмежень.

Підтримка формату CircuitikZ навмисно залишається обмеженою. Найкраще працюють ампліфікатори типу NMOS із загальнодоступним кодом та підтримувані блоки CMOS. Перед використанням генерованої схеми у технічних чи видавничих роботах завжди перевіряйте її попередній перегляд та вихідний код.

Попередній перегляд у форматі SVG — це інструмент для перевірки, створений Notemd. Він не є доказом того, що локальна установка LaTeX чи TikZJax успішно скомпілювала файл `.tex`.

**Необов’язкова компіляція безpoсередньо в програмі.** Для попереднього перегляду всередині додатка, експорту у форматах SVG, PNG та PDF не потрібен LaTeX. На настільних ПК ви можете відкрити **Середовище компіляції CircuitikZ** через налаштування схеми або палітру команд, якщо потрібні діагностика процесу компіляції чи PDF у форматі LaTeX. Notemd може використовувати системні інструменти `tectonic` або `pdflatex`, власний виконуваний файл чи встановити керовану версію середовища Tectonic після того, як ви явно оберете опцію **Встановити**. Панель середовища відображає прогрес та помилки безпосередньо у інтерфейсі та дозволяє пізніше видалити кероване середовище.

## Усунення проблем

### Результат — неправильний тип діаграми

Виберіть тип діаграми вручну замість використання опції «Автодетекція». Для схеми оберіть **Circuit diagram** та скористайтеся командою **Generate diagram**, а не застарілою командою **Summarise as Mermaid diagram**.

### Формат вихідних даних є непридатним

Поверніть формат вихідних даних у режим **Auto**, або оберіть формат, призначений для цього типу діаграми. CircuitikZ призначений для схем електричних мереж; Draw.io та Drawnix — для підтримуваних структурованих діаграм.

### Меню експорту відсутнє

Для форматів SVG, PNG та PDF необхідна візуальна попередня перегляд. Якщо є лише вихідний текст, збережіть файл та відкрийте його у відповідному зовнішньому інструменті.

### Файл CircuitikZ не компілюється ззовні

Відкрийте **нативне середовище компіляції CircuitikZ** та запустіть перевірку стану середовища. Виправте проблеми з керованим часом виконання або переконайтеся, що ваш власний/системний компілятор може отримати пакет `circuitikz`. У файлі плагіна Notemd не містить повноцінного розподілу TeX.
