# Діаграми

<TLDR>
Виберіть кілька типів діаграм за один запуск і кілька форматів для кожного типу окремо. Зняття позначки зберігає формати типу; без вибраних типів вміст аналізується автоматично.
</TLDR>


Кожен попередній перегляд має незалежне масштабування, переміщення, уміщення й початковий розмір. Ctrl/Command + коліщатко змінює масштаб; звичайне коліщатко прокручує. Великі PNG зберігають вибрані 72–600 PPI (типово 300). SVG — векторний формат; PPI застосовується лише до растрового експорту.


**Створювати зображення, сумісні з Obsidian** — Увімкнено за замовчуванням. Перевіряє декодування PNG в Obsidian; у разі помилки зберігає оригінал і додає копію з нижчим PPI. Обидві назви файлів містять PPI. Після вимкнення експортує лише запитаний оригінал. (`note_drawnix_300ppi.png`, `note_drawnix_obsidian_87ppi.png`).

## Три окремі рішення

| Вибір | Що визначає | Приклади |
| --- | --- | --- |
| Тип діаграми | Зміст діаграми | Блок-схема, послідовність, електрична схема, графік даних |
| Формат джерела | Редагований або повторно використовуваний файл Notemd | Mermaid, JSON Canvas, Draw.io, Drawnix, CircuitikZ |
| Формат експорту | Зображення чи документ для поширення | SVG, PNG, PDF |

HTML діаграми містить масштабовану графіку; HTML структурованого підсумку — текст, структуру та посилання на джерела. Редагований HTML/SVG — назва рендерера, а не вебредактора. Для редагування використовуйте рідний вихідний файл. Експорт презентацій, зокрема PPTX і MP4, має окремі налаштування та залежності.

## Вибір джерела

| Формат | Для чого | Файл джерела |
| --- | --- | --- |
| Mermaid | Діаграми безпосередньо в Markdown | Блок коду Mermaid |
| JSON Canvas | Нативні canvas-процеси Obsidian | `.canvas` |
| Draw.io | Подальше редагування в diagrams.net чи сумісних засобах | `.drawio` |
| Drawnix | Редагування дошки або мальованих схем | `.drawnix` |
| CircuitikZ | Структуровані електричні й транзисторні схеми | `.tex` |

Підтримувані формати показано першими; несумісні залишаються видимими, але вимкненими. Наявні неактивні запити можна видалити. Формати належать своєму типу. Якщо жоден не придатний, система пробує типовий вихідний формат поточного рендерера та повідомляє про недоступні запити.

## Створення й експорт

1. Відкрийте підтримувану нотатку-джерело. Для уривка створіть окрему нотатку; виділення не звужує файлової дії.
2. Виберіть кілька типів діаграм за один запуск і кілька форматів для кожного типу окремо. Зняття позначки зберігає формати типу; без вибраних типів вміст аналізується автоматично.
3. Прапорець додає тип. Натисніть назву, щоб вибрати його й налаштувати формати. Наведення вказівника або фокус клавіатури змінює перегляд без збереження налаштувань. Escape закриває меню й повертає фокус.
4. Запустіть **Створити діаграму** з панелі чи палітри.
5. Вибрані файли автоматично експортуються поряд із вихідною нотаткою або безпосередньо до заданої папки. Назва містить тип, наприклад `topic_drawnix.pdf` та `topic_flowchart.svg`. За збігу додаються `-2`, `-3` тощо без перезапису файлів.
6. Перевірте спільний вертикально прокручуваний перегляд: Drawnix, потім усі Mermaid-панелі в порядку джерела й повній висоті.
7. Використовуйте **Експортувати SVG**, **Експортувати PNG** або **Export PDF** окремої панелі чи верхній експорт зображень для всіх. Для кількох панелей виберіть папку джерела або власну відносно сховища. Записується один файл із передбачуваною назвою на панель; окрема помилка не зупиняє решти. **Зберегти файл джерела** збереже редагований артефакт.

Задайте спільну папку проміжних файлів відносно Vault або залиште поле порожнім для `notemd_assert/` поряд із кожним джерелом. Тут зберігаються записи відновлення, кеш рендерингу й додаткові вкладення. Зберігайте файли, на які ще є посилання; зміна діє лише для нових запусків.

Типи генеруються послідовно. Помилка одного не блокує інших; скасування зупиняє типи в очікуванні та зберігає готові файли. Повторіть експорт із перегляду чи історії без нового запиту до моделі. Помилка генерації потребує повторного створення цього типу. Записи v1/v2 залишаються читабельними.

Меню експорту й заголовок кожної панелі мають однакові SVG/PNG/PDF дії. Великий перегляд не потрібно зводити до одного непрозорого зображення.

**History** відкриває шухляду історії сховища, не приховуючи діаграми. Шукайте, фільтруйте, відкривайте перегляди чи збережені артефакти. Історія доступна також із палітри й панелі без активної нотатки.

SVG і PDF утворюються з векторної геометрії. PDF використовує розташування SVG й метрики тексту, а не растеризацію всього перегляду. PPI впливає лише на PNG: 72–600, типово 300.

## Читабельні щільні діаграми

Редаговані HTML/SVG діаграми зі смугами вимірюють і переносять підсумок перед розміщенням назви й заголовка. Комірки малюються перед з’єднаннями та підписами. Ортогональні міжсмугові маршрути враховують зайняті комірки й написи, щоб довгі описи не закривали текст і не примушували до зайвого горизонтального прокручування.

Mermaid `quadrantChart` має окрему нормалізацію сімейства. Виправлення лапок і форм лише для flowchart пропускаються. Скопійована моделлю відкрита дужка вилучається тільки як непарний останній символ підпису точки; навмисні дужки назв, осей і квадрантів лишаються.

[docs/diagram-examples/](https://github.com/Jacobinwwey/obsidian-NotEMD/tree/main/docs/diagram-examples) містить двомовні входи, SVG/PNG та машинний manifest із реального сховища для кожного виконуваного типу. `passed` стосується записаного запуску й bundle, не нового проходження всіх типів у кожному пізнішому випуску.

Каталог має 33 виконувані записи, UI — 21 локалізацію, сайт — 34 мовні маршрути. Це різні поверхні. П’ять точних еталонних граматик залишаються поза вибором до незалежного підтвердження їхніх контрактів розташування.

## Drawnix із вбудованим Mermaid

Notemd очищує SVG й зберігає Mermaid-джерело в метаданих `.drawnix`. Перегляду не потрібні runtime Drawnix чи Plait. Типовий шлях самодостатній без окремої `.assets`. Увімкніть **Also export complete Mermaid visuals**, якщо для передавання чи зовнішнього редагування потрібні Mermaid-джерело, SVG і manifest. Старі `.assets` підтримуються; відсутній SVG можна відновити з джерела в метаданих.

Розпізнані вбудовані зображення за можливості отримують SVG-перегляд із даними всередині. Завантаження спершу використовує дані, потім старі супровідні файли, потім доступне відтворення з тексту. Зберігайте файли, на які ще є посилання; новий самодостатній експорт не доводить непотрібності старої спільної папки.

Єдина прокручувана поверхня спочатку показує Drawnix, а потім Mermaid у порядку джерела. Повторне відкриття історії відновлює той самий список панелей, розміри й дії експорту.

Drawnix зберігає всі явно задані спрямовані зв’язки без загального обмеження або ліміту на вузол. Видаляються лише однакові твердження; різні предикати та зворотні напрямки залишаються. Зовнішні маршрути з перекриттям отримують окремі доріжки, розділені маршрути використовують їх повторно. Для підписів виділяються рядки за розміром тексту, а полотно розширюється за потреби. Стрілки без підпису, загальні асоціації та повторення ієрархії залишаються в метаданих із причиною. Текст у рамках зв’язків видно в PDF, зокрема зі старого кешу SVG. Міжгілкові стрілки статичні й можуть від’єднатися після перестановки вузлів у Drawnix.

## Межі нативного експорту

Джерело й візуальний експорт — окремі результати. До поширення перевірте показовий файл у цільовій програмі. PowerPoint зберігає підтримувану редаговану структуру таблиць, включно з виправленими роздільниками під об’єднаними комірками. Mermaid/SVG можуть бути зображеннями замість нативних фігур. Перегляд або оцінка скриншота цілої сторінки не замінює перевірки програми.

## Електричні схеми

Виберіть **Circuit diagram** та **CircuitikZ source file**. Спочатку Notemd генерує структурований опис схеми, потім CircuitikZ, замість необмеженого LaTeX від моделі.

Підтримка свідомо обмежена: NMOS-підсилювачі зі спільним витоком і підтримувані CMOS-блоки. До технічного чи видавничого використання перевірте джерело й перегляд. SVG — супровід для контролю, не доказ успішної компіляції `.tex` локальним LaTeX/TikZJax.

**Необов’язкова нативна компіляція.** Перегляд та його SVG/PNG/PDF експорти не потребують LaTeX. На настільній системі відкрийте **CircuitikZ native compile environment** для діагностики чи нативного LaTeX PDF. Можна використати системний `tectonic`/`pdflatex`, власний виконуваний файл або зафіксований керований Tectonic після явного **Install**. Панель показує прогрес/помилки й дозволяє видалити runtime пізніше.

## Проблеми

### Неправильний тип

Виберіть тип явно. Для схеми використовуйте **Circuit diagram** і **Створити діаграму**, не стару **Підсумувати як діаграму Mermaid**.

### Невідповідне джерело

Підтримувані формати показано першими; несумісні залишаються видимими, але вимкненими. Наявні неактивні запити можна видалити. Формати належать своєму типу. Якщо жоден не придатний, система пробує типовий вихідний формат поточного рендерера та повідомляє про недоступні запити.

### Немає меню експорту

SVG/PNG/PDF потребують візуального перегляду. Якщо є лише текст, збережіть джерело й відкрийте відповідним зовнішнім засобом.

### CircuitikZ не компілюється зовні

Відкрийте **CircuitikZ native compile environment** і перевірте середовище. Відновіть керований runtime або перевірте, що власний/системний компілятор отримує пакет `circuitikz`. Розширення не містить повної дистрибуції TeX.

## 1.9.10 — Безпечний перегляд і локальні налаштування сховища

Імпортовані SVG очищуються від активного вмісту та зовнішніх ресурсів зі збереженням китайських підписів і стилів панелей. Локальні провайдери ізольовано за сховищами; явно імпортуйте старий список у налаштуваннях, зберігаючи початковий список і наявні конфігурації. Презентації використовують loopback-сервер із керуванням спільними споживачами. Помилки збереження обраного й копіювання відображаються; видалення відповідає налаштуванням сховища. Сумісність PNG увімкнена: оригінал зберігається, перевірена копія з меншим PPI додається лише за потреби. Drawnix не має фіксованої межі зв’язків; презентації зберігають окремі налаштування. Встановіть файли однієї версії, перезавантажте та перевірте одну нотатку перед пакетною обробкою.

## 1.9.11 — Зрозуміліші діаграми та надійний експорт PDF

Drawnix розміщує тісно пов’язані гілки ближче та зменшує накладання й перетини з’єднувальних ліній, зберігаючи всі вузли та явні зв’язки. Стрілки між гілками залишаються статичними після перестановки.

Експорт PDF обробляє складні селектори SVG та успадковані стилі після очищення. Відсутні viewBox відновлюються; завеликі сторінки масштабуються пропорційно зі збереженням векторної графіки.

Діагностику згруповано за мітками та типово згорнуто. Розгорніть групу, щоб прочитати всі повідомлення й поради; лічильники за рівнем серйозності залишаються видимими.

Журнал накопичується між етапами завдання та повторними відкриттями перегляду протягом сеансу плагіна. Натисніть Очистити журнал для скидання; перезавантаження плагіна не зберігає історію.

## 1.9.12 — Компактніший перегляд діагностики

Якщо помилок немає, всю панель діагностики типово згорнуто: видно лише заголовок і лічильники за рівнем серйозності. За наявності помилок панель відкривається автоматично. Розгорніть панель і групи міток, щоб прочитати всі повідомлення й поради. Діагностичні записи не видаляються. Автоматично відкриваються лише групи помилок; попередження та інформація залишаються згорнутими, навіть за спільної мітки.
