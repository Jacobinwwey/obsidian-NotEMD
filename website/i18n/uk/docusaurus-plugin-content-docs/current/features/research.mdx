# Дослідження та вебпошук

<TLDR>Research & summarize шукає за виділенням чи назвою, просить LLM підсумувати доступний контекст і додає результат до активного Markdown. Явно виберіть Tavily або DuckDuckGo та перевірте посилання на джерела.</TLDR>

## Огляд

Пошуковий сервіс і модель підсумку вибираються окремо. Tavily потребує ключа; DuckDuckGo — ні, але потребує мережі й може обмежувати трафік. Локальна модель не робить вебдослідження автономним.

## Як це працює

### Пошук і підсумок

1. Відкрийте ціль у редакторі Markdown та виділіть тему або використайте назву.
2. Запустіть **Дослідити й підсумувати**.
3. Tavily надає уривки; DuckDuckGo може завантажувати сторінки результатів.
4. Можна додати дозволений локальний контекст із вибраної області.
5. Модель записує `Research Summary` із темою та типом джерела.
6. Відкрийте адреси й перевірте твердження. Знайдений контекст не доводить кожної згенерованої цитати.

### Tavily чи DuckDuckGo

| Вибір | Підготовка | Операційна межа |
| -------- | ------- | ---------------------- |
| Tavily | Виберіть Tavily і введіть ключ | Квоти облікового запису й повернені уривки |
| DuckDuckGo | Явно виберіть DuckDuckGo | Без ключа; ліміти пошуку та доступність сторінок |

Порожній або неправильний ключ Tavily не перемикає сервіс. Якщо вебконтексту мало, читайте звіт. Дозволені локальні уривки можуть підтримати підсумок; мітка джерела відрізняє його від вебобґрунтованого.

### Дослідження під час генерації за назвами

**Enable research in "Generate from title"** додає дослідження й до пакетів, типово вимкнене. Це підтримуваний шлях для папки; окремої загальної дії Research Folder немає.

## Параметри

| Параметр | Початкове значення | Вплив |
| --------- | --------- | -------- |
| `searchProvider` | `tavily` | Пошуковий сервіс |
| `tavilyApiKey` | `''` | Ключ Tavily |
| `tavilyMaxResults` | `5` | Бажана кількість результатів Tavily |
| `tavilySearchDepth` | `basic` | Глибина пошуку Tavily |
| `ddgMaxResults` | `5` | Бажана кількість результатів DuckDuckGo |
| `ddgFetchTimeout` | `15` | Тайм-аут сторінок у секундах |
| `maxResearchContentTokens` | `3000` | Приблизний бюджет вебконтексту |
| `researchProvider` | `DeepSeek` | Провайдер підсумку за маршрутизації завдань |
| `researchModel` | `''` | Порожнє поле бере модель провайдера |
| `researchSummarizeLanguage` | `en` | Мова результату завдання |
| `enableResearchInGenerateContent` | `false` | Дозволяє дослідження за назвами |
| `enableLocalKnowledgeRetrieval` | `false` | Окремо вмикає локальний пошук |
| `enableLocalKnowledgeForResearchSummarize` | `false` | Локальний контекст для цього завдання |

### Контекст і модель

Бюджети приблизні, не точні токени провайдера. Обрізання може вилучити докази. Звузьте запит, змініть модель/бюджет. Локальний індекс лексичний, без прихованих embeddings і гарантії повного пошуку.

## Приклад

Створіть `Відносне позиційне кодування`, дослідіть тему й зіставте з оригінальними публікаціями чи офіційною документацією. Збережіть запит, справжні URL і виправлення. Приклад не означає вже виконаного пошуку у вашому сховищі.

## Скасування та приватність

Завершені додавання залишаються. Прийнятий запит моделі/сторінки може завершитися. Пошуковий сервіс отримує питання, сайти — звернення, LLM — увесь контекст із дозволеними локальними уривками. Перед поширенням перевірте діагностику.

## Рекомендації

- Відрізняйте вебджерело, локальну нотатку й висновок моделі.
- Звіряйте цитати, дати та ключові твердження з оригіналом.
- Перевіряйте пошук і LLM окремо малим запитом.
- Перед новим додаванням перечитайте наявні підсумки.
