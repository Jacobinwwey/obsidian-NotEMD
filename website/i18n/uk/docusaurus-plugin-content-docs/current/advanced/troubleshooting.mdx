# Усунення несправностей

<TLDR>Відтворіть на тестовій нотатці з тим самим провайдером, моделлю й налаштуваннями. Читайте прогрес і шлях результату. Відрізняйте автентифікацію, генерацію, парсинг та запис; тест з’єднання не перевіряє всього процесу.</TLDR>

## Огляд

Запишіть версії Notemd/Obsidian, ОС, дію, протокол, модель і мінімальні кроки. Не перезапускайте програму під час завершення скасування. Зберігайте файли результатів і відновлення до з’ясування їхнього походження.

## Діагностика

### Тест з’єднання

**Перевірити підключення** може перевіряти лише список моделей чи коротку генерацію. Потім запустіть мале справжнє завдання вибраною моделлю в потрібному форматі.

### Прогрес і діагностика розробника

Прогрес показує стан, помилки й шляхи; активність API відрізняє очікування від завершення. Вмикайте debug за потреби. Довгий діагностичний запит може витратити квоту. Звіти можуть містити нотатки, часткові відповіді, endpoint-и та ключі. Перед поширенням локально перевірте й очистіть їх, включно з метаданими очищених профілів.

## Типові помилки

### Неправильний або відсутній ключ

401: профіль, endpoint і зайві пробіли. 403: обліковий запис, проєкт, права моделі й оплата. Повтори не виправлять неправильних облікових даних.

### Мережа

Із пристрою Obsidian перевірте сервер, порт, протокол і шлях. Ollama/LM Studio мають працювати з доступною моделлю. `localhost` означає цей пристрій, не інший комп’ютер. Виберіть правильний профіль; fallback автоматичний, окремого загального перемикача транспорту немає.

### Ліміт 429

Зменште одночасні запити та перевірте квоти викликів/токенів і стороннє використання ключа. Повтори усувають лише деякі тимчасові помилки.

### Модель не знайдена

Скористайтеся **Fetch models** або відомим ID моделі/deployment. Перевірте API й регіон. Приклади застарівають; Azure потребує deployment, Ark може потребувати endpoint-ID.

### Немає посилань чи понять

Перевірте фактичний файл, придатне джерело, формат відповіді та ввімкнену вибрану папку понять. Самостійне виділення починає з назв без зворотних посилань. Якщо немає маркерів, порівняйте типовий запит.

### Результат зник або в іншому місці

Читайте повідомлений `_processed.md`, `_<language>.md` чи complete шлях. Помилка папки перекладу може повернути результат у папку джерела. Перед повтором перевірте конфлікти та права.

### Файли після скасування

Завершені записи лишаються, прийняті запити можуть закінчитися. Перед видаленням чи повтором усієї папки перевірте файли та конфлікти відновлення.

### Діаграма чи експорт у програму

Використовуйте підтримуваний тип/джерело й перевірте середовище слайдів/CircuitikZ. Попередній перегляд не є тестом цільової програми. Без візуального перегляду збережіть текст джерела для відповідного зовнішнього засобу. [Діаграми](../features/diagrams).

## Повідомлення про помилку

1. Відтворіть синтетичною нотаткою й тестовою папкою.
2. Укажіть версії, дію, модель, потрібні параметри та очікуваний/фактичний результат.
3. Додайте мінімальні файли/журнали без ключів, приватного вмісту й зайвих метаданих endpoint.
4. Уточніть, чи виникає з одним файлом і типовими інструкціями.
5. Створіть [GitHub Issue](https://github.com/Jacobinwwey/obsidian-NotEMD/issues).

Сам скриншот рідко доводить помилку формату чи скасування. За можливості додайте джерело/результат або мінімальні кроки.
