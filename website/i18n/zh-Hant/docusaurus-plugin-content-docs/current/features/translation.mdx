# 翻譯

<TLDR>
Notemd 使用配置的 LLM 翻譯活動檔案或目錄內合格檔案，預設寫出有語言後綴的獨立檔。語言涵蓋與品質依模型而定；21 個 UI 與 34 個網站 locale 不是翻譯能力保證或限制。
</TLDR>

## 概覽

先選輸出語言和翻譯 provider，以含術語、連結與程式碼的代表性副本測試。此功能使用所選 LLM，不是專門的 Google Translate 整合。

翻譯動作針對檔案和資料夾。僅需段落時，先複製至暫存筆記；編輯器選取文字不會縮小 **翻譯目前檔案** 範圍。

## 工作原理

### 翻譯命令

1. 選擇輸出語言，預設英文，與 UI 無關。
2. 開啟源檔，執行 **翻譯目前檔案**。
3. 長文分塊傳給翻譯 provider/model，再合併回應。
4. 打開報告路徑，核對意義、術語、引用、連結與程式碼。

預設將 `Example.md` 翻譯為法文，會在同目錄產生 `Example_fr.md`，保留原文。既有同名輸出會覆寫；沒有預設附加至源文模式或保證存在的 `Translation` 標題。

### 語言配對

模型推斷源語言，選單列出目標不證明特定語言對準確。以樣本檢查術語與混語內容，分塊可能失去跨塊上下文。

### 任務專用模型

啟用任務模型後使用 `translateProvider`、`translateModel`，否則用活動 provider。本地模型需執行中的服務與下載模型；雲端會接收提示詞和內容。

以領域樣本對照源文驗證，不只依通用速度／品質排名選擇。

### 資料夾批次翻譯

執行 **批次翻譯資料夾**，選目錄並核對範圍。預設只含直接子檔案，高級選取 profile 可改變。輸出沿用 basename 和語言後綴，同名源檔集中至一個自訂目錄可能衝突；明確選擇位置，重跑前檢查舊譯文。

## 設定

| 設定 | 預設 | 作用 |
| --------- | --------- | -------- |
| `language` | `en` | 目標輸出語言 |
| `translateProvider` | `DeepSeek` | 專用路由啟用時的翻譯 provider |
| `translateModel` | `''` | 空白時使用 provider 模型 |
| `useCustomTranslationSuffix` | `false` | 預設語言代碼後綴 |
| `translationCustomSuffix` | `_translated` | 啟用自訂後綴後使用的值 |
| `useCustomTranslationSavePath` | `false` | 預設儲存於源檔旁 |
| `translationSavePath` | `''` | 自訂 Vault 相對目錄 |
| `batchConcurrency` | `1` | 目錄翻譯要求的並行數 |

自訂目錄建立失敗可回退源目錄，實際位置以報告為準。空自訂後綴可指向源檔名稱；需要獨立譯文時使用不同後綴。

## 範例

輸出設英文，將短中文筆記複製至測試目錄，翻譯後與 `_en.md` 並排核對。術語、數字、公式與連結正確後再處理整個目錄。

## 取消與審核

取消在支援處停止後續工作，不回復既有譯文，也不保證遠端停止計費。檢查報告與檔案。要求保留 Markdown 是提示詞要求，不是解析器保證語意相等。

## 建議

- 保留源文備份並檢查名稱衝突。
- 試驗用獨立後綴與目錄。
- 人工核對標識符、數學符號、來源 URL 與專名。
- 分享診斷前移除私密內容。
