# 문제 해결

<TLDR>정확한 provider·모델·설정으로 시험 노트 하나에서 재현하세요. 진행 로그와 출력 경로를 확인합니다. 인증·생성·파싱·쓰기 실패를 구분하세요. 연결 성공만으로 전체 워크플로가 검증되지는 않습니다.</TLDR>

## 개요

Notemd/Obsidian 버전, OS, 동작, 프로토콜, 모델, 최소 재현을 기록합니다. 취소가 정리되는 동안 다른 작업을 시작하지 말고 산출물의 출처를 알 때까지 복구 파일을 유지하세요.

## 진단

### 연결 시험

**연결 테스트**은 프로필에 따라 목록만 확인하거나 짧은 생성을 합니다. 선택 모델의 출력 계약은 작은 실제 작업으로 확인합니다.

### 진행과 개발자 진단

진행 화면은 상태·오류·목적지를, API 활동은 대기/완료/실패 요청을 보여 줍니다. 필요한 경우에만 오류 debug를 켜세요. 긴 개발자 진단은 quota를 소비할 수 있습니다. 본문에 노트, 부분 응답, endpoint와 인증 정보가 있을 수 있으므로 로컬에서 확인·삭제 후 공유합니다. 마스킹된 프로필도 메타데이터 검토가 필요합니다.

## 흔한 오류

### 키 누락 또는 오류

401은 올바른 provider/endpoint의 키와 공백을, 403은 계정·프로젝트·모델 권한과 결제를 확인합니다. 재시도는 잘못된 인증을 고치지 않습니다.

### 네트워크

Obsidian 장치에서 host·port·프로토콜·경로를 확인합니다. Ollama/LM Studio 서버와 모델이 준비되어야 합니다. `localhost`는 다른 컴퓨터가 아닙니다. 올바른 프로필을 선택하세요. fallback은 자동이며 UI 전송 모드 스위치가 아닙니다.

### 429 제한

동시성을 낮추고 요청/token quota 및 같은 키를 쓰는 다른 클라이언트를 확인합니다. 재시도는 일부 일시 오류만 복구합니다.

### 모델 없음

지원 시 **Fetch models**, 아니면 계정의 정확한 모델/deployment를 입력합니다. API 버전·지역·모델 퇴역을 확인하세요. Azure는 deployment 이름, Ark는 endpoint ID가 필요할 수 있습니다.

### 링크·개념 없음

실제 출력과 유용한 원문, 응답 형식, 비어 있지 않은 활성 개념 폴더를 확인합니다. 독립 추출은 제목만, 역링크 꺼짐이 기본입니다. 사용자 prompt에서 표식을 없앴다면 기본값으로 비교하세요.

### 출력 누락 또는 다른 위치

작업이 보고한 `_processed.md`, `_<language>.md` 또는 complete 경로를 확인합니다. 번역 폴더 생성 실패 시 원본 폴더로 돌아갈 수 있습니다. 충돌과 권한을 확인하고 재실행하세요.

### 취소 후 파일이 남음

완료 쓰기는 유지되며 이미 수락된 원격 요청/쓰기는 끝날 수 있습니다. 파일별 결과와 복구 충돌을 확인한 후 삭제/재실행하세요.

### 도표·네이티브 export

지원 조합과 슬라이드/CircuitikZ 환경 검사를 사용하세요. 미리보기는 네이티브 검증이 아닙니다. 원본만 있으면 저장해 외부 도구에서 엽니다. [도표](../features/diagrams).

## 문제 보고

1. 합성 노트와 전용 폴더에서 재현합니다.
2. 버전·동작·모델·설정·기대와 실제 결과를 기록합니다.
3. 비밀·개인 내용·불필요한 endpoint 정보를 제거한 로그와 최소 산출물을 첨부합니다.
4. 단일 파일/기본 prompt에서도 재현되는지 명시합니다.
5. [GitHub Issues](https://github.com/Jacobinwwey/obsidian-NotEMD/issues)에 등록합니다.

스크린샷만으로 파일 형식이나 취소 문제를 증명하기 어렵습니다. 원본/출력 쌍이나 최소 재현 순서를 제공하세요.
