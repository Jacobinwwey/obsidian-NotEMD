# 워크플로

<TLDR>워크플로는 기존 사이드바 동작을 순서대로 실행합니다. 폴더 선택이나 활성 편집기가 필요할 수 있습니다. 텍스트 파이프가 아니므로 각 동작의 입력·출력·부수 효과가 유지됩니다. 시험용 노트와 전용 폴더로 시작하세요.</TLDR>

## 개요

기본 **One-Click Extract**:

```text
One-Click Extract::process-current-add-links>batch-generate-from-titles>batch-mermaid-fix
```

1. 활성 노트에 링크를 추가하고 폴더가 설정되어 있으면 개념 파일을 만듭니다.
2. 설정된 개념 폴더 또는 배치 단계에서 고른 폴더의 적격 노트를 제목으로 생성합니다. 기존 노트도 포함됩니다.
3. 생성 결과의 complete 폴더에서 Mermaid를 복구합니다.

기본 체인에 웹 연구는 없습니다. 제목 생성에서 별도 연구 설정을 켠 경우만 사용합니다. [배치](../advanced/batch-processing)를 확인하세요.

## 동작 방식

### 실행 순서

단계는 직렬 실행되며 사이드바가 현재 단계와 오류를 보여 줍니다. 취소는 후속 단계와 지원되는 요청으로 전파되지만 완료 파일을 되돌리는 전체 트랜잭션은 없습니다. 초기 폴더는 설정된 개념 폴더를 우선하고, 배치 생성이 원본/complete 폴더를 기록해 후속 Mermaid 복구에 전달합니다. 다른 동작의 활성 파일·선택·상호작용 요구는 유지됩니다.

### DSL 형식

줄마다 버튼 이름을 씁니다. `::`는 이름과 동작, `>`는 동작 사이를 구분합니다. 빈 줄과 `#`로 시작하는 줄은 무시하고 알 수 없는 ID는 거부합니다.

```text
추출과 도표::extract-concepts-current>summarize-as-mermaid
```

빌더로 선택하거나 직접 편집하세요. 동작 ID는 고정이고 표시 이름은 UI 언어를 따릅니다. 폴더 동작 ID는 문자열 치환으로 임의 생성하지 않습니다.

| ID | 동작과 조건 |
| ------------ | ----------------------- |
| `process-current-add-links` | 활성 노트에 링크 추가 |
| `process-folder-add-links` | 선택 폴더에 링크 추가 |
| `extract-concepts-current` | 활성 노트에서 개념 추출 |
| `extract-concepts-folder` | 선택 폴더에서 개념 추출 |
| `generate-from-title` | 활성 노트 제목으로 내용 생성 |
| `batch-generate-from-titles` | 폴더의 적격 노트를 제목으로 생성 |
| `research-and-summarize` | 열린 Markdown 편집기의 선택/제목 연구 |
| `summarize-as-mermaid` | 지원 활성 입력을 Mermaid로 요약 |
| `generate-diagram` | 지원 입력에서 도표 산출물 생성 |
| `preview-diagram` | 지원 도표 원본/산출물 미리보기 |
| `translate-current-file` | 지원 활성 파일 번역 |
| `batch-translate-folder` | 선택 폴더 번역 |
| `extract-original-text` | 지정 원문 구절 추출 |
| `batch-extract-original-text` | 폴더 적격 파일에서 구절 추출 |
| `split-note-by-chapters` | 활성 노트를 장으로 분할 |
| `batch-mermaid-fix` | 선택 폴더 Mermaid 코드 블록 복구 |
| `fix-formula-current` | 활성 노트 수식 구분자 정규화 |
| `batch-fix-formula` | 선택 폴더 수식 구분자 정규화 |
| `check-duplicates-current` | 활성 노트 중복 확인 |
| `check-remove-duplicate-concepts` | 개념 중복을 상호작용으로 검토·삭제 |
| `test-llm-connection` | 설정 provider 시험 |
| `probe-slide-export-env` | 로컬 슬라이드 내보내기 환경 확인 |
| `export-slides` | 활성 파일을 슬라이드로 내보내기 |

### 기본과 사용자 워크플로

One-Click Extract 외 버튼은 직접 정의합니다. 설정에서 이름과 동작 순서를 정하고 사이드바 tooltip을 확인하세요. 파서 오류를 먼저 수정한 후 체인을 사용합니다.

## 설정

| 설정 | 초기 값 | 효과 |
| --------- | --------- | -------- |
| `customWorkflowErrorStrategy` | `stop_on_error` | 처음 보고된 단계 오류에서 중지 |
| `useMultiModelSettings` | `false` | 작업별 경로를 켜기 전 활성 provider 사용 |
| `enableResearchInGenerateContent` | `false` | 켜기 전 제목 생성에서 웹 연구 제외 |

`continue_on_error`는 이전 단계 실패 후에도 다음 단계를 실행합니다. 남은 입력으로 동작할 수 있을 때만 사용하세요. 부분 성공을 전체 성공으로 바꾸지는 않습니다.

### 작업별 모델

provider/모델 선택은 개별 작업이 소유합니다. 작업별 모델 override가 비면 그 provider의 모델을 사용합니다. 비공개 내용을 다룬다면 모든 단계의 경로를 확인하세요.

## 예시

빈 `trial-concepts` 폴더를 설정하고 시험 노트 하나로 실행한 다음 개념 파일과 complete 폴더를 확인하세요. 목적지가 불명확하면 각 동작을 먼저 단독으로 실행하고 결과 검토 후 범위를 넓힙니다.

## 권장 사항

- 실패와 출력 소유권을 파악할 수 있도록 체인을 짧게 유지하세요.
- 삭제/정리 동작은 상호작용 확인 요구가 남으므로 무인 체인에 넣지 마세요.
- 취소/복구 충돌 후 파일과 로그를 확인하세요.
- 실제 모델과 폴더 선택으로 시험하세요. 짧은 연결 시험은 장시간 배치의 할당량 적합성을 보장하지 않습니다.
