# Wiki-lenker

<TLDR>Process file (add links) ber valgt LLM finne begreper og legge til Obsidian-lenker. Som standard lages separat `_processed.md`, mens kilden bevares. Begrepsfiler krever valgt mappe. Kontroller resultatet før større kjøringer.</TLDR>

## Oversikt

Utvalget kan variere mellom kjøringer og vise til begreper som ikke finnes som filer ennå. En wiki-lenke er et navigasjonsmål, ikke bevis på samme betydning eller riktig forklaring.

## Slik fungerer det

### Behandling

Notatet deles, sendes til leverandør/modell og settes sammen fra svarene. Oppgaven kan opprette eller oppdatere begrepsfiler i valgt mappe. Les delfeil og faktisk resultatsti i framdriften.

### Eksempel

Kilde:

```text
Maskinlæring bruker nevrale nettverk til å gjenkjenne mønstre.
```

Mulig resultat:

```markdown
[[Maskinlæring]] bruker [[nevrale nettverk]] til å gjenkjenne mønstre.
```

Dette er en illustrasjon. Kilde, modell og instruksjon avgjør begrepene.

## Bruk

### Aktivt notat

Kjør **Process file (add links)** på en kopi og se den tilstøtende `_processed.md`. Eget suffiks, resultatmappe og flytting av original kan endre målet.

### Flere notater

Velg **Process folder (add links)**, kontroller mappe og omfang, og start smått. Mappeoppgaver deler ikke én overskriv/hopp over-bryter. Se [batchbehandling](../advanced/batch-processing).

### Velg termen selv

**Create wiki link and generate note from selection** er en egen handling for valgt term. Den avgrenser ikke hele filhandlingen til markeringen. Se begrepsfilen og eventuelt generert innhold.

## Velg metode

Modellbasert lenking finner mulige begreper i innhold. Deterministisk tittelmatching passer bedre når gjentakbare lenker til kjente navn er viktigst. Sammenlign andre verktøy med oppdaterte veiledninger og samme daterte prøve.

## Muligheter

### Begrens synonymer

`replaceSynonymsDuringConceptExtraction` legger til en instruksjon mot overlappende begreper. Den er en Boolean, av som standard, ikke en numerisk likhetsterskel. Vurder forkortelser og nærliggende betydninger selv.

### Lenkeintegritet

Obsidian håndterer oppdateringer ved navnebytte ut fra sine innstillinger og handlingen som brukes. Slettet mål kan etterlate en uløst wiki-lenke, forskjellig fra en omtale uten lenke. Kontroller like filnavn i ulike mapper.

### Bare uttrekk

**Extract concepts (current file)** henter begreper uten å omskrive kilden. Maler og tilbakekoblinger skiller seg fra lenking. [Begrepsnotater](./concept-notes).

## Begrepsfiler

### Automatisk opprettelse

Med aktivert og valgt begrepsmappe kan filer med tittel og `Linked From` opprettes. Undersøkte forklaringer, relaterte begreper og generelle frontmatter-maler legges ikke automatisk til. Generer innhold fra titler separat.

### Oppsett

Finn begrepsmappe, mappe for behandlede filer, suffiks og kildeflytting. Begrepsmappen begynner tom. Hold testresultater skilt fra kildene.

## Avansert

### Kontekst og instruksjoner

`chunkWordCount` begrenser tekstbiter omtrentlig. Fagområder og egne instruksjoner kan styre utvalget. Generelle setnings-/avsnittsvelgere, minste forekomsttall og begrepsmalvariabler er ikke beskrevne valg for oppgaven.

## God praksis

- Sammenlign sitater, formler og kode med kilden.
- Velg hvilke termer som fortjener egne notater.
- Test instruksjonsendringer på et fast utvalg.
- Sikkerhetskopier før kildeflytting og overskriving.

## Ytelse

Tid og pris avhenger av leverandør, modell, innhold, svar og nye forsøk. Ingen fast tid per notat eller pris per hundre filer. Mål eget utvalg og faktisk forbruk.

## Problemer

### Ingen lenker

Kontroller forespørsel, svar, tilsiktet kilde og rapportert fil. Ingen minste tekstlengde garanterer nyttige lenker.

### For mange lenker

Avgrens instruksjonen eller fagområdet. Synonymregler veileder modellen, men håndhever ingen ordliste.

### Lenker etter navnebytte

Se Obsidian-innstillinger og tvetydige navn. Rett målet bevisst. En ny modellkjøring er ikke deterministisk lenkereparasjon.
