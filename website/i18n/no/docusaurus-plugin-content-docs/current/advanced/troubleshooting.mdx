# Feilsøking

<TLDR>Gjenskap problemet på ett testnotat med samme leverandør, modell og oppgaveinnstillinger. Les framdrift og resultatsti. Skill autentisering, generering, parsing og skriving; forbindelsestest kontrollerer ikke hele arbeidsflyten.</TLDR>

## Oversikt

Noter Notemd-/Obsidian-versjon, OS, handling, protokoll, modell og minste trinn. Ikke start på nytt mens avbruddet avsluttes. Bevar resultater og gjenopprettingsfiler til opphavet er klart.

## Diagnostikk

### Forbindelsestest

**Test connection** kan bare kontrollere modelliste eller kort generering. Kjør deretter en liten virkelig oppgave med riktig modell og resultatformat.

### Framdrift og utviklerdiagnostikk

Framdrift viser status, feil og plasseringer; API-aktivitet skiller ventende og ferdige forespørsler. Aktiver debug ved behov. Lang diagnostikk kan bruke kvoter. Rapporter kan inneholde notater, delsvar, adresser og nøkler. Kontroller og masker lokalt før deling; maskerte profiler trenger også metadata-gjennomgang.

## Vanlige feil

### Manglende eller ugyldig nøkkel

401: rett profil/endepunkt, ingen utilsiktede mellomrom. 403: konto, prosjekt, modellrettigheter og fakturering. Nye forsøk retter ikke feil legitimasjon.

### Nettverk

Se vert, port, protokoll og rute fra Obsidian-enheten. Ollama/LM Studio må være i gang med tilgjengelig modell. `localhost` er denne enheten, ikke en annen maskin. Velg riktig profil; fallback velges automatisk, ikke med en transportknapp.

### Grense 429

Senk samtidighet og undersøk forespørsels-/tokenkvoter og annen bruk av samme nøkkel. Nye forsøk hjelper bare enkelte midlertidige feil.

### Modell finnes ikke

Bruk **Fetch models** eller kjent modell/deployment. Se API-versjon og region. Eksempler kan være utdaterte; Azure krever deployment og Ark kan kreve endepunkt-ID.

### Ingen lenker eller begreper

Kontroller faktisk resultatfil, brukbar kilde, svarformat og valgt aktiv begrepsmappe. Selvstendig uttrekk begynner med titler uten tilbakekoblinger. Sammenlign standardinstruksjonen dersom markører er utelatt.

### Resultat borte eller feil sted

Les rapportert `_processed.md`, `_<language>.md` eller complete-sti. Feil ved opprettelse av oversettelsesmappe kan gi kildemappe som reserve. Kontroller kollisjoner og rettigheter før ny kjøring.

### Filer etter avbrudd

Fullførte skrivninger beholdes og aksepterte forespørsler kan avsluttes. Kontroller filer og gjenopprettingskonflikter før sletting eller ny hel mappekjøring.

### Diagram eller native eksport

Typer genereres etter hverandre. Én feil stopper ikke de andre. Avbryting stopper ventende typer og beholder ferdige filer. Prøv eksport på nytt fra forhåndsvisning eller historikk uten en ny modellforespørsel. Genereringsfeil krever at typen genereres på nytt. v1/v2-poster kan fortsatt leses.

Diagram-HTML inneholder grafikk med zoom; HTML med strukturert sammendrag inneholder tekst, struktur og referanser. Redigerbar HTML/SVG er en renderer, ikke en nettredigerer. Bruk den opprinnelige kildefilen for redigering. Presentasjonseksport, inkludert PPTX og MP4, har egne innstillinger og avhengigheter. [Diagramhåndbok](../features/diagrams).

## Rapportere feil

1. Gjenskap med syntetisk notat og testmappe.
2. Oppgi versjoner, handling, modell, nødvendige innstillinger og forventet/faktisk resultat.
3. Legg ved minimale filer/logger uten nøkler, privat tekst eller unødvendige endepunktdetaljer.
4. Si om feilen skjer på én fil med standardinstruksjoner.
5. Åpne [GitHub Issues](https://github.com/Jacobinwwey/obsidian-NotEMD/issues).

Et skjermbilde beviser sjelden alene en format- eller avbruddsfeil. Gi kilde/resultat eller en minimal trinnrekke hvis mulig.
