# Wiki 連結

<TLDR>
“Process file (add links)” 請所選 LLM 識別概念並加入 Obsidian wiki 連結。預設寫入獨立 `_processed.md` 並保留源檔；概念輸出需指定資料夾。擴大範圍前先檢查結果。
</TLDR>

## 概覽

適合根據筆記含義提出候選連結。各次模型選詞可能不同，也可能指向尚無檔案的概念。連結只是導覽目標，不證明概念等價或生成解釋正確。

## 工作原理

### 處理流程

筆記分塊傳送給所選 provider/model，回應合併後寫入處理結果，也可建立／更新指定目錄的概念筆記。核對進度報告中的部分失敗和實際路徑。

### 範例

源文：

```text
機器學習模型使用神經網路，從範例中學習規律。
```

可能的處理結果：

```markdown
[[機器學習]]模型使用[[神經網路]]，從範例中學習規律。
```

這是示意，精確選詞取決於源文、模型與提示詞。

## 使用方式

### 基本：為目前筆記添加連結

開啟 Markdown 副本，從側欄或命令面板執行 **處理檔案（新增連結）**，檢查同層 `_processed.md`。自訂後綴、處理後目錄及移動原檔設定會改變目標行為。

### 批次：處理多篇筆記

選擇 **處理資料夾（新增連結）**，確認資料夾和範圍，從小樣本開始。所有資料夾任務沒有共用的覆寫／略過開關，重跑前參閱[批次處理](../advanced/batch-processing)。

### 選取：連結指定文字

自行選詞時，使用 **Create wiki link and generate note from selection**。這是獨立動作，不會讓整檔添加連結只處理選區。審核建立的概念筆記和生成內容。

## 選擇連結方式

需要從含義發現概念時使用模型輔助；重視與現有筆記名稱穩定比對時使用確定性標題匹配。依其他專案最新文件評估，本文不作沒有具日期基準的功能或效能比較。

## 功能

### 同義詞抑制

`replaceSynonymsDuringConceptExtraction` 加入避免同義或高度重疊概念的指令。這是預設關閉的布林設定，不是相似度數值閾值；縮寫與近義詞仍需審核。

### 連結完整性

重新命名的內部連結更新由 Obsidian 的設定與操作決定。刪除目標可能留下未解析連結，與未連結提及不同。不同資料夾有同名筆記時，檢查 basename 歧義。

### 純擷取模式

不改寫源筆記而建立概念檔時，使用 **擷取概念（目前檔案）**；其最小模板和反向連結控制不同於添加連結。見[概念筆記](./concept-notes)。

## 概念筆記生成

### 自動建立

啟用並指定概念目錄後，可建立含標題與 `Linked From` 來源連結的概念筆記。不會自動產生研究說明、相關概念章節或可設定 frontmatter 模板；需正文時另執行標題生成。

### 設定

搜尋概念目錄、處理後目錄、添加連結後綴和移動原檔選項。概念目錄初始空白，測試時區分源資料與輸出位置。

## 進階選項

### 上下文與提示詞

`chunkWordCount` 控制近似區塊大小，聚焦學習和自訂提示詞可縮小概念範圍。此任務沒有句子／段落上下文選擇器、最少出現次數閾值或通用概念模板變數。

## 實務建議

- 對照源文核對引文、公式和程式碼。
- 評估新連結是否值得建立概念筆記。
- 在固定樣本測試提示詞再擴大到資料夾。
- 移動源檔或重跑既有目標前備份。

## 效能

延遲和費用受 provider、模型、提示詞大小、輸出長度和重試影響，不承諾固定單篇秒數或每百篇費用。擴大範圍前測量代表性樣本，核對實際帳號用量。

## 疑難排解

### 未添加連結

檢查請求狀態與模型回應，確認處理了正確筆記並查看輸出檔。沒有保證連結有效的最小字數。

### 連結太多

縮小提示詞或啟用聚焦學習，並檢查結果。同義詞抑制是引導，不是強制詞彙表。

### 重新命名後連結失效

核對 Obsidian 連結更新設定及既有歧義，明確還原或修復目標；再次呼叫 LLM 不是確定性連結修復。
