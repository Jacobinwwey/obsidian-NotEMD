# 工作流程

<TLDR>
工作流程依序執行現有側欄動作，可能要求資料夾或活動編輯器。它不是文字管線，各動作保留輸入、輸出與副作用。先使用可捨棄筆記和專用目錄。
</TLDR>

## 概覽

內置 **One-Click Extract** 定義：

```text
One-Click Extract::process-current-add-links>batch-generate-from-titles>batch-mermaid-fix
```

1. 為活動筆記添加連結；已配置目錄時建立概念檔。
2. 為概念或批次選定目錄內符合條件的筆記生成正文，包含既有檔案。
3. 修復批次生成的 complete 目錄內 Mermaid。

預設不執行網路研究。只有標題生成的獨立研究設定開啟時，生成才使用研究。詳見[批次處理](../advanced/batch-processing)。

## 工作原理

### 執行管線

步驟依序執行，側欄顯示進行步驟與失敗。取消停止後續步驟並傳播至支援請求，保留已完成寫入，沒有整體原子回復。

概念目錄為初始優先上下文，批次生成記錄源目錄與 complete 目錄，後續 Mermaid 修復使用 complete。其他動作仍要求各自活動檔案、選區或互動條件。

### DSL 格式

每行一個命名按鈕，`::` 分隔名稱與動作，`>` 分隔 ID。忽略空行和 `#` 開頭行，未知動作 ID 會拒絕。

```text
擷取與圖表::extract-concepts-current>summarize-as-mermaid
```

可用建構器或直接編輯 DSL。動作 ID 穩定，標籤隨 UI 語言。資料夾變體有自己的 ID，不能一般化替換名稱。

| 標識符 | 動作／先決條件 |
| ------------ | ----------------------- |
| `process-current-add-links` | 為活動筆記添加連結 |
| `process-folder-add-links` | 為所選資料夾添加連結 |
| `extract-concepts-current` | 擷取活動筆記概念 |
| `extract-concepts-folder` | 擷取所選資料夾概念 |
| `generate-from-title` | 依活動筆記標題生成正文 |
| `batch-generate-from-titles` | 為目錄內合格筆記生成正文 |
| `research-and-summarize` | 在 Markdown 編輯器研究選區或標題 |
| `summarize-as-mermaid` | 將受支援活動輸入摘要為 Mermaid |
| `generate-diagram` | 一次勾選多種圖表，每種類型獨立選擇多種輸出格式。取消勾選仍保留該類型的格式偏好；全部取消則自動分析原文。 |
| `preview-diagram` | 預覽受支援圖表源或產物 |
| `translate-current-file` | 翻譯目前受支援檔案 |
| `batch-translate-folder` | 翻譯所選資料夾 |
| `extract-original-text` | 擷取指定原文片段 |
| `batch-extract-original-text` | 從資料夾合格檔案擷取原文 |
| `split-note-by-chapters` | 依章節拆分活動筆記 |
| `batch-mermaid-fix` | 修復所選目錄 Mermaid 代碼塊 |
| `fix-formula-current` | 正規化目前筆記公式分隔符 |
| `batch-fix-formula` | 正規化所選目錄公式分隔符 |
| `check-duplicates-current` | 檢查目前筆記重複項 |
| `check-remove-duplicate-concepts` | 互動審核並移除重複概念 |
| `test-llm-connection` | 測試已設定 provider |
| `probe-slide-export-env` | 檢查本地投影片匯出環境 |
| `export-slides` | 將活動檔案匯出為投影片 |

### 預設與自訂流程

One-Click Extract 是內置預設，其他按鈕由你定義。搜尋設定、命名並排序動作，執行前核對側欄提示。先修正解析錯誤，再依賴預期鏈條。

## 設定

| 設定 | 預設 | 作用 |
| --------- | --------- | -------- |
| `customWorkflowErrorStrategy` | `stop_on_error` | 第一個步驟報告失敗後停止 |
| `useMultiModelSettings` | `false` | 任務專用路由啟用前使用活動 provider |
| `enableResearchInGenerateContent` | `false` | 標題生成預設不研究 |

`continue_on_error` 允許前步失敗後繼續。僅在後續可使用剩餘輸入時啟用；繼續不使部分流程成為成功。

### 流程中的任務模型

Provider/model 選擇屬於任務。啟用專用設定時，空模型覆寫使用該 provider 模型。處理私密材料前檢查每個任務。

## 範例

指定空的 `trial-concepts`，處理一篇可捨棄筆記，核對概念與 complete 目錄。如需了解各步輸出，先分別執行；審核後再擴大範圍。

## 建議

- 保持流程短，讓失敗與輸出歸屬清楚。
- 無人值守鏈條避免清理／刪除，這些動作仍需互動確認。
- 取消或復原衝突後，檢查日誌和檔案再重試。
- 測試精確 provider/model 和目錄，連線成功不保證長批次符合配額。
