# Configuration

<TLDR>
Open **Settings → Notemd** and use settings search to find a field. Configure the provider and output destinations before processing notes. Test configuration changes on one note before applying them to a folder; a running operation can retain settings captured when it started.
</TLDR>

## Settings Overview

The default active provider is DeepSeek. Its account credentials are initially empty. Selecting a preset does not create an account, install a model or grant access to a hosted model. [Provider setup](../providers/overview) explains each protocol and model discovery.

## Notemd settings discovery and favorites

- **Search settings** matches names, descriptions, aliases and visible categories, then jumps to the selected field.
- **★ Favorites** opens a list of saved settings with descriptions, categories and navigation targets. Favorites are stored in the current Vault and survive restarts; obsolete setting IDs are discarded.
- Collapse the discovery toolbar with its chevron to recover vertical space. Reopening it restores the current query.
- The favorites list and favorites-only search filter are separate controls.

**Diagram preview export PPI** defaults to **300 PPI** and accepts **72-600**. It affects PNG rasterization; SVG/PDF retain vector geometry where supported by the selected export. **Also export complete Mermaid visuals** controls companion files, not Mermaid visibility inside a Drawnix preview.

Select several chart types in one run and choose multiple output formats independently for each type. Unchecking a type retains its format preferences; leaving every type unchecked uses automatic analysis.

Set the diagram intermediate-files folder to a shared Vault-relative path, or leave it empty for `notemd_assert/` beside each source. Recovery records, cached renders and optional attachments stay there. Retain files still referenced by existing exports; folder changes affect new runs only.

## 1. Provider Configuration

Choose the provider, enter credentials if required, retain the preset's protocol-appropriate endpoint, and select an accessible model. Use **Fetch models** when supported, followed by **Test connection**. Listing models and successfully generating a response are separate checks.

A local provider needs a running server and a downloaded or loaded model. A cloud provider or gateway receives the task content sent to it. Check task-specific providers as well as the active provider when configuring private work.

## 2. Task-Specific Models

Enable `useMultiModelSettings` to choose separate provider/model pairs for linking, title generation, research, translation, concept extraction, original-text extraction and Mermaid summarization. Empty task-model overrides use the selected provider's configured model. Otherwise the active provider supplies the task.

Compare providers using a representative note, output accuracy, latency and actual account pricing. This documentation does not rank models or guarantee their availability.

## 3. Output Configuration

| Task | Default output behavior |
|------|-------------------------|
| Add links | Separate `_processed.md` file beside the source; moving the original is disabled |
| Standalone concept extraction | Requires a chosen concept folder; creates title-only notes, with backlinks disabled |
| Translation | Separate `_<language>.md` file beside the source; an existing destination can be overwritten |
| Research | Appends a research summary to the active Markdown note |
| Batch title generation | Writes generated content and moves eligible notes to the reported sibling `<folder>_complete` folder when that destination permits it |
| Diagram preview/export | Selected files are exported automatically beside the source note, or directly into the configured output folder. Names include the type, such as `topic_drawnix.pdf` and `topic_flowchart.svg`; collisions add `-2`, `-3` and so on without overwriting existing files. |
The concept folder starts empty. `concepts` is a useful folder name you can choose, not a default path. Standalone concept templates are the supported minimal/full forms; there is no general note-template variable engine. [Concept notes](../features/concept-notes) describes their content.

Custom add-links suffixes, processed folders, translation suffixes and translation save paths are separate settings. Check whether a destination already exists before rerunning a write operation. Recovery and conflict messages identify outputs requiring attention; cancellation does not roll back completed writes.

## 4. Language Settings

The plugin has **21 UI locales**, while the website has **34 locale routes**. `uiLocale: auto` follows the available UI-language mapping; unsupported UI languages fall back to English.

The generated-content language is independent and defaults to English. Enable task-specific language settings when linking, title generation, research, concept extraction or Mermaid summaries need different output languages. Translation uses the selected output language (`language`), independently of the UI language. The model's language ability is separate from both the UI and website locale counts.

## 5. Search Integration

Select **Tavily** and provide its API key, or select **DuckDuckGo** explicitly. An empty Tavily key does not select DuckDuckGo automatically. Both make network requests; DuckDuckGo may also fetch result pages.

Title generation does not perform research by default. Enable `enableResearchInGenerateContent` only when you want that extra step. Optional local knowledge retrieval is also disabled by default and has separate folder and task scopes. Retrieved note excerpts are sent to the task's LLM when used as context, even though indexing is local.

## 6. Workflow Configuration

Use the workflow builder or one named DSL definition per line. The shipped default is:

```text
One-Click Extract::process-current-add-links>batch-generate-from-titles>batch-mermaid-fix
```

`::` separates the button name from its actions, and `>` separates action IDs. The default error policy stops on a reported step failure. [Workflows](../features/workflows) lists supported IDs, folder context and the consequences of continuing after errors.

## 7. Advanced Settings

| Setting | Default | Effect |
|---------|---------|--------|
| `activeProvider` | `DeepSeek` | Provider used without task-specific routing |
| `useMultiModelSettings` | `false` | Enable separate task provider/model choices |
| `useCustomConceptNoteFolder` | `true` | Allow concept-file creation once a folder is chosen |
| `conceptNoteFolder` | `''` | No concept folder is initially selected |
| `extractConceptsMinimalTemplate` | `true` | Use title-only standalone concept notes |
| `extractConceptsAddBacklink` | `false` | Add standalone extraction backlinks only when enabled |
| `moveOriginalFileOnProcess` | `false` | Preserve the source during add-links processing |
| `chunkWordCount` | `3000` | Approximate text chunk size, not a provider token limit |
| `batchConcurrency` | `1` | Default batch concurrency |
| `enableBatchParallelism` | `false` | Opt in to parallelism on batch paths that use this switch |
| `enableStableApiCall` | `false` | Explicit stable request mode |
| `customWorkflowErrorStrategy` | `stop_on_error` | Stop workflows on a reported error |

Chunking and output-token budgets are different controls. Smaller chunks do not guarantee a provider context limit will be met. Lower concurrency can reduce pressure on quotas but cannot prevent every 429 response.

## Configuration Profiles

Settings belong to the Vault's plugin data. Keep backups before changing a working configuration. Provider-profile exports have their own redaction contract; they are not a complete Vault backup. Review endpoint URLs and other metadata before sharing even a redacted export. Do not publish the plugin's raw settings file or diagnostic bodies containing private notes.

## Troubleshooting Configuration

Use **Test connection** for the exact provider/model, then retry one small note. If settings appear missing, search by name, inspect the current category and developer-mode visibility, and confirm you opened the intended Vault. Report reproducible failures with the plugin version and sanitized configuration details.

## 1.9.10 — Safer previews and Vault-local settings

Imported SVG previews remove active content and external resources while preserving Chinese labels and panel styles. Device-only providers are now isolated by Vault; use the explicit legacy import action in settings, which preserves the old list and existing configurations. Presentation previews use a loopback server with shared-consumer lifecycle control. Failed favorites saves and clipboard writes report errors; deletion follows Vault preferences. PNG compatibility stays enabled by default, preserving the requested original and adding a verified lower-PPI copy only when needed. Drawnix has no fixed relation quota; presentation exports keep separate settings. Install matching release files, reload, and test one note before batching.
